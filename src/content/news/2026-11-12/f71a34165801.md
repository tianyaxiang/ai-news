# About the downtime and security incident

evazion about 11 hours ago On November 4th there was a security incident where someone found a way to upload a malicious Flash post. Since then the site has been down for a week while we responded. This is what happened. The short version is that someone found an exploit that let them upload a Flash file that contained an XSS worm. The worm tried to spread itself across the site and steal the IP address of anyone viewing the infected posts. The site was shut down within about 6 minutes, so the actual damage was very limited. The main thing it did was grab the IPs of anyone who viewed the posts.

evazion 在约 11 小时前发布：11 月 4 日发生了一起安全事件，有人找到了一种上传恶意 Flash 帖子的方法。自那时起，网站已关闭一周以进行响应。以下是事件经过。简而言之，有人发现了一个漏洞，允许他们上传包含 XSS 蠕虫的 Flash 文件。该蠕虫试图在网站上传播，并窃取任何查看受感染帖子的人的 IP 地址。网站在约 6 分钟内被关闭，因此实际损害非常有限。它主要的操作是获取了查看这些帖子的人的 IP。

The exploit itself was quickly fixed, but it was clear that the attacker had used LLMs to find this exploit, and that they were targeting us and would use LLMs to find other exploits if we brought the site back up too soon. So we spent the next week fixing every security issue we could find and generally beefing up security to make sure this kind of thing couldn't happen again. We also used the downtime to do some much-needed server maintenance and upgrades that we had been putting off for a long time, which also took a couple of days.

漏洞本身很快得到了修复，但很明显攻击者使用了大语言模型（LLM）来寻找该漏洞。他们以我们为目标，如果我们过早恢复网站，他们会利用 LLM 寻找其他漏洞。因此，我们在接下来的一周里修复了所有能发现的安全问题，并全面加强了安全性，以确保此类事件不再发生。我们还利用这段停机时间进行了一些急需的服务器维护和升级，这些工作我们已经推迟了很久，也花费了几天时间。

What happened? An attacker uploaded a malicious Flash post that, among other things, grabbed your IP address and hijacked your account to spread the file. The servers themselves weren't hacked, and the file itself didn't hack your computer or anything like that. It just let the attacker take over your account while you were viewing an infected post. It only affected those who viewed it in the 6-minute window the site was up.

发生了什么？攻击者上传了一个恶意 Flash 帖子，该帖子除了其他操作外，还获取了您的 IP 地址并劫持了您的账户以传播该文件。服务器本身没有被黑，文件本身也没有入侵您的电脑或类似操作。它只是在您查看受感染帖子时让攻击者接管了您的账户。它仅影响了在网站运行的 6 分钟窗口期内查看该帖子的人。

What exactly did it do? This is what it did: First it showed a video from hxxps://domain2doamin.duckdns.org/cdn/worm-video.flv. This grabbed your IP address (this is the attacker's site, so don't visit that site without a VPN, it's an IP grabber). If you were a logged-in user, it would log your username, so it would get your username and IP. Next it tried to create a backdoor API key for your account. This only worked if you had entered your password in the last hour. It was only able to do this for 7 people who had recently logged in. These API keys were never used and have been deleted.

它具体做了什么？它执行了以下操作：首先，它显示了一个来自 hxxps://domain2doamin.duckdns.org/cdn/worm-video.flv 的视频。这获取了您的 IP 地址（这是攻击者的网站，请勿在没有 VPN 的情况下访问，这是一个 IP 抓取器）。如果您是已登录用户，它会记录您的用户名，从而获取您的用户名和 IP。接下来，它尝试为您的账户创建后门 API 密钥。这仅在您过去一小时内输入过密码时才有效。它仅成功对 7 名近期登录的用户执行了此操作。这些 API 密钥从未被使用，且已被删除。

Next it used your account to post copies of itself, upvote other copies of itself, and post links to itself in the forum. If you were an approver level user, it would also approve copies of itself. If you were a moderator, it would try to harvest the email addresses of users. It also tried to promote other accounts. Neither of these things worked because the site was shut down before any mods had their accounts hacked. Lastly, it tried to delete all your favorites. These have been restored.

接下来，它利用您的账户发布自身的副本、为自身的其他副本点赞，并在论坛中发布指向自身的链接。如果您是审批者级别的用户，它还会批准自身的副本。如果您是版主，它会尝试收集用户的电子邮件地址。它还试图推广其他账户。由于网站在任何版主账户被黑之前就已关闭，这些操作均未成功。最后，它尝试删除您所有的收藏夹。这些收藏夹已被恢复。

Who was affected? The infected posts got about 600 page views. Not all of these views actually triggered the worm. About 300 people actually ran the worm. 200 of them were logged out and 100 logged in. The 200 logged-out users had their IPs harvested. The 100 logged-in users had their username and IPs harvested, and had their accounts temporarily hijacked to spread the worm. 48 users had a total of 1000 favorites deleted. These have been restored. 7 users had backdoor API keys created. These have been deleted. 68 copies of the worm were posted. They have all been deleted. The infected posts were upvoted a total of about 5000 times. 129 forum posts were created to help spread the worm.

谁受到了影响？受感染的帖子获得了约 600 次页面浏览量。并非所有这些浏览都触发了蠕虫。约 300 人实际运行了蠕虫。其中 200 人处于未登录状态，100 人处于登录状态。200 名未登录用户的 IP 被收集。100 名登录用户的用户名和 IP 被收集，且账户被暂时劫持以传播蠕虫。48 名用户的总计 1000 个收藏被删除，这些已恢复。7 名用户被创建了后门 API 密钥，这些已删除。68 个蠕虫副本被发布，均已删除。受感染的帖子总共被点赞约 5000 次。129 个论坛帖子被创建以帮助传播蠕虫。

How did they upload it? The ability to upload Flash files was disabled in 2021. It was accidentally enabled again after the upload process was reworked in 2022. But you still couldn't upload Flash files, because another bug prevented it. On 2026-10-28, someone submitted a pull request to fix a bug that uploads would fail if they couldn't generate thumbnails. It turned out that this was the attacker, and that by fixing this bug we were inadvertently allowing Flash files to be uploaded again. The pull request itself didn't contain any malicious code. It was a genuine one-line fix for a genuine bug. The problem was that unbeknownst to us, the bug it was fixing was the only thing preventing Flash files from being uploaded.

他们是如何上传的？上传 Flash 文件的功能在 2021 年被禁用。在 2022 年重构上传流程后，该功能被意外重新启用。但由于另一个漏洞的阻碍，当时仍然无法上传 Flash 文件。2026 年 10 月 28 日，有人提交了一个拉取请求（Pull Request），旨在修复一个导致无法生成缩略图时上传失败的漏洞。事实证明，这就是攻击者，通过修复这个漏洞，我们无意中再次允许了 Flash 文件的上传。该拉取请求本身不包含任何恶意代码。这是一个针对真实漏洞的真实单行修复。问题在于，我们当时并不知道，它所修复的那个漏洞正是阻止 Flash 文件上传的唯一屏障。

What went wrong? It was a chain of failures: The test suite wasn't thorough enough. When Flash uploads were first disabled, a test wasn't added to verify that they were disabled. Then when they were accidentally enabled again, it went unnoticed. We didn't sandbox the Ruffle player used for playing Flash videos. We didn't do this because we didn't recognize the need for it at the time, since new Flash uploads had already been disabled. We got social engineered into accepting a malicious pull request. The biggest one was: we weren't using LLMs to audit the codebase soon enough. Attackers adopted LLMs to look for exploits faster than we did, and we had to catch up fast. In the last six months or so AI has gotten really good at finding exploits, to the point where now people with no knowledge can pull off exploits that in the past would haven taken a lot of expertise.

哪里出了问题？这是一连串的失败：测试套件不够全面。当 Flash 上传首次被禁用时，没有添加测试来验证其是否已禁用。随后当它们被意外重新启用时，也没有被察觉。我们没有对用于播放 Flash 视频的 Ruffle 播放器进行沙盒处理。我们当时没有这样做，是因为我们认为没有必要，毕竟新的 Flash 上传功能已经被禁用了。我们被社会工程学手段欺骗，接受了一个恶意的拉取请求。最主要的原因是：我们没有足够早地使用 LLM 来审计代码库。攻击者采用 LLM 寻找漏洞的速度比我们快，我们必须迅速追赶。在过去六个月左右的时间里，人工智能在寻找漏洞方面变得非常出色，以至于现在即使是毫无知识的人也能实施过去需要大量专业知识才能完成的攻击。

How do I make sure my account is secure? There is no reason to believe anyone's accounts have been hacked. But if you want to be sure: Go to your Settings page. Click "Security". Change your password. Enable two-factor authentication (2FA). Check your login history for anything suspicious. Go to your Profile page, click on API keys, and check for any you don't recognize. Again, the servers themselves weren't hacked and there are no indications any accounts have been persistently compromised. But it doesn't hurt to check your account and enable 2FA.

我该如何确保我的账户安全？没有理由相信任何人的账户已被黑。但如果您想确保安全：前往您的设置页面。点击“安全”。更改您的密码。启用双重身份验证 (2FA)。检查您的登录历史记录是否有任何可疑之处。前往您的个人资料页面，点击 API 密钥，检查是否有任何您不认识的密钥。再次重申，服务器本身没有被黑，也没有迹象表明任何账户受到了持续性的损害。但检查您的账户并启用 2FA 总没有坏处。
