### Merging two datasets that don't agree with each other
### 合并两个互不兼容的数据集

I trained on two public datasets that have no common schema. PaySim is a simulation of mobile money transactions and has attributes like `oldbalanceOrg` and `newbalanceOrig`. On the other hand, the IEEE-CIS fraud detection dataset covers card transactions and has none of that; instead, it has only `ProductCD`, `card1`, `card2`, and a long tail of other anonymized features.
我使用了两个没有共同模式（schema）的公共数据集进行训练。PaySim 是移动支付交易的模拟数据，包含 `oldbalanceOrg` 和 `newbalanceOrig` 等属性。而 IEEE-CIS 欺诈检测数据集涵盖的是信用卡交易，完全没有这些属性；相反，它只有 `ProductCD`、`card1`、`card2` 以及一长串其他匿名特征。

Before any of that merging actually happens, each dataset gets validated against its own schema first, so a malformed row fails loudly instead of quietly poisoning the training set:
在进行任何合并之前，每个数据集都会先根据其自身的模式进行验证，这样格式错误的行会直接报错，而不是悄无声息地污染训练集：

```python
class PaySimSchema(BaseModel):

    newbalanceOrig: float

    newbalanceDest: float

    isFlaggedFraud: int

class IeeeCisSchema(BaseModel):

    P_emaildomain: Optional[str] = None
```

Once both sides pass validation, mapping them into one shared structure looks like this:
一旦双方都通过验证，将它们映射到一个共享结构的过程如下：

```python
df_paysim_aligned["transaction_id"] = "PAYSIM_" + df_paysim["step"].astype(str) + "_" + df_paysim.index.astype(str)
df_paysim_aligned["channel"] = df_paysim["type"].astype(str)

df_ieee_aligned["channel"] = df_ieee["ProductCD"].map(product_map).fillna("CARD_OTHER")
```

What took me way too long to realize was that having a unified schema meant the chosen features would have to be ones both datasets shared. The paySim balances didn't make the cut because IEEE-CIS doesn't have a similar field. The actual deployed model is trained using three things: the amount of transaction, one-hot encoding of the channel, and one-hot encoding of the source dataset.
我花了太长时间才意识到，拥有统一的模式意味着所选特征必须是两个数据集共有的。PaySim 中的余额数据没能入选，因为 IEEE-CIS 没有类似的字段。最终部署的模型仅使用三项内容进行训练：交易金额、渠道的独热编码（one-hot encoding）以及源数据集的独热编码。

I'm flagging that now because it matters a lot later in this piece, and ignoring it would undercut a very good thing I am trying to say here.
我在这里特别指出这一点，是因为它对后文非常重要，忽略它会削弱我接下来要表达的核心观点。

### Balancing a dataset where fraud barely shows up
### 在欺诈样本极少的数据集中实现平衡

Since there is very little fraud in both data sources, a model will be able to achieve high accuracy simply by predicting "no fraud" a lot of times while not predicting many fraud instances.
由于两个数据源中的欺诈样本都非常少，模型只需大量预测“无欺诈”即可获得高准确率，而无需准确识别出多少欺诈实例。

I used SMOTE to oversample the minority class on the training split only, with a fallback to a hand-written interpolation version in case imbalanced-learn wasn't available in the deployment environment:
我仅在训练集上使用 SMOTE 对少数类进行过采样，并编写了一个手写的插值版本作为备选，以防部署环境中无法使用 `imbalanced-learn` 库：

```python
k_neigh = min(2, sum(y_train == 1) - 1)
if k_neigh >= 1:
    smote = SMOTE(random_state=42, k_neighbors=k_neigh)
    X_train_res, y_train_res = smote.fit_resample(X_train, y_train)
else:
    print("[Warning] Insufficient minority class samples to perform SMOTE. Skipping resampling.")
    X_train_res, y_train_res = X_train, y_train
```

The zero dependency fallback uses interpolation between a sample and its closest neighbors through Euclidean distance to produce synthetic minority samples, which is essentially a simpler version of how SMOTE works internally but left in the code for the sake of preventing failure when in a minimalistic setting.
这个零依赖的备选方案通过欧几里得距离在样本及其最近邻之间进行插值，从而生成合成的少数类样本。这本质上是 SMOTE 内部工作原理的简化版，保留在代码中是为了防止在极简环境下出现运行失败。

### Six models and a spreadsheet that argues with itself
### 六个模型与一份自相矛盾的电子表格

I trained Random Forest, Logistic Regression, XGBoost (both baseline and optimized versions), and LightGBM (again, both baseline and optimized). Every one of them ran through the same evaluation helper, so the numbers would actually be comparable instead of six slightly different measurement approaches wearing one result:
我训练了随机森林、逻辑回归、XGBoost（基准版和优化版）以及 LightGBM（同样包含基准版和优化版）。每一个模型都通过同一个评估辅助函数运行，以确保数据具有可比性，而不是用六种略有不同的测量方法来得出结果：

```python
def fit_eval_and_log(model, name, filename, params, fit_kwargs=None):
    print(f"\n--- Training Model: {name} ---")
    start_time = time.time()
    model.fit(X_train, y_train, **(fit_kwargs or {}))
    print(f"[Training Info] Model training completed in {time.time() - start_time:.3f} seconds.")
    
    preds = model.predict(X_test)
    probs = model.predict_proba(X_test)[:, 1] if hasattr(model, "predict_proba") else preds.astype(float)
    
    metrics = {
        "Accuracy": round(accuracy_score(y_test, preds), 6),
        "Precision": round(precision_score(y_test, preds, zero_division=0), 6),
        "Recall": round(recall_score(y_test, preds, zero_division=0), 6),
        "AUC-ROC": round(roc_auc_score(y_test, probs), 6),
        "AUC-PR": round(average_precision_score(y_test, probs), 6),
    }
    print(f"{name} Test AUC-PR:", metrics["AUC-PR"])
    joblib.dump(model, filename)
    log_experiment_run(name, params, metrics)
    return metrics
```
