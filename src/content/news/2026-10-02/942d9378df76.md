# WSL containers are now generally available
# WSL 容器现已正式发布 (General Availability)

September 29, 2026 WSL containers is now generally available By Logan Iyer, Corporate Vice President, Windows Platform + Developer
2026 年 9 月 29 日，WSL 容器现已正式发布。作者：Logan Iyer，Windows 平台与开发者部门企业副总裁。

WSL is central to our commitment to making Windows the best place to build, run and manage Linux workloads. As AI, cloud-native development, containers, and open-source ecosystems continue to converge on Linux, more developers are choosing to perform these workloads directly on Windows devices. We’re continuing our journey towards this goal with a new feature in WSL: WSL containers, which is generally available today.
WSL 是我们致力于将 Windows 打造成构建、运行和管理 Linux 工作负载的最佳平台的关键。随着人工智能、云原生开发、容器和开源生态系统持续向 Linux 靠拢，越来越多的开发者选择直接在 Windows 设备上执行这些工作负载。我们通过 WSL 的一项新功能——WSL 容器，继续朝着这一目标迈进，该功能于今日正式发布。

To try it out, simply run `wsl --update` in your terminal or download the latest release from GitHub and you will gain access to:
想要尝试该功能，只需在终端中运行 `wsl --update`，或从 GitHub 下载最新版本，即可获得以下功能：

*   **WSL containers CLI:** `wslc.exe` to directly build, run and deploy Linux containers on Windows, or use its built-in alias `container.exe` to run the same familiar container commands.
*   **WSL 容器命令行工具 (CLI)：** 使用 `wslc.exe` 直接在 Windows 上构建、运行和部署 Linux 容器，或者使用其内置别名 `container.exe` 来运行熟悉的容器命令。

*   **WSL containers API:** Access functions to run Linux containers programmatically in your native Windows apps – unlocking scenarios like running local AI workloads or using cloud-based containerized applications locally.
*   **WSL 容器 API：** 提供相关函数，以便在原生 Windows 应用程序中以编程方式运行 Linux 容器，从而解锁诸如运行本地 AI 工作负载或在本地使用基于云的容器化应用程序等场景。

For a deeper look at how WSL containers are built, how they work with WSL, and the architecture behind the platform, see our WSL containers architecture blog. Let’s get into what’s new with GA.
如需深入了解 WSL 容器的构建方式、其与 WSL 的协作原理以及平台背后的架构，请参阅我们的 WSL 容器架构博客。接下来，让我们看看正式发布版 (GA) 有哪些新特性。

### New commands and capabilities
### 新命令与新功能

Since public preview, we’ve continued to evolve WSL containers and our focus has been on making every day container workflows simpler, improving visibility into running environments, and adding the flexibility needed to manage containers at scale. As part of the GA release, we’ve introduced several new commands and capabilities across container lifecycle, networking, and observability.
自公开预览版以来，我们不断改进 WSL 容器，重点在于简化日常容器工作流、提高运行环境的可见性，并增加大规模管理容器所需的灵活性。作为正式发布版的一部分，我们在容器生命周期、网络和可观测性方面引入了多项新命令和功能。

Here are a few highlights, and you can view the full change logs on our releases page:
以下是部分亮点，您可以在我们的发布页面查看完整的更新日志：

*   `wslc container restart` — restart a running container
*   `wslc container restart` — 重启正在运行的容器
*   `wslc container cp` — copy files in and out via tar archive
*   `wslc container cp` — 通过 tar 归档文件在容器内外复制文件
*   `wslc system info` — see the state of your container environment at a glance
*   `wslc system info` — 一目了然地查看容器环境的状态
*   `wslc network connect` and `wslc network disconnect` — attach and detach containers from networks
*   `wslc network connect` 和 `wslc network disconnect` — 将容器连接到网络或从网络中分离
*   `wslc network create` now supports arbitrary network driver options
*   `wslc network create` 现支持任意网络驱动程序选项
*   `wslc events` – Streams real time container activity
*   `wslc events` – 实时流式传输容器活动
*   Container health checks are now supported
*   现已支持容器健康检查
*   `--stop-timeout` on `wslc create` and `wslc run`, including -1 for an infinite timeout
*   `wslc create` 和 `wslc run` 支持 `--stop-timeout` 参数，包括设置为 -1 以实现无限超时
*   `--mount` support during `wslc create` and `wslc run`
*   `wslc create` 和 `wslc run` 期间支持 `--mount`
*   A configurable storage path for the default `wslc` session, so you can put your container storage on the drive you want.
*   为默认 `wslc` 会话提供可配置的存储路径，以便您可以将容器存储放置在所需的驱动器上。

Alongside new commands and platform enhancements for developers, we’ve also focused on helping organizations adopt WSL containers with the governance and security controls required for production environments.
除了为开发者提供新命令和平台增强功能外，我们还致力于帮助企业采用 WSL 容器，并提供生产环境所需的治理和安全控制。

### Enterprise manageability for WSL containers
### WSL 容器的企业级可管理性

This release extends Microsoft Intune and Microsoft Defender for Endpoint (MDE) integrations in WSL to include container workflows as well. MDE’s existing plugin for WSL has been augmented to also include support for containers. MDE can surface process, file and network activity from WSL containers and connect that activity back to Windows host, helping security teams investigate suspicious activity without creating a separate security workflow.
此版本扩展了 WSL 中 Microsoft Intune 和 Microsoft Defender for Endpoint (MDE) 的集成，使其涵盖了容器工作流。MDE 现有的 WSL 插件已得到增强，增加了对容器的支持。MDE 可以从 WSL 容器中提取进程、文件和网络活动，并将这些活动关联回 Windows 主机，从而帮助安全团队调查可疑活动，而无需创建单独的安全工作流。

Microsoft Intune has also added controls to enable or disable WSL container and restrict image pulls to approved registries. Additionally, on your Intune dashboard you will see new settings specific to the WSL container feature:
Microsoft Intune 还增加了启用或禁用 WSL 容器的控制选项，并限制仅能从已批准的注册表中拉取镜像。此外，在您的 Intune 仪表板上，您将看到针对 WSL 容器功能的新设置：

*   **Allow WSL containers access** – Control access to the entire WSL containers feature.
*   **允许 WSL 容器访问** – 控制对整个 WSL 容器功能的访问权限。
*   **WSL containers registry allow list** – For WSL containers enterprise adoption, organizations need stronger controls over the container images that can be introduced into their environment. With container registry allow lists, administrators can define approved registries and help ensure developers only pull container images from that list, that meet organizational security and compliance requirements.
*   **WSL 容器注册表允许列表** – 对于企业采用 WSL 容器而言，组织需要对引入其环境的容器镜像进行更严格的控制。通过容器注册表允许列表，管理员可以定义已批准的注册表，并确保开发者仅从该列表中拉取符合组织安全和合规性要求的容器镜像。

You can view the WSL enterprise doc pages to learn more on how to set up WSL for your company.
您可以查看 WSL 企业文档页面，了解更多关于如何为您的公司设置 WSL 的信息。

### Partner and community integrations
### 合作伙伴与社区集成

Partners and community contributors are bringing WSL containers into the editors, terminals and desktop tools developers already use, adding support for WSLc into existing projects or creating new ones. We’re grateful for the fantastic community contributions that continue to expand the ecosystem around WSL containers.
合作伙伴和社区贡献者正在将 WSL 容器引入开发者已经在使用的编辑器、终端和桌面工具中，为现有项目添加对 WSLc 的支持或创建新项目。我们非常感谢社区的出色贡献，这些贡献不断扩展了 WSL 容器的生态系统。

*   **VS Code dev container support:** Use `wslc` as your default driver for creating and interacting with VS Code dev containers.
*   **VS Code 开发容器支持：** 使用 `wslc` 作为创建和交互 VS Code 开发容器的默认驱动程序。
*   **Aspire:** Aspire can use WSL Containers as first-class container runtime.
*   **Aspire：** Aspire 可以将 WSL 容器作为一流的容器运行时使用。
*   **VS Code container extension:** A popular extension to manage your containers in VS Code, now supports `wslc`.
*   **VS Code 容器扩展：** 一个用于在 VS Code 中管理容器的流行扩展，现已支持 `wslc`。
*   **Lazywslc:** A TUI dashboard to manage your WSL containers.
*   **Lazywslc：** 一个用于管理 WSL 容器的 TUI（终端用户界面）仪表板。
*   **WSL Container Desktop:** WinUI 3 desktop app for managing WSL containers, Kubernetes (k3s) and container registries.
*   **WSL Container Desktop：** 用于管理 WSL 容器、Kubernetes (k3s) 和容器注册表的 WinUI 3 桌面应用程序。
*   **WSLc remote:** A short wrapper script to run `wslc` from within WSL distros.
*   **WSLc remote：** 一个简短的包装脚本，用于在 WSL 发行版内运行 `wslc`。

### What’s next for WSL
### WSL 的未来展望

Over time, we see Linux on Windows evolving beyond a development environment into a strategic execution platform for AI and cloud-native workloads, participating in the same enterprise security, management, and governance frameworks as Windows. We will continue to invest in the broader WSL experience, and in context of this release wanted to highlight two WSL specific items on our roadmap.
随着时间的推移，我们看到 Linux on Windows 正在从开发环境演变为 AI 和云原生工作负载的战略执行平台，并参与到与 Windows 相同的企业安全、管理和治理框架中。我们将继续投资于更广泛的 WSL 体验，并结合此次发布，重点介绍我们路线图中的两项 WSL 特定事项。

*   **Adding `wslc compose`:** Our top feature request for WSLc is adding compose support, and this will be our focus for our next iterations. Our aim is for `wsl compose up` to work with your existing `compose.yaml` files, unchanged. We’ve started on this and hope to share more soon.
*   **添加 `wslc compose`：** 我们收到的关于 WSLc 的首要功能请求是添加 compose 支持，这将是我们下一次迭代的重点。我们的目标是让 `wsl compose up` 能够直接使用您现有的 `compose.yaml` 文件，无需任何修改。我们已经开始了这项工作，并希望很快能分享更多进展。

*   **WSL fundamental improvements:** We are also actively investigating how to better improve some of the core platform capabilities for WSL including networking, cross-OS file performance and more. You can see some of this work today with `wslc`, supporting up to 2x faster performance when accessing Windows files from Linux environments, helping reduce one of the most common cross-OS bottlenecks. It also introduces the new `consomme` network mode...
*   **WSL 基础改进：** 我们也在积极研究如何更好地改进 WSL 的一些核心平台功能，包括网络、跨操作系统文件性能等。您今天可以通过 `wslc` 看到部分成果，它在从 Linux 环境访问 Windows 文件时支持高达 2 倍的性能提升，有助于减少最常见的跨操作系统瓶颈之一。它还引入了新的 `consomme` 网络模式……
