**本次审查重点关注当部署新实现、代理存储布局发生变更，或升级流程本身被修改（例如添加新模块、更改治理流程或迁移至新的 L2 Roll-up）时所产生的兼容性风险。**

Key Findings:
Category | Severity | Summary
--- | --- | ---
Storage‑slot collisions | High | Several upcoming upgrades (e.g., “Dynamic Collateral Factors”) introduce new state variables without reserving a dedicated storage gap, risking overwriting existing ReserveData fields.
Upgrade‑authority compromise | Critical | The Timelock delay (24 h) is shorter than the typical 48 h used by comparable protocols, providing a narrow window for governance attacks, especially when combined with flash‑loan‑driven voting power accumulation.
Delegatecall‑based modules | Medium | The Interest‑Rate Model is called via delegatecall. A malicious implementation could corrupt the proxy’s storage or re‑enter the core contract.
Cross‑chain bridge state sync | Medium | L2 bridge adapters share the same proxy admin but maintain independent storage. A mis‑aligned upgrade on L1 could desynchronize the L2 state, leading to “phantom” liquidity or double‑counted collateral.
Reentrancy in liquidation path | Low‑Medium | The liquidation function uses external calls to the borrower’s collateral token (ERC‑20 transfer). Although a reentrancy guard exists, the guard is bypassed when the call is made via a custom CollateralAdapter that does not inherit the guard.
Oracle upgrade path | Low | The protocol relies on immutable Chainlink feeds, but a future “oracle aggregator” upgrade is planned. No explicit fallback or emergency pause is defined for this component.

Overall, the protocol’s upgrade framework is well‑designed, but the lack of rigorous storage‑gap discipline and short governance timelock constitute the most pressing compatibility concerns.

**总体而言，该协议的升级框架设计良好，但缺乏严格的存储间隙规范以及较短的治理时间锁构成了最紧迫的兼容性问题。**

2. Identified Attack Vectors
# Vector Description Exploit Scenario Impact
1 Storage‑slot collision / layout drift Adding new state variables without a reserved storage gap (e.g., uint256[50] private __gap;) can overwrite existing data when the new implementation is linked to the proxy. An attacker proposes an upgrade that adds a bool emergencyShutdown; at slot 0, overwriting ReserveData.totalLiquidity. The TVL displayed to users becomes corrupted, enabling false liquidation triggers. High – Mis‑reported balances, unintended liquidations, loss of collateral.
2 Governance timelock abuse The 24‑hour timelock can be bypassed by a flash‑loan‑driven vote swing that executes a malicious upgrade before the community can react. An attacker borrows $200 M in flash loans, stakes the borrowed assets in governance, queues a malicious implementation that adds a mint(address,uint256) function, and executes it after 24 h. Critical – Direct minting of assets, unlimited supply, total loss of funds.
3 Delegatecall injection The Interest‑Rate Model (IRM) is invoked via delegatecall. A malicious IRM can modify the proxy’s storage or call back into the core contract. Deploy a malicious IRM that, on getBorrowRate, writes address(this) into the admin slot, effectively hijacking upgrade control. High – Loss of upgrade authority, potential for arbitrary code execution.
4 Cross‑chain state desynchronisation L2 bridge adapters maintain separate storage but share the same admin. An upgrade that changes the L1 proxy’s storage layout without updating the L2 adapter can cause mismatched reserve indices. After an L1 upgrade, the L2 adapter still reads reserveCount from slot 5 (old layout) while L1 now stores it at slot 7, leading to “ghost” reserves on L2. Medium – Inconsistent liquidity reporting, possible double‑spend across chains.
5 Reentrancy via custom collateral adapters Certain collateral adapters (e.g., for LP tokens) bypass the global nonReentrant modifier. An attacker creates a malicious LP token that, during transfer, calls back into liquidateBorrow, re‑entering the liquidation loop and draining collateral. Low‑Medium – Partial loss of collateral, reputation damage.
6 Oracle aggregator upgrade without pause Future upgrade to a composite oracle aggregator lacks an emergency pause. If the aggregator is compromised, price feeds could be manipulated for an extended period before the community notices. Low – Potential for price manipulation, but mitigated by existing Chainlink feeds.
7 Admin key leakage via multi‑sig mis‑configuration The admin key for the proxy is a 3‑of‑5 multisig. One signer’s private key is stored on a cloud VM without hardware‑security‑module (HSM) protection. An attacker exfiltrates the key, signs an upgrade transaction, and pushes a malicious implementation. Critical – Same impact as #2.
