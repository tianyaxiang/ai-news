# 1,619 Compiler Messages, Four Real Causes: A CA 2E to RPGLE Compile Reference

**1,619 Compiler Messages, Four Real Causes: A CA 2E to RPGLE Compile Reference**
1619 条编译器消息，四个根本原因：CA 2E 到 RPGLE 编译参考指南

**What actually happens when a Synon model becomes a compiled RPGLE program — and how to read the wall of errors when it doesn't**
当 Synon 模型被编译为 RPGLE 程序时，幕后究竟发生了什么？以及当编译失败时，如何解读那堆积如山的错误信息。

**CA 2E (Synon) does not write RPG. It writes a model — files, functions, action diagrams — and a code generator turns that model into RPG source, then a separate step turns that source into a compiled object.**
CA 2E (Synon) 并不直接编写 RPG 代码。它编写的是一个模型——包含文件、函数和操作图——然后由代码生成器将该模型转换为 RPG 源代码，接着通过一个独立的步骤将该源代码编译为目标对象。

**Most of the confusion people have converting CA 2E work to RPGLE comes from not knowing where the seam between those two steps is. This is a reference for that seam: the path from model to object, what it looks like when it breaks, and how to read a compile listing with over a thousand messages in it without treating each one as a separate problem.**
人们在将 CA 2E 工作转换为 RPGLE 时产生的大多数困惑，都源于不知道这两个步骤之间的分界线在哪里。本文档旨在作为该分界线的参考：从模型到对象的路径、出错时的表现，以及如何解读包含上千条消息的编译列表，而不必将每一条都视为一个独立的问题。

**No library names, program names, or field names below are real. They've been left out entirely rather than replaced with placeholders, because the mechanics and the error categories don't need them to make sense.**
下文中的库名、程序名或字段名均非真实名称。它们被完全省略，而不是用占位符代替，因为理解其机制和错误分类并不需要这些名称。

### Two things to know before you touch a model
### 在接触模型前需要了解的两件事

**Generate and Create are different steps, and only one of them needs the model to be right. "Generate" turns a function's action diagram into RPG source and writes it to a member. It does not compile anything. "Create" compiles and binds that source into an object. CA 2E's menu lets you do both in one submitted job, which is convenient right up until that job fails, because the failure message tells you almost nothing.**
“生成 (Generate)”和“创建 (Create)”是不同的步骤，且只有其中一个步骤要求模型必须正确。“生成”将函数的操作图转换为 RPG 源代码并写入成员中，它不会进行任何编译。“创建”则负责编译并将该源代码绑定为目标对象。CA 2E 的菜单允许你在一个提交的作业中同时完成这两项操作，这在作业成功时很方便，但一旦作业失败，其错误消息几乎无法提供任何有价值的信息。

**Target HLL "RPG IV" does not mean free-format. This is the part that surprises people coming from a "just convert it to RPGLE free" mindset. Setting a function's target high-level language to RPG IV makes CA 2E generate traditional fixed-format RPG — column-based calculation specs, sequence numbers, no free-format delimiters. It compiles as an RPGLE member type, and ILE will bind it like any other RPGLE program, but the source itself reads like an older RPG dialect with a newer header.**
目标高级语言 (HLL) 设置为“RPG IV”并不意味着自由格式 (Free-format)。这一点常让那些抱着“直接把它转换成 RPGLE Free”心态的人感到惊讶。将函数的目标高级语言设置为 RPG IV，会使 CA 2E 生成传统的固定格式 RPG——即基于列的计算规范、序列号，且没有自由格式的分隔符。它会以 RPGLE 成员类型进行编译，ILE 也会像对待其他 RPGLE 程序一样对其进行绑定，但源代码本身读起来更像是带有新头部的旧式 RPG 方言。

**If you want genuinely free-format output, that is a second, deliberate step after the generated source compiles clean — never before. Free-format conversion tools rewrite syntax; they don't fix logic. Feed one a program that doesn't compile and you get free-format syntax wrapped around the same bug, which is now harder to spot because it looks new. So the realistic pipeline is: model, then generate, then fixed-format RPG IV source, then compile clean, and only then — if you actually want free-format — convert the syntax. Not model straight to free-format RPGLE in one step. Nothing in the generator does that for you.**
如果你想要真正的自由格式输出，那必须是在生成的源代码成功编译之后，进行第二个刻意的步骤——绝不能提前。自由格式转换工具只会重写语法，而不会修复逻辑。如果你将一个无法编译的程序喂给转换工具，你只会得到包裹着同样 Bug 的自由格式语法，而且由于外观变了，这些 Bug 反而更难被发现。因此，现实的流程应该是：模型 -> 生成 -> 固定格式 RPG IV 源代码 -> 成功编译，然后——如果你确实需要自由格式——再进行语法转换。不要试图一步到位从模型直接生成自由格式的 RPGLE，生成器中没有任何功能可以为你做到这一点。

### The path from model to object
### 从模型到对象的路径

1. **Get the model on the library list. The generation commands need to find both the model itself and the separate generation library it automatically maintains alongside it. If the underlying product library isn't available, you get a blunt message before you even get near your own code, something to the effect of the product library not being installed for high-level-language generation.**
   **将模型加入库列表。** 生成命令需要同时找到模型本身以及它自动维护的独立生成库。如果底层的产品库不可用，你甚至还没接触到自己的代码，就会收到一条直白的错误消息，大意是用于高级语言生成的程序库未安装。

2. **Copy the model if you don't want to touch the real one. There's a menu option specifically for commands that copy a model, and the command behind it lets you copy from one model to a new one while telling it not to create any objects — just the definitions. That gives you a sandbox to generate and compile in without touching anything the real model owns.**
   **如果你不想改动真实模型，请复制一份。** 菜单中有一个专门用于复制模型的选项，其背后的命令允许你将一个模型复制到新模型中，同时指定不创建任何对象——仅复制定义。这为你提供了一个沙盒环境，可以在不触碰真实模型任何内容的情况下进行生成和编译。

3. **Set the function's target language. Inside the copied model, find the function you're working on and set its target high-level language to RPG IV. This is a setting on the individual function, not on the model as a whole — different functions in the same model can target different languages.**
   **设置函数的目标语言。** 在复制的模型中，找到你正在处理的函数，将其目标高级语言设置为 RPG IV。这是针对单个函数的设置，而不是针对整个模型的——同一个模型中的不同函数可以指向不同的语言。

4. **Generate the function. From the screen that lists a model's functions, there's an option to generate. This writes the RPG IV source member into the model's generation library, whether or not anything gets compiled afterward. The member existing is not evidence the program works. It's evidence the generator ran.**
   **生成函数。** 在列出模型函数的屏幕上，有一个生成选项。无论后续是否进行编译，它都会将 RPG IV 源代码成员写入模型的生成库中。成员的存在并不代表程序可以运行，它只代表生成器已经运行过。

5. **Submit the model create request. There's a follow-on option that submits generation and compilation and binding together as one batch job. If that job finishes clean, you have a working object and nothing below this line matters. If it doesn't —**
   **提交模型创建请求。** 还有一个后续选项，可以将生成、编译和绑定作为一个批处理作业一起提交。如果该作业顺利完成，你就得到了一个可用的对象，下文的内容也就无关紧要了。如果失败了——

### When the submit job dies, stop debugging the submit job
### 当提交的作业失败时，停止调试该作业本身

**The message you get back is short: a job identifier, and a note that it ended abnormally. That's it. No compiler message, no line number, no indication of which of the several things inside a generate-then-compile-then-bind job actually failed. You can chase this through job logs and the model's own error lists, and sometimes that's the right call if the model itself is broken — a missing access path, an undefined function reference. But most of the time, the model is fine and the generated source has a problem the compiler would tell you about immediately, if you asked the compiler directly instead of through that wrapper.**
你收到的消息非常简短：一个作业标识符，以及一条异常结束的提示。仅此而已。没有编译器消息，没有行号，也没有任何迹象表明“生成-编译-绑定”作业中的哪一个环节真正失败了。你可以通过作业日志和模型自身的错误列表去追查，如果模型本身损坏（例如缺少访问路径、未定义的函数引用），这有时是正确的做法。但大多数情况下，模型是正常的，而生成的源代码存在问题——如果你直接询问编译器而不是通过那个包装器，编译器会立即告诉你问题所在。

**You already have the source. The generate step wrote it, independent of whether the create step's compile succeeded. Go find it with the standard member-list utility, pointed at the generation library and the source file the generator writes to. The member is sitting there — generated, uncompiled or compiled-and-failed. Compile it directly from that member list. Now you're not waiting on a batch job to tell you it died. You're looking at the actual compiler output, the same listing you'd get for hand-written source.**
你已经拥有了源代码。生成步骤已经将其写入，无论创建步骤的编译是否成功。使用标准的成员列表工具，指向生成库和生成器写入的源文件，去找到它。该成员就在那里——已生成，但未编译或编译失败。直接从该成员列表中进行编译。现在，你无需等待批处理作业来告诉你它失败了。你正在查看实际的编译器输出，这与你手动编写源代码时得到的列表完全相同。

**That's the pivot: the moment the black-box submit job fails, drop out of the model layer entirely and work with the generated source like it's just RPGLE, because at this point it is.**
这就是转折点：一旦黑盒提交作业失败，就完全跳出模型层，将生成的源代码视为普通的 RPGLE 代码来处理，因为此时它确实就是 RPGLE 代码。
