# 5 AI Skills That Will Keep Data Scientists Relevant in 2027
# 2027 年数据科学家保持竞争力的 5 项 AI 技能

Anyone can now build an LLM demo with a single API call. Getting that same feature to survive real users, real data, and a real bill is a different job.
现在，任何人都可以通过一个 API 调用构建一个大模型（LLM）演示。但要让同一功能在真实用户、真实数据和真实账单的考验下存活下来，则是另一回事。

That job comes down to five skills that show up in almost every production system I've worked on or reviewed: retrieval, routing, guardrails, evals, and agent loops.
这项工作归结为五项技能，它们几乎出现在我参与或评估过的每一个生产系统中：检索（Retrieval）、路由（Routing）、护栏（Guardrails）、评估（Evals）和智能体循环（Agent loops）。

Each one answers a question a frontier model alone can't handle. Where does my company's data come from? Why is the bill this high? What happens when someone sends a hostile prompt? Did my last change make things better or worse? How do I get a model to do multi-step work without falling over?
每一项技能都回答了仅靠前沿模型无法解决的问题。我的公司数据从哪里来？为什么账单这么高？当有人发送恶意提示词时会发生什么？我上次的修改是让系统变好了还是变差了？如何让模型在不崩溃的情况下完成多步骤任务？

### One wrapper so the code runs anywhere
### 一个封装，让代码随处运行

Fill in one branch of this function with the SDK you have. The rest of the article never touches a provider directly, so switching models means editing this function and nothing else.
用你现有的 SDK 填充此函数的一个分支。本文的其余部分不会直接接触任何服务商，因此切换模型只需修改此函数，无需其他操作。

```python
def call_llm(prompt: str, system: str = "", model: str = "default") -> str:
    """Send a prompt to whatever model you have and return the text reply."""
    # --- Option A: OpenAI-compatible (OpenAI, Together, a local vLLM, Ollama) ---
    from openai import OpenAI
    client = OpenAI() # reads OPENAI_API_KEY; pass base_url=... to hit a local server
    resp = client.chat.completions.create(
        model="gpt-4o-mini" if model == "default" else model,
        messages=[
            {"role": "system", "content": system},
            {"role": "user", "content": prompt},
        ],
    )
    return resp.choices[0].message.content
```

### Skill #1: RAG, grounding a model in your own data
### 技能 #1：RAG（检索增强生成），让模型基于你的数据进行回答

A base model doesn't know your company's documents, and fine-tuning on them every time they change is slow and expensive. Retrieval-augmented generation (RAG) fetches the relevant documents at query time and passes them to the model as context. It's still the most common LLM pattern in production, and it's usually the first thing a curriculum teaches.
基础模型不了解你公司的文档，且每次文档更新都进行微调既缓慢又昂贵。检索增强生成（RAG）在查询时获取相关文档，并将其作为上下文传递给模型。这仍然是生产中最常见的 LLM 模式，也是课程中通常教授的第一项内容。

The interesting work is in the retrieval. Whether you return the right chunk depends on how you split documents (chunking), whether you combine keyword and semantic search (hybrid retrieval), and whether you reorder results before they reach the model (reranking).
有趣的工作在于检索。能否返回正确的片段取决于你如何拆分文档（分块）、是否结合了关键词和语义搜索（混合检索），以及在结果到达模型之前是否进行了重排序（重排序）。

Here's a small pipeline that runs on CPU with no external service. It embeds a handful of documents, retrieves the closest ones to a question, and answers from them.
这是一个在 CPU 上运行且无需外部服务的小型流水线。它对少量文档进行嵌入（Embedding），检索出与问题最相关的文档，并据此回答。

```python
# pip install sentence-transformers numpy
import numpy as np
from sentence_transformers import SentenceTransformer

embedder = SentenceTransformer("all-MiniLM-L6-v2") # small, runs on a laptop

docs = [
    "Our refund policy allows returns within 30 days of purchase.",
    "Standard shipping takes 3 to 5 business days.",
    "The Pro plan costs 49 dollars per month and includes priority support.",
    "Password resets happen from the account settings page.",
]

# Embed the knowledge base once, up front.
doc_vectors = embedder.encode(docs, normalize_embeddings=True)

def retrieve(question: str, k: int = 2) -> list[str]:
    """Return the k documents closest in meaning to the question."""
    q = embedder.encode([question], normalize_embeddings=True)[0]
    scores = doc_vectors @ q # cosine similarity
    top = np.argsort(scores)[::-1][:k]
    return [docs[i] for i in top]

def answer(question: str) -> str:
    context = "\n".join(retrieve(question))
    prompt = f"Answer using only the context below.\n\nContext:\n{context}\n\nQuestion: {question}"
    return call_llm(prompt, system="You are a support assistant.")

print(answer("How long do I have to send something back?"))
```

Notice the question says "send something back" and the matching document says "returns". Keyword search would miss that. The embedding match catches it because the two phrases sit close in vector space.
注意，问题中提到的是“send something back”（退回东西），而匹配的文档中写的是“returns”（退货）。关键词搜索会漏掉这一点，但嵌入匹配捕捉到了它，因为这两个短语在向量空间中非常接近。

**How to learn RAG:** Build this over your own notes, then break it on purpose. Ask a question the retriever gets wrong and watch the answer go bad. Fix it by changing the chunk size. Add BM25 keyword search next to the embeddings (hybrid retrieval) and measure whether answers improve. When you outgrow a numpy array, move to a vector database (FAISS, Qdrant, or Pinecone) and a framework like LlamaIndex or LangChain.
**如何学习 RAG：** 用你自己的笔记构建这个系统，然后故意破坏它。问一个检索器会出错的问题，观察回答如何变差。通过调整分块大小来修复它。在嵌入搜索旁边添加 BM25 关键词搜索（混合检索），并衡量回答是否有所改善。当你不再满足于 numpy 数组时，转向向量数据库（如 FAISS、Qdrant 或 Pinecone）以及 LlamaIndex 或 LangChain 等框架。

### Skill #2: Model routing: paying for the model the task needs
### 技能 #2：模型路由：为任务所需的模型付费

Sending every request to a frontier model is the fastest way to a bill nobody can explain. Routing sends easy, high-volume requests to a small or local model and saves the expensive model for the hard ones. Adding a cache for repeated prompts is reported to cut 40% to 70% off production inference bills.
将每个请求都发送给前沿模型是导致账单无法解释的最快方式。路由将简单、高频的请求发送给小型或本地模型，并将昂贵的模型留给复杂任务。据报道，为重复的提示词添加缓存可以减少 40% 到 70% 的生产推理成本。
