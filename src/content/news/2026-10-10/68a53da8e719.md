An AI coding agent can now take a Vercel domain purchase from name search through the final buy command. The important boundary is where that command runs: in a non-interactive session, vercel domains buy returns a structured error and suggested next commands instead of completing the purchase. A person must review and confirm the transaction in an interactive terminal or the Vercel dashboard. That changes the useful delegation question. You can ask an agent to research names and prepare the purchase, but what exactly should it bring back, and what should you verify before you authorize it? Vercel’s October 9, 2026 changelog describes the new sequence. Its CLI documentation lists the relevant commands and the separate steps for attaching and verifying a domain.

AI 编码代理现在可以完成从域名搜索到最终购买指令的 Vercel 域名购买流程。关键的界限在于该指令运行的位置：在非交互式会话中，`vercel domains buy` 会返回结构化错误和建议的后续指令，而不是直接完成购买。用户必须在交互式终端或 Vercel 控制面板中审查并确认交易。这改变了有效授权的问题。你可以要求代理研究名称并准备购买，但它究竟应该带回什么，以及你在授权前应该核实什么？Vercel 2026 年 10 月 9 日的更新日志描述了这一新流程。其 CLI 文档列出了相关指令以及附加和验证域名的独立步骤。

What the agent can do before approval The flow has four commands, each with a distinct job: vercel domains search <query> finds candidate names from a keyword or domain fragment. vercel domains check <domain> checks whether a candidate is available. vercel domains price <domain> returns pricing for one or more domain names. vercel domains buy <domain> initiates the purchase workflow. This lets an agent do the repetitive discovery work: explore naming variations, check availability, and assemble the pricing information for your shortlist. Vercel says the CLI also ships an agent-facing skill for the sequence, so the agent can be guided through discovery, pricing, and purchase without you spelling out each command. Treat the first three commands as research. Ask for the exact domain string, its availability result, and the returned purchase and renewal information. If the domain is unavailable or the pricing output is unclear, have the agent stop and report that; don’t let it silently substitute a different name. The choice of a public name is a product decision, even when the agent can search faster than you can.

代理在批准前能做什么？该流程包含四个指令，每个指令都有明确的任务：`vercel domains search <query>` 根据关键词或域名片段查找候选名称；`vercel domains check <domain>` 检查候选域名是否可用；`vercel domains price <domain>` 返回一个或多个域名的定价；`vercel domains buy <domain>` 启动购买工作流。这让代理可以完成重复的发现工作：探索命名变体、检查可用性并汇总候选名单的定价信息。Vercel 表示，CLI 还为该序列提供了面向代理的技能，因此无需你逐一拼写指令，代理即可完成发现、定价和购买流程。将前三个指令视为研究。要求提供确切的域名字符串、可用性结果以及返回的购买和续费信息。如果域名不可用或定价输出不明确，让代理停止并报告；不要让它悄悄替换为其他名称。选择公开名称是一项产品决策，即使代理的搜索速度比你快。

Where the approval boundary sits Vercel’s safeguard is tied to how the purchase command is run. In a non-interactive environment, vercel domains buy does not finish the purchase. It returns a structured, machine-readable error and suggested next commands, handing the confirmation back to the user. Vercel describes this as preventing the agent from spending money without approval. You can then complete the confirmation in an interactive terminal or in the dashboard. Before you do, check three things Vercel calls out directly: the price, whether automatic renewal is on, and the registrant contact details. Read the values shown at confirmation time; don’t rely on a number or contact record copied from an earlier search. That boundary is useful, but it does not make the review optional. The agent can still find a name you did not intend, select a confusingly similar spelling, or report a candidate that is unsuitable for your product. Human confirmation is the point where you verify that the exact string, account scope, renewal choice, and registration details match your intent.

批准界限在哪里？Vercel 的安全保障与购买指令的运行方式挂钩。在非交互式环境中，`vercel domains buy` 不会完成购买。它会返回一个结构化的、机器可读的错误和建议的后续指令，将确认权交还给用户。Vercel 将此描述为防止代理在未经批准的情况下花钱。随后，你可以在交互式终端或控制面板中完成确认。在操作之前，请检查 Vercel 直接指出的三件事：价格、自动续费是否开启以及注册人联系方式。请阅读确认时显示的值；不要依赖从早期搜索中复制的数字或联系记录。该界限很有用，但这并不意味着审查是可选的。代理仍可能找到你并不想要的名称、选择拼写容易混淆的名称，或报告不适合你产品的候选名称。人工确认是你核实确切字符串、账户范围、续费选择和注册详情是否符合你意图的关键环节。

A review checklist for the handoff Ask the agent to return a compact handoff before it attempts the final command: The exact domain, copied as plain text so you can inspect spelling and punctuation. The availability check for that exact name. The current registration and renewal details returned by the CLI. The automatic-renewal choice it expects the confirmation step to use. The registrant contact details that will be submitted. The Vercel scope in which the purchase will be made. Any unresolved question that could change your choice. Then compare that handoff with the confirmation screen. If the domain, price, renewal setting, contact details, or account scope differs, stop and resolve the mismatch before confirming. A domain registration is a real purchase attached to an account; a prompt saying “buy something suitable” is not a substitute for checking the final transaction. You can also set the boundary in your task instructions: have the agent search and compare candidates, but require it to stop before completing the interactive confirmation. The non-interactive behavior is the technical backstop described by Vercel; clear task wording helps keep the intended handoff visible in the conversation.

移交审查清单：在代理尝试执行最终指令前，要求其返回一份简洁的移交信息：确切的域名（以纯文本复制，以便你检查拼写和标点）；该名称的可用性检查结果；CLI 返回的当前注册和续费详情；它预期在确认步骤中使用的自动续费选项；将要提交的注册人联系方式；购买将要进行的 Vercel 范围；任何可能改变你选择的未决问题。然后将该移交信息与确认屏幕进行对比。如果域名、价格、续费设置、联系方式或账户范围有差异，请在确认前停止并解决不匹配问题。域名注册是关联到账户的真实购买；“购买合适的域名”这样的提示不能替代对最终交易的检查。你也可以在任务指令中设定界限：让代理搜索并比较候选名称，但要求它在完成交互式确认前停止。非交互式行为是 Vercel 描述的技术保障；清晰的任务措辞有助于在对话中保持预期的移交可见性。

Buying and connecting are separate steps The domains CLI reference describes vercel domains buy <domain> as buying a domain for the current scope. It separately documents vercel domains add <domain> <project> to add a domain to the current scope or a Vercel project, and vercel domains verify <domain> to check DNS configuration. In other words, the purchase command and the project-connection workflow are distinct operations in the CLI. After the registration is confirmed, decide whether and where the domain should be connected. Check the selected project, then use the documented add and verification steps for that project. Do not let a successful purchase stand in for a verified connection: the registration can be complete while the app’s domain configuration still needs attention. This distinction also helps you keep the agent’s authority narrow. It can prepare a purchase handoff without being asked to change project configuration, DNS, or deployment settings. Add those tasks only when you want them, and review the expected domain and project before they run.

购买和连接是独立的步骤。域名 CLI 参考文档将 `vercel domains buy <domain>` 描述为为当前范围购买域名。它另外记录了 `vercel domains add <domain> <project>` 用于将域名添加到当前范围或 Vercel 项目，以及 `vercel domains verify <domain>` 用于检查 DNS 配置。换句话说，购买指令和项目连接工作流在 CLI 中是不同的操作。注册确认后，决定是否以及将域名连接到何处。检查选定的项目，然后对该项目使用记录的添加和验证步骤。不要让成功的购买代替已验证的连接：注册可能已完成，但应用的域名配置仍需关注。这种区分也有助于你将代理的权限限制在较小范围内。它可以在不被要求更改项目配置、DNS 或部署设置的情况下准备购买移交。仅在你需要时添加这些任务，并在它们运行前审查预期的域名和项目。

A practical sequence to delegate For a new app, use a staged request: Ask the agent to search for names based on a short list of words or naming constraints. Ask it to check availability and pricing for the exact candidates you want to compare. Have it return the review checklist above, including renewal and registrant details when available. Review the handoff and choose one exact domain. Complete the purchase confirmation yourself in the interactive terminal or dashboard. Only after registration, decide whether to add the domain to a Vercel project and verify its DNS configuration. This puts the agent on the preparation side and you on the purchase decision.
