# Gliver completes the Guix desktop

Gliver completes the Guix desktopBy Christine Lemmer-Webber on Sun 22 November 2026There's a bit of irony in the title. At the time of writing, Gliver, a Guile based window manager for Wayland in the style of StumpWM and Emacs, isn't yet in Guix. There is, however, an open PR to add Gliver to Guix. However, what that patch is really waiting on is an upcoming release of Gliver which will solve many bugs.

标题带有一点讽刺意味。在撰写本文时，Gliver（一个基于 Guile、模仿 StumpWM 和 Emacs 风格的 Wayland 窗口管理器）尚未被收录进 Guix。不过，目前有一个将 Gliver 添加到 Guix 的合并请求（PR）处于开放状态。然而，该补丁实际上是在等待 Gliver 的下一个版本发布，该版本将修复许多错误。

Notably, that release will be 0.0.5. If that sounds early, Gliver still is early. There are bugs, and you will probably have to file issues for some that you discover. There are also some noticeable missing features. But it doesn't matter. Gliver is everything I want from a desktop experience, and I suspect for many of the kinds of people who read my blog, it will be for them as well.

值得注意的是，该版本将是 0.0.5。如果这听起来很早期，那是因为 Gliver 确实还处于早期阶段。目前存在一些错误，你可能需要为你发现的问题提交反馈。此外，还有一些明显的缺失功能。但这并不重要。Gliver 是我所期望的桌面体验的一切，我怀疑对于许多阅读我博客的人来说，它也会是他们的理想之选。

Gliver might not be for everyone. But if the following appeals to you: a live-hackable, written in Guile Scheme, tiling window manager which looks good, feels good, and whose codebase is understandable and, indeed, encourages you to understand and explore it, Gliver is for you.

Gliver 可能并不适合所有人。但如果以下特点吸引你：一个可实时修改、用 Guile Scheme 编写、外观精美、手感舒适，且代码库易于理解、甚至鼓励你去理解和探索的平铺式窗口管理器，那么 Gliver 就很适合你。

Why I think Gliver mattersI think Anna Liberty's Towards Understandable Software is a must-read. Call it a counter-vision to the vibe bobsled. Anna lays out that software should be more understandable, not less, and easy to participate in even for people with no programming background. While Gliver doesn't itself try all the approaches Anna lays out, it is an understandable codebase.

为什么我认为 Gliver 很重要？我认为 Anna Liberty 的《迈向可理解的软件》（Towards Understandable Software）是一篇必读文章。可以将其视为对“氛围雪橇”（vibe bobsled）的一种反向愿景。Anna 指出，软件应该变得更易于理解，而不是相反，并且即使对于没有编程背景的人来说，也应该易于参与。虽然 Gliver 本身并没有尝试 Anna 提出的所有方法，但它确实拥有一个易于理解的代码库。

Furthermore, Gliver is participatory. Gliver invites you to learn its internals and explore it. By default, Gliver's describe-key functionality opens a window where you can type the command you are thinking of, and it will show you what key it is bound to... but you can also type in a key sequence, and it'll show you what command that runs.

此外，Gliver 具有参与性。它邀请你去学习其内部结构并进行探索。默认情况下，Gliver 的“描述按键”（describe-key）功能会打开一个窗口，你可以在其中输入你正在思考的命令，它会显示该命令绑定到了哪个按键……你也可以输入一个按键序列，它会显示该序列运行的是什么命令。

More than that, by default Gliver opens a unix domain socket in ~/.local/state/gliver/repl.sock. You can connect to this, say with Geiser. You are live! You know that command you just looked up with the above describe-key interface? Why not try running it at the REPL! Hey, how does it work? Well Geiser already has a feature for that; by default typing M-. (geiser-edit-symbol-at-point) will jump you right to the definition, and you can explore how that code works! You can run commands manually at the REPL, you can inspect the state of the system, you can hack away, you can take the useful things you have learned and add them to your init.scm file so that the next time Gliver starts things are more the way you want them than last time. But of course there's no need to wait, this is a lisp style system! You can eval those changes and apply them immediately and carry on your way.

不仅如此，Gliver 默认会在 ~/.local/state/gliver/repl.sock 处打开一个 Unix 域套接字。你可以连接到它，比如使用 Geiser。你现在处于实时状态！还记得你刚才用上述 describe-key 界面查到的那个命令吗？何不在 REPL 中运行它试试！嘿，它是怎么工作的？Geiser 已经具备了相应功能；默认情况下，输入 M-. (geiser-edit-symbol-at-point) 就会直接跳转到定义处，你可以探索该代码是如何工作的！你可以在 REPL 中手动运行命令，检查系统状态，进行修改，并将学到的有用内容添加到你的 init.scm 文件中，这样下次启动 Gliver 时，一切就会更符合你的心意。当然，无需等待，这是一个 Lisp 风格的系统！你可以评估这些更改并立即应用它们，然后继续你的工作。

Maybe this all sounds pretty technical, and even technically elite. And I think Gliver is probably not very accessible to non-scheme-hackers. But on the other hand, it could help you become a Scheme hacker.

也许这一切听起来非常技术化，甚至带有技术精英色彩。我认为 Gliver 对于非 Scheme 黑客来说可能不太容易上手。但另一方面，它或许能帮助你成为一名 Scheme 黑客。

When I started using Emacs, I was not a programmer. By extending Emacs, I became a programmer. (My background is not in CS; I was an interdisciplinary humanities student.) Emacs invites you to explore how it works by customizing it. My entire career would not have likely happened if Emacs did not welcome me into this process.

当我开始使用 Emacs 时，我并不是一名程序员。通过扩展 Emacs，我成为了一名程序员。（我的背景并非计算机科学；我曾是一名跨学科人文专业的学生。）Emacs 通过自定义功能邀请你去探索它的工作原理。如果 Emacs 没有欢迎我参与这个过程，我的整个职业生涯很可能就不会发生。

Gliver takes the same approach. But instead of Emacs Lisp, which is a hackable but honestly not really great lisp, it uses Guile Scheme, which is lovely. And notably, this is the same language as Guix.

Gliver 采取了同样的方法。但它使用的不是 Emacs Lisp（一种可修改但老实说并不算优秀的 Lisp），而是 Guile Scheme，这非常棒。值得注意的是，这与 Guix 使用的是同一种语言。

There is more I want to say on this, and I will in a future article. In many ways I think Blender is also an interesting example of reflective software in action, and actually does expose some of the ideas such as visual programming for non-programmers in a way that Emacs and Gliver don't, with great success too. But that's to discuss later.

关于这一点我还有更多想说的，我会在以后的文章中讨论。在许多方面，我认为 Blender 也是一个反射式软件实践的有趣例子，它实际上以一种 Emacs 和 Gliver 所没有的方式，成功地向非程序员展示了诸如可视化编程等理念。但这留待以后讨论。

But as for the choice to switch. I have gotten tired of using systems that feel like they know better than I do. I have spent most of my days using GNOME, but without getting too much into it, I have been burnt way too many times by a paternalistic attitude which seems at the center of its design philosophy. When I did the latest upgrade and found out that custom application launcher shortcuts did not work anymore, and I could not figure out for the life of me why, I decided I didn't actually care to try to solve the problem this time. I was going to try something else.

至于切换系统的选择，我已经厌倦了使用那些自以为比我更了解我需求的系统。我大部分时间都在使用 GNOME，但不想深入讨论细节，我已经被其设计哲学核心中那种家长式的态度伤害过太多次了。当我进行最近一次升级，发现自定义应用程序启动快捷方式不再起作用，且我无论如何也找不出原因时，我决定这次我不想再费心去解决这个问题了。我打算尝试点别的。

Which is when I re-discovered Gliver. Thanks to ebeem for working on Gliver and jfred for having been an earlier adopter than I was and who helped me with some messy this-isnt-yet-packaged trickiness.

就在那时，我重新发现了 Gliver。感谢 ebeem 对 Gliver 的开发，也感谢 jfred，他比我更早采用该软件，并帮助我解决了一些尚未打包的混乱棘手问题。

A bit more on Gliver before we wrap upI suppose I've already said most of it, but a few more details. One interesting aspect of Gliver is that it uses River, which is a Wayland compositor which is designed as a framework for building window managers on top of. Building small window managers had become a lot harder to do with the move from X11 to Wayland; River provides a common foundation that makes it much more possible.

在结束之前再多说一点关于 Gliver 的内容。我想我已经说得差不多了，但还有一些细节。Gliver 的一个有趣之处在于它使用了 River，这是一个 Wayland 合成器，旨在作为构建窗口管理器的框架。随着从 X11 向 Wayland 的迁移，构建小型窗口管理器变得困难得多；River 提供了一个共同的基础，使得这变得更加可行。

Gliver allegedly supports different tiling modes, but I don't use them, I just use manual tiling. I like splitting up my screens the way I like them. I know I want this thing here and that thing there. Gliver shines at this kind of manual flow. It also has multiple "tabbed" windows stacked in each pane of the frames (in Gliver, each of those panes is called a "container"). You can move around what workspace and container a window "belongs to" with keybindings. Personally I bound <super>-x to be a keymapping with sub-bindings for splitting things up with the same equivalent keys as they are in emacs, since those mappings are burned into my brain.

据称 Gliver 支持不同的平铺模式，但我并不使用它们，我只使用手动平铺。我喜欢按照自己的方式分割屏幕。我知道我想要这个东西放在这里，那个东西放在那里。Gliver 在这种手动流程上表现出色。它还在框架的每个窗格中堆叠了多个“标签页”窗口（在 Gliver 中，每个窗格被称为一个“容器”）。你可以通过按键绑定来移动窗口所属的工作区和容器。就我个人而言，我将 <super>-x 绑定为一个按键映射，并设置了子绑定来分割窗口，使用的按键与 Emacs 中的等效按键相同，因为这些映射已经刻在我的脑海里了。

The default theme is very nice. You can customize its colors but black and purple is exactly my jam already.

默认主题非常漂亮。你可以自定义颜色，但黑色和紫色正合我意。
