LookAtMyQuant is a quantization compiler. It measures how much each stored piece of a model hurts the output when compressed. It then picks a code for each piece so the whole model fits a size budget with the least damage.

LookAtMyQuant 是一个量化编译器。它会测量模型中每个存储部分在压缩后对输出造成的损害程度，然后为每个部分选择一种编码，以确保整个模型在满足大小预算的同时，将性能损失降至最低。

On Gemma 4 E2B, its GGUF has 12× lower KL than Q4_K_M at the same file size. The method and every result are on the site.

在 Gemma 4 E2B 上，其 GGUF 格式在相同文件大小下，KL 散度比 Q4_K_M 低 12 倍。该方法及所有结果均可在网站上查阅。

The code is under the MIT license.

该代码采用 MIT 许可证。

LookAtMyQuant 2 takes Qwen3.5-4B to 1.23 GB, 2.3 bits per weight. The file solves 330 of 540 exact-answer math problems. Prism ML's Bonsai 2 Ternary 4B solves 328 at 1.20 GB, and the original solves 359. Its KL from the original on held-out text is 0.45 nats, against 0.59 for Bonsai.

LookAtMyQuant 2 将 Qwen3.5-4B 压缩至 1.23 GB，即每个权重 2.3 位。该文件能解决 540 道精确答案数学题中的 330 道。Prism ML 的 Bonsai 2 Ternary 4B 在 1.20 GB 大小下能解决 328 道，而原始模型能解决 359 道。其在留出文本集上与原始模型的 KL 散度为 0.45 nats，而 Bonsai 为 0.59 nats。

The recipe is post-training quantization with trellis codes, calibrated on the model's own worked math solutions with digit tokens weighted 10×, and with bits allocated per row by Fisher information. 4,000 steps of distillation follow, in which every layer is re-quantized once from the original weights. The page has the findings, the full recipe and its cost, about $34 of GPU time.

其方案是使用网格编码（trellis codes）进行训练后量化，通过模型自身的数学解题过程进行校准，其中数字标记的权重被加权 10 倍，并根据 Fisher 信息量按行分配位数。随后进行 4,000 步蒸馏，期间每一层都从原始权重重新量化一次。网页中包含了研究结果、完整方案及其成本（约 34 美元的 GPU 时间）。

The same recipe takes Qwen3.8-27B from 53.7 GB to 7.2 GB, 2.1 bits per weight, calibrated and distilled on English prose and chat, code and math. The file solves 401 of the 540 math problems, as many as the original, and Unsloth's UD-IQ2_XXS GGUF of the same size solves 348. It also scores above that GGUF on HumanEval (73.8% against 67.1%), MMLU (78.8% against 75.0%) and GSM8K (94.5% against 92.7%).

同样的方案将 Qwen3.8-27B 从 53.7 GB 压缩至 7.2 GB，即每个权重 2.1 位，并在英语散文、对话、代码和数学数据上进行了校准和蒸馏。该文件能解决 540 道数学题中的 401 道，与原始模型持平，而相同大小的 Unsloth UD-IQ2_XXS GGUF 能解决 348 道。它在 HumanEval（73.8% 对 67.1%）、MMLU（78.8% 对 75.0%）和 GSM8K（94.5% 对 92.7%）上的得分也高于该 GGUF。

Beside it sits a 4-bit DSpine drafter (1.02 GB, converted from tencent/Qwen3.8-27B-DSpine-b16 with runtime_mlx/convert_dspine.py and packed with pack_drafter.py), which roughly doubles decode speed on math and code on Apple silicon.

旁边还有一个 4 位的 DSpine 草稿模型（1.02 GB，通过 runtime_mlx/convert_dspine.py 从 tencent/Qwen3.8-27B-DSpine-b16 转换并使用 pack_drafter.py 打包），它在 Apple Silicon 上将数学和代码的解码速度提高了约一倍。

Extended to a 26.4B physical / 5.4B active 3×-looped MoE (L6–17 looped 3× = 48 logical visits, 128 experts top-8), the compiler and full-MoE proximal fine-tuning (SQYFR) compress thinkingmachines/Inkling-2-Mini from 18.89 GB of text weights into four Apple Silicon MLX builds: 5.38 GB (1.65 bpp), 8.87 GB (2.72 bpp), 11.18 GB (3.43 bpp), and 12.76 GB (3.92 bpp) — combining 4 KB SRAM hashed block-vector trellis codes (ht2/ht3), row trellis codes (rtr1/rtr4), a tr2 floor on the tail lm_head bucket (head.7), and exact native NVFP4 passthrough (69/192 and 109/192 highest-sensitivity expert buckets kept at 0.0 error in the 11.2 GB and 12.8 GB builds).

扩展至 26.4B 物理参数 / 5.4B 激活参数的 3 倍循环 MoE（L6–17 循环 3 次 = 48 次逻辑访问，128 个专家 top-8），该编译器和全 MoE 近端微调（SQYFR）将 thinkingmachines/Inkling-2-Mini 从 18.89 GB 的文本权重压缩为四个 Apple Silicon MLX 构建版本：5.38 GB (1.65 bpp)、8.87 GB (2.72 bpp)、11.18 GB (3.43 bpp) 和 12.76 GB (3.92 bpp) —— 结合了 4 KB SRAM 哈希块向量网格编码 (ht2/ht3)、行网格编码 (rtr1/rtr4)、尾部 lm_head 桶 (head.7) 上的 tr2 下限，以及精确的原生 NVFP4 直通（在 11.2 GB 和 12.8 GB 构建中，69/192 和 109/192 个最高敏感度专家桶保持 0.0 误差）。

Install the dependencies and download the model and WikiText-2. The code reads SmolLM2-360M's config when it starts, so do this first.

安装依赖项并下载模型和 WikiText-2。代码在启动时会读取 SmolLM2-360M 的配置，因此请先执行此操作。

Measure. This compresses one piece at a time, leaves the rest exact, and records the KL to the original model. The full set for this model, 2,312 measurements, took about 50 minutes on an L40S.

测量。此步骤每次压缩一个部分，其余部分保持精确，并记录与原始模型的 KL 散度。该模型全套 2,312 次测量在 L40S 上耗时约 50 分钟。

Allocate. This picks one code per piece, with the least summed KL inside the budget. It needs no GPU. This command uses the SmolLM2-360M measurements in this repository, with a budget of 3.044 bits per weight.

分配。此步骤为每个部分选择一种编码，以在预算内实现最小的 KL 散度总和。它不需要 GPU。此命令使用本仓库中的 SmolLM2-360M 测量数据，预算为每个权重 3.044 位。
