# Changes on freedesktop.org

Today we launched a change that has been a long time in the making: The updated website for freedesktop.org, as well as the refreshed wiki.freedesktop.org are live now! You can read the announcement here, this blog post elaborates a bit on it and on the background of the changes, as well as future plans.

今天我们发布了一项酝酿已久的变更：freedesktop.org 的更新版网站以及焕然一新的 wiki.freedesktop.org 现已上线！您可以在此处阅读公告，本篇博文将详细介绍其背景及未来计划。

Why change anything? The freedesktop.org website has been a wiki for a long time, which definitely was the right call in its inception. A wiki is very much in spirit of Freedesktop’s mission statement to foster collaboration between desktop environments and to be a place to create de-facto standards. However, over the years, working with the wiki became a bit of an issue: Not only did we face multiple spam-apocalypses (which in part motivated the switch to IkiWiki in 2013 and resulted in us heavily restricting write access to the wiki), but it also meant that official project information, finished specifications, half-finished proposals and pages nobody had touched in fifteen years were all sitting next to each other.

为什么要做出改变？长期以来，freedesktop.org 网站一直以 Wiki 的形式存在，这在创立之初无疑是正确的选择。Wiki 非常符合 Freedesktop 的使命，即促进桌面环境之间的协作，并成为创建事实标准的场所。然而，多年来，使用 Wiki 逐渐成为一个问题：我们不仅面临多次垃圾信息泛滥（这在一定程度上促使我们在 2013 年转向 IkiWiki，并导致我们严格限制了 Wiki 的写入权限），而且这意味着官方项目信息、已完成的规范、未完成的提案以及十五年来无人问津的页面全都混杂在一起。

Since 2000 when Freedesktop.org was started, the project has grown so much and has had so many associated projects and specifications over the decades that it is now very difficult for new people to get an overview what is current and what state the software projects and specifications hosted by Freedesktop.org are in. Having only a wiki as a large and somewhat disorganized pile of information did not help with that issue, so I worked to split things up: We now have a website as well as a wiki, using different designs to distinguish the two, and serving different purposes.

自 2000 年 Freedesktop.org 启动以来，该项目在过去几十年中发展迅速，拥有了众多的关联项目和规范，以至于新人很难概览当前的情况，也难以了解 Freedesktop.org 所托管的软件项目和规范处于何种状态。仅靠一个庞大且杂乱无章的 Wiki 无法解决这个问题，因此我致力于将它们拆分：我们现在拥有一个网站和一个 Wiki，通过不同的设计来区分两者，并服务于不同的目的。

Website & website plans The website at www.freedesktop.org will be the place for “official”, or rather, more curated information. Now that the new website is live, its content is still largely that of the old wiki. Over the next weeks, I will be working on cleaning up its contents and listings. For example, I will clearly split active projects from archived ones, add missing ones, and also work towards synchronizing the specifications hosted on the former wiki / website with the ones listed on specifications.fd.o. So, basically I will do an inventory check of Freedesktop. That work has already started, but until now, I could not make any public changes to not disrupt workflows or make my own future work harder by having diverging information in two places (website & wiki). I also wanted to make it easier for people to find information on how to get involved with Freedesktop and associated projects, so the new website now has a more discoverable section for that. The new website is a static site hosted via GitLab Pages and using Pelican. You can view its sources if you like.

网站及网站计划：www.freedesktop.org 网站将成为发布“官方”或经过精心整理的信息的地方。随着新网站上线，其内容目前仍主要来自旧的 Wiki。在接下来的几周里，我将致力于清理其内容和列表。例如，我将明确区分活跃项目和归档项目，添加缺失的项目，并努力将原 Wiki/网站上托管的规范与 specifications.fd.o 上列出的规范进行同步。简而言之，我将对 Freedesktop 进行一次盘点。这项工作已经开始，但在此之前，我无法进行任何公开更改，以免干扰工作流程，或因两处（网站和 Wiki）信息不一致而增加未来的工作难度。我还希望让人们更容易找到参与 Freedesktop 及相关项目的信息，因此新网站为此设置了一个更易于发现的板块。新网站是一个通过 GitLab Pages 托管并使用 Pelican 构建的静态网站。如果您愿意，可以查看其源代码。

Wiki changes Of course, we also still want to keep the Wiki and all of its rich history around! It remains the easy-to-edit place for collaboration on upcoming projects and specifications. Wiki edits must now happen through GitLab instead of the old IkiWiki web interface. While this sounds like an additional barrier to edit the wiki, it is significantly easier than requesting an account on annarchy to edit the old Wiki through the web interface. It also still allows us to keep the existing history as well as spam protection measures. In order to use the wiki with GitLab Pages and to keep the history easily accessible and readable, I rewrote the Git history of the wiki to make it pretend that all changes always happened in a content subdirectory. So, if commit signatures are missing and hashes are different: That is the only reason why. There have been no content changes or other metadata changes (and we still have a copy of the pristine wiki Git repository). For the fd.o wiki, we are now also using Hari’s IkiWiki template that is already in use on the X.org website and which is much easier on the eyes.

Wiki 的变更：当然，我们仍然希望保留 Wiki 及其所有丰富的历史记录！它依然是协作处理即将开展的项目和规范的便捷编辑场所。现在，Wiki 的编辑必须通过 GitLab 进行，而不是旧的 IkiWiki Web 界面。虽然这听起来像是增加了编辑 Wiki 的门槛，但它比在 annarchy 上申请账户并通过 Web 界面编辑旧 Wiki 要容易得多。它还使我们能够保留现有的历史记录以及垃圾信息防护措施。为了将 Wiki 与 GitLab Pages 一起使用并保持历史记录易于访问和阅读，我重写了 Wiki 的 Git 历史记录，使其看起来像是所有更改都发生在内容子目录中。因此，如果提交签名丢失且哈希值不同，这就是唯一的原因。内容或其他元数据没有发生任何变化（我们仍然保留着原始 Wiki Git 仓库的副本）。对于 fd.o Wiki，我们现在还使用了 Hari 的 IkiWiki 模板，该模板已在 X.org 网站上使用，视觉效果更佳。

Next steps At the moment, I am mostly concerned with ensuring that the change has not broken any existing links and all systems keep working. After that, the wiki 🡘 website deduplication work will start and we can modernize both the content of the website and wiki. If you find a broken link, an outdated page or anything else that looks wrong, please file an issue or, even better, open a merge request. For the wiki, you are very welcome to just fix or otherwise update the page directly. I did reach out to all wiki editors and projects impacted by this change in advance, but since there are so many people and projects involved, it is always possible to miss someone or something. If you found a bug, need edit permissions, or need help with anything, don’t hesitate to ping me: You can find me as ximion in OFTC’s #freedesktop IRC channel, in the very recently created #xdg-specs channel on the Freedesktop Matrix space, or you can email me. Thank you!

后续步骤：目前，我主要关注的是确保此次变更没有破坏任何现有链接，并确保所有系统正常运行。此后，Wiki 与网站的去重工作将开始，我们将能够对网站和 Wiki 的内容进行现代化改造。如果您发现损坏的链接、过时的页面或任何看起来不对劲的地方，请提交 Issue，或者更好的是，提交合并请求（Merge Request）。对于 Wiki，非常欢迎您直接修复或更新页面。我已提前联系了所有受此变更影响的 Wiki 编辑和项目，但由于涉及的人员和项目众多，难免会有遗漏。如果您发现 Bug、需要编辑权限或需要任何帮助，请随时联系我：您可以在 OFTC 的 #freedesktop IRC 频道、最近创建的 Freedesktop Matrix 空间中的 #xdg-specs 频道找到我（ID 为 ximion），或者给我发电子邮件。谢谢！
