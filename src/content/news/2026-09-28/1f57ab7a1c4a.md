### I'm building FGOTHS: A Go + Templ + HTMX project generator with SSE/FlatBuffers and HMR
### 我正在构建 FGOTHS：一个结合 Go + Templ + HTMX，并支持 SSE/FlatBuffers 和 HMR 的项目生成器

I'm building FGOTHS (For The GOTH Stack) for my own studio because I needed a way to bootstrap production-ready Go webapps with zero cloud overhead, no heavy JS frameworks, and a fast dev loop. It generates single static binaries (<10MB) targeting bare FROM scratch containers while delivering 100k+ req/s.
我正在为我的工作室构建 FGOTHS (For The GOTH Stack)，因为我需要一种能够快速启动生产级 Go Web 应用的方法，要求零云开销、无需沉重的 JS 框架，并具备快速的开发循环。它生成的单个静态二进制文件（小于 10MB）可直接部署在 `FROM scratch` 容器中，同时能提供每秒 10 万次以上的请求处理能力。

Key Features Two Presets: api (Flat JSON API) and webapp (MVC + Templ + HTMX). True HMR: Uses SSE + FlatBuffers to swap Templ HTML fragments in real-time, keeping form states, focus, and scroll position intact. Zero CGO & Minimal Footprint: Compiles to a ~8.8MB binary with a low dependency surface area. Embedded Runtime: Native reverse proxy, circuit breaker, health-checked failover, and deployment policies built right into the binary. The project is released under the Apache 2.0 license. I’d love to get feedback from the community on the architecture, the SSE/FlatBuffers HMR implementation, or the embedded runtime design!
核心功能包括：两种预设：api（扁平化 JSON API）和 webapp（MVC + Templ + HTMX）。真正的 HMR：使用 SSE + FlatBuffers 实时替换 Templ HTML 片段，同时保持表单状态、焦点和滚动位置不变。零 CGO 与极小体积：编译后的二进制文件约为 8.8MB，依赖项极少。嵌入式运行时：内置原生反向代理、断路器、健康检查故障转移和部署策略。该项目采用 Apache 2.0 许可证发布。我非常期待社区对该架构、SSE/FlatBuffers HMR 实现或嵌入式运行时设计的反馈！
