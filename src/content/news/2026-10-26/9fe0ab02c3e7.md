ThinkRail is the agentic IDE that gets better every time you use it — learning your project through living specs today, and building its own capabilities tomorrow. We built a rich interface around the pi coding agent, isolated work into separate workspaces, and gave the agent durable project knowledge through living specs and reusable skills. Next, we're adding full extension support, so ThinkRail can create the tools it needs based on how you actually work.

ThinkRail 是一款代理式 IDE，它会随着你的使用不断进化——今天通过动态规范（living specs）学习你的项目，明天就能构建属于自己的能力。我们围绕 pi 编码代理构建了丰富的界面，将工作隔离在独立的 workspace 中，并通过动态规范和可重用技能赋予代理持久的项目知识。接下来，我们将增加完整的扩展支持，让 ThinkRail 能够根据你的实际工作方式创建所需的工具。

Website: thinkrail.ai · Blog: thinkrail.ai/blog ⭐ If you find ThinkRail useful, give it a star — it helps others discover it. A pi session and the change it made, scoped to an isolated git-worktree workspace.

网站：thinkrail.ai · 博客：thinkrail.ai/blog ⭐ 如果你觉得 ThinkRail 有用，请给它点个星标——这能帮助其他人发现它。这是一个 pi 会话及其所做的更改，作用于一个隔离的 git-worktree 工作区。

What you get Isolated workspaces. Open any git repo as a project and cut workspaces from it as git worktrees, each with its own branch and working directory. Agents work in parallel without touching your checkout; merge the good branch, delete the rest. You can also attach existing worktrees or explicitly work in the project folder itself.

你将获得隔离的工作区。你可以将任何 git 仓库作为项目打开，并将其切分为 git worktrees 作为工作区，每个工作区都有自己的分支和工作目录。代理可以并行工作而不会触碰你的检出（checkout）；合并好的分支，删除其余的。你也可以附加现有的 worktrees 或直接在项目文件夹中工作。

Finished and dormant workspaces settle onto a per-project shelf on their own — when their pull request merges or closes, or after a quiet week — and come back the moment you work in them. The topbar shows where the active branch stands against origin and its pull request, with the next step one click away: publish, push, or open a PR described from the plan, the commits, your PR template, or an agent-written draft.

已完成和休眠的工作区会自动进入每个项目的“搁置区”（shelf）——当它们的拉取请求（PR）合并或关闭后，或者在一周未活动后——当你再次操作它们时，它们会立即恢复。顶部栏显示了当前分支相对于远程仓库及其拉取请求的状态，只需点击一下即可执行下一步：发布、推送，或根据计划、提交记录、你的 PR 模板或代理撰写的草稿来打开一个 PR。

Once a GitHub PR is open it shows the CI checks and review decision, and lets you mark it ready, hand failing checks or a diverged branch to the agent, merge it with the repository's last-used method, reopen it, or delete the remote branch.

一旦 GitHub PR 打开，它会显示 CI 检查和审查决定，并允许你将其标记为就绪，将失败的检查或分叉的分支交给代理处理，使用仓库上次使用的方法合并它，重新打开它，或删除远程分支。

A real IDE around the agent. A splittable workbench of Monaco editor tabs, a Files tree with live git change marks and a Changed view, terminals, and documents — all scoped to the active workspace. Leave anchored review comments on files and diffs and send them to a chat as structured context, or open the worktree in your installed IDE.

围绕代理的真正 IDE。一个可拆分的工作台，包含 Monaco 编辑器标签页、带有实时 git 更改标记的文件树和“已更改”视图、终端和文档——所有这些都限定在当前活动的工作区内。你可以在文件和差异对比上留下锚定审查评论，并将它们作为结构化上下文发送到聊天中，或者在你已安装的 IDE 中打开该 worktree。

Chats that stream like the engine thinks. Several concurrent pi sessions per workspace, each with its own model and live token and cost readout. Steer a running turn or queue a follow-up, delegate to subagents, and work a shared plan the agent updates and you edit — each completed step can be committed and reviewed on its own.

像引擎思考一样流式传输的聊天。每个工作区可以有多个并发的 pi 会话，每个会话都有自己的模型以及实时 token 和成本读数。你可以引导正在进行的任务或排队后续任务，委派给子代理，并处理一个由代理更新、你进行编辑的共享计划——每个完成的步骤都可以单独提交和审查。

Specs as ground truth. A connected graph of SPEC.md files lives beside the code; the agent reads, searches, and maintains it through dedicated spec_* tools, so intent survives the session. The read-only Specs tool renders the graph as a tree in the workbench.

作为事实依据的规范。一个由 SPEC.md 文件组成的连接图存在于代码旁边；代理通过专门的 spec_* 工具读取、搜索和维护它，从而使意图在会话结束后依然存在。只读的“规范”工具在工作台中将该图渲染为树状结构。

Skills and workflows. Portable Agent Skills you already keep for other coding agents are read in place, and bundled workflows guide project setup, design brainstorming, and shipping a pull request — pushing the workspace branch and opening or updating its GitHub PR through your own gh.

技能与工作流。你为其他编码代理保留的可移植代理技能可以直接读取，捆绑的工作流可以指导项目设置、设计头脑风暴和发布拉取请求——通过你自己的 gh 工具推送工作区分支并打开或更新其 GitHub PR。

Agent tools beyond the shell. Web research, and inline diagrams, option comparisons and file previews rendered right in the chat — when the agent proposes a UI change it shows a before/after mockup you can comment on like a diff. Settings → Extensions lists the ThinkRail extensions the agent gets and lets you switch each one off.

超越 Shell 的代理工具。网络研究、内联图表、选项比较和文件预览直接在聊天中渲染——当代理提出 UI 更改建议时，它会显示一个你可以像对比差异一样进行评论的修改前后模型。设置 → 扩展列出了代理获取的 ThinkRail 扩展，并允许你关闭其中的任何一个。

MCP servers. Connect the MCP servers in your pi mcp.json (or add them, and a few presets, from Settings): ThinkRail asks in the chat before calls the server does not mark read-only (or always allows the tools you trust in a project), keeps servers a repository defines off until you approve them, signs you in to OAuth servers from Settings, and shows each chat's servers next to its background commands and subagents.

MCP 服务器。在你的 pi mcp.json 中连接 MCP 服务器（或者从设置中添加它们及一些预设）：ThinkRail 会在调用服务器之前在聊天中询问（除非该服务器被标记为只读，或者你已在项目中信任该工具），保持仓库定义的服务器处于关闭状态直到你批准，从设置中登录 OAuth 服务器，并在每个聊天的后台命令和子代理旁边显示其使用的服务器。

Your providers, your credentials. Sign in with JetBrains AI or connect any provider through pi's own auth. ThinkRail has no accounts of its own.

你的提供商，你的凭据。使用 JetBrains AI 登录或通过 pi 自身的身份验证连接任何提供商。ThinkRail 本身没有账户。

Desktop app or browser. A native desktop app, or the thinkrail CLI that opens the same app in your browser. Both embed the same engine host; app state lives under ~/.thinkrail.

桌面应用或浏览器。一个原生桌面应用，或者通过 thinkrail CLI 在浏览器中打开同一个应用。两者都嵌入了相同的引擎宿主；应用状态存储在 ~/.thinkrail 下。

Your language. Settings → Language follows your system language or a language you pick; English and Simplified Chinese are built in. Add a language ThinkRail doesn't ship yet by dropping a translated en.json into ~/.thinkrail/locales — it applies as you save. Agent replies and tool output stay as the agent wrote them.

你的语言。设置 → 语言跟随你的系统语言或你选择的语言；内置了英语和简体中文。通过将翻译好的 en.json 放入 ~/.thinkrail/locales，可以添加 ThinkRail 尚未提供的语言——保存后即可生效。代理的回复和工具输出保持代理编写时的原样。

The project's spec graph as a tree, with the spec itself rendered alongside.

项目的规范图以树状结构显示，规范本身在旁边渲染。

Install ThinkRail ships in two additive forms: a native desktop installer and the self-contained thinkrail CLI. Both are published with SHA256SUMS on the releases page.

安装 ThinkRail 以两种附加形式发布：原生桌面安装程序和独立的 thinkrail CLI。两者都在发布页面上附带 SHA256SUMS 发布。

Desktop Download the thinkrail-desktop-* asset for your platform: macOS (Apple Silicon) — open the DMG. There is no Intel desktop build. Windows x64 — extract the complete setup ZIP, then run its setup executable in place, next to its payload. Linux x64 / ARM64 — extract the setup tarball and run installer.

桌面版 下载适用于你平台的 thinkrail-desktop-* 资源：macOS (Apple Silicon) — 打开 DMG。没有 Intel 桌面版本。Windows x64 — 解压完整的安装 ZIP，然后在有效载荷旁边运行其安装可执行文件。Linux x64 / ARM64 — 解压安装压缩包并运行安装程序。

Desktop builds need glibc 2.38+ with GTK 3, WebKitGTK 4.1, Ayatana AppIndicator 3, and librsvg 2 — Ubuntu 24.04 or newer: sudo apt install libgtk-3-0 libwebkit2gtk-4.1-0 libayatana-appindicator3-1 librsvg2-2

桌面版本需要 glibc 2.38+ 以及 GTK 3、WebKitGTK 4.1、Ayatana AppIndicator 3 和 librsvg 2 — Ubuntu 24.04 或更新版本：sudo apt install libgtk-3-0 libwebkit2gtk-4.1-0 libayatana-appindicator3-1 librsvg2-2

Packaged stable and nightly desktop builds check for updates in the background and offer them in Settings → Updates: Download → Preparing update → Install & Restart. Nothing is applied until you choose Install & Restart. ThinkRail then shows the installation's progress and log, closes, and reopens on the new version. After the restart it tells you whether the update installed. If it didn't, it explains why and offers to retry. The updater appears only when the package carries a valid HTTPS feed identity; installations that predate that identity need one manual installation first.

打包的稳定版和每日构建版桌面应用会在后台检查更新，并在“设置 → 更新”中提供更新：下载 → 准备更新 → 安装并重启。在你选择“安装并重启”之前，不会应用任何更改。ThinkRail 随后会显示安装进度和日志，关闭并以新版本重新打开。重启后，它会告诉你更新是否安装成功。如果失败，它会解释原因并提供重试选项。更新程序仅在软件包带有有效的 HTTPS 源标识时才会出现；早于该标识的安装需要先进行一次手动安装。
