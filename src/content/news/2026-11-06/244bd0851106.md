Releases: Releasing code is important. It’s the only way to make people actually enjoy the result of your work. I have no problem to admit I struggle with this. As an R&D guy I’ve always considered myself an “enabler”. I do something, I show how it is done and let people learn from it and actually implement it. That’s fine in some contexts but it has been driving me to some level of frustration recently, as the size of the projects I take part in grow.

发布：发布代码很重要。这是让人们真正享受到你工作成果的唯一途径。我毫不避讳承认我在这一点上感到困难。作为一名研发人员，我一直认为自己是一个“赋能者”。我做一些事情，展示它是如何完成的，并让人们从中学习并付诸实践。这在某些情况下没问题，但随着我参与的项目规模不断扩大，这最近让我感到有些沮丧。

一个例子是 Guix 上的 RISC-V 引导程序。我花了几年的时间在上面。我们为 live-bootstrap 制作了一个可用的引导程序，但它尚未被纳入 Guix，因为我把最后一步委托出去了。现在，即使在我投入了多年心血、经历了无数不眠之夜后，这依然是我无法完全享受、而你们根本无法享用的成果。“我的工作完成了”这种心态对我来说已经不够了。我现在所做的项目值得更好的对待。我值得更好的，你们也值得更好的。

GNU Mes：在 Mes 项目中，我有一个分支里大约有 300 次提交，非常混乱，反复地做、撤销、重做某些事情。整个代码库被搞得天翻地覆，提交信息有时详尽有时缺失，我还有一些修复提交，用来修正那些被改动得面目全非的内容，以至于重新排序产生的冲突量令人难以承受……那简直是一团糟。那是我在尝试新事物、边学边清理的过程。这是我树状思维过程的极致体现。

GNU Mes 0.28：本周，我发布了 GNU Mes 0.28。这是我作为 GNU 维护者所做的第一次发布。Janneke 在整个过程中一直指导我——包括使用 CVS 将网站发布到 GNU 的部分。我确信如果靠我自己，永远无法搞定这一切。这一路走来真是跌宕起伏！但在一年多的工作之后，我很高兴看到关于此次发布的大多数评论都是积极的，尤其是来自那些我曾共事过且非常尊敬的人们的评价。

But, what will you find in GNU Mes 0.28 that we didn’t mention in the blog yet? M2-Planet, MesCC and GCC: First of all, the main difference from the earlier blogpost is now Mes can be compiled with both M2-Planet and MesCC, and also with GCC as before. It’s a tricky process, because the error reporting is very limited (I’m being benevolent here), and I was being a very nasty boy with some gotos inside switch statements. After some wrestling with allowed C syntax, I figured it out.

那么，在 GNU Mes 0.28 中，有哪些我们之前在博客中未提及的内容呢？M2-Planet、MesCC 和 GCC：首先，与之前博文的主要区别在于，现在 Mes 既可以用 M2-Planet 编译，也可以用 MesCC 编译，当然也可以像以前一样用 GCC 编译。这是一个棘手的过程，因为错误报告非常有限（我这里说得还算客气），而且我在 switch 语句中使用了一些 goto 语句，表现得非常糟糕。在与允许使用的 C 语法进行了一番博弈后，我终于搞定了。

M2-Planet is limited, and we had to leave some things out. When Mes is compiled with M2-Planet it doesn’t have support for errors (aka exceptions) and those abort the interpreter, this is because M2-Planet’s C library doesn’t include setjmp. The stack operations had also to be rewritten as functions for M2-Planet, as the macros with array access were too complex for it. With that, Mes is a little bit slower when compiled with M2-Planet. None of those are a big deal because that’s only the starting point of the bootstrap process and Mes is rebuilt with MesCC right after it.

M2-Planet 功能有限，我们不得不舍弃一些东西。当 Mes 使用 M2-Planet 编译时，它不支持错误（即异常），这些错误会导致解释器中止，这是因为 M2-Planet 的 C 库不包含 setjmp。栈操作也必须重写为 M2-Planet 的函数，因为带有数组访问的宏对它来说太复杂了。因此，当使用 M2-Planet 编译时，Mes 的速度会慢一点。这些都不是什么大问题，因为这只是引导过程的起点，Mes 紧接着就会用 MesCC 重新构建。
