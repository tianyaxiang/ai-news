Finding anagrams The two usual tricks for finding anagrams are to use either a letter-sorted permutation or a letter-count vector as a unique identifier for the letters in the word in an order-independent way: letter_sort("spot") -> "opst" or letter_count("spot") -> "[... o:1, p: 1, s: 1, t:1 ...]" and then run through the dictionary and insert items into a hash table based upon their letter count. In python-ish pseudocode: for word in dictionary: table[letter_sort(word)] += word which creates a table with entries like: "opst" : ["spot", "post", "tops", "stop"]

寻找变位词。寻找变位词的两种常用技巧是使用字母排序后的排列或字母计数向量，作为单词中字母的唯一标识符，以一种与顺序无关的方式：letter_sort("spot") -> "opst" 或 letter_count("spot") -> "[... o:1, p: 1, s: 1, t:1 ...]"，然后遍历字典并根据它们的字母计数将项目插入哈希表。用类似 Python 的伪代码表示：for word in dictionary: table[letter_sort(word)] += word，这将创建一个包含如下条目的表："opst" : ["spot", "post", "tops", "stop"]。

Eliminating Vec allocations When optimizing, one of the first places to be suspicious is allocations, and this one has them in droves. Every word results in either the allocation of a Vec or an append to a Vec, which sometimes needs an allocation. Practically, there are about 161019 keys in the table, so that's 161k allocations (!!). Let's improve those by using a slightly more clever data structure, noting two things: With 161k entries in the hash table and only 178k dictionary items, most of those hash table entries will be singletons. We have the original word list stored in memory and it can be indexed by a u32 given its size. So we'll do two things: We'll find a way to store singleton items without needing a dynamic-length data structure at all, and we'll implement the equivalent of a linked list for appending items to the lists, since they're append-only and we only scan them once at the end. To do this, we'll use a structure like this: heads: HashMap::<K, u32>, next: Vec<u32>, word: Vec<u32> Where heads is indexed by the anagram-identifying-key (e.g., the character-sorted string). We'll overload that u32 by using the high bit (we only have 170k or so words) to let it represent either an actual data value (the index of an element in the list) OR an index into the next+word arrays. The next array is our linked list - it stores pointers to another entry in the next array. The word array stores the associated data. It looks like this: Result: 31ms -> 20ms (112ns / word)

Packing letter counts into a u128 Much better, but we can do better yet. The time to sort that string and create a new string allocation is non-trivial and we're doing 178k of them. That's going to be another big chunk of nanoseconds. Let's try a letter count vector instead, and pack it tightly into an integer. With only 26 characters, if we assume that no word has more than 15 repetitions of the same character, we could use 4 bits per character for 26 x 4=104 bits. That fits comfortably in a u128, and while that's not tiny, it's at least a nice fixed size 16 byte thing we can use as a fast hash table key. /// Group words by a u128 holding a 4-bit count of each letter A-Z. /// Assumes uppercase A-Z words with no letter repeated more than 15 times. fn u128_lettercount(words: &[String]) -> KeyGroups { let items = words.iter().enumerate().map(|(idx, word)| { let mut lettercount = 0u128; for letter in word.bytes() { lettercount += 1u128 << ((letter - b'A') as u32 * 4); } (lettercount, idx as u32) }); KeyGroups::new(words.len(), items) } (Note that we've done something else here - we're only returning the list of anagrams, not a full dictionary containing all of the words that don't have anagrams.) Avoiding the string manipulation and sorting gives a big win: Result: 20ms -> 5.6ms (31ns / word)

将字母计数打包到 u128 中。好多了，但我们还可以做得更好。排序字符串并创建新字符串分配的时间是不容忽视的，而且我们正在进行 17.8 万次这样的操作。那将是另一大块纳秒。让我们尝试改用字母计数向量，并将其紧凑地打包到一个整数中。只有 26 个字符，如果我们假设没有单词包含超过 15 次相同的字符重复，我们可以为每个字符使用 4 位，即 26 x 4 = 104 位。这可以舒适地放入 u128 中，虽然它不算小，但至少是一个很好的固定大小的 16 字节对象，我们可以将其用作快速哈希表键。/// 按 u128 对单词进行分组，其中包含每个字母 A-Z 的 4 位计数。/// 假设单词为大写 A-Z，且没有字母重复超过 15 次。fn u128_lettercount(words: &[String]) -> KeyGroups { let items = words.iter().enumerate().map(|(idx, word)| { let mut lettercount = 0u128; for letter in word.bytes() { lettercount += 1u128 << ((letter - b'A') as u32 * 4); } (lettercount, idx as u32) }); KeyGroups::new(words.len(), items) }（请注意，我们在这里做了另一件事——我们只返回变位词列表，而不是包含所有没有变位词的单词的完整字典。）避免字符串操作和排序带来了巨大的胜利：结果：20ms -> 5.6ms（每词 31ns）。
