# Connecting My LangGraph AI Agent to Postgres
# 将我的 LangGraph AI 智能体连接到 Postgres

In the first three articles of this series, I built a stateful LangGraph agent that handles a 15-minute booking process and wrapped it up with a Streamlit UI to improve user experience, and added a proper backend with Postgres database.
在本系列的前三篇文章中，我构建了一个有状态的 LangGraph 智能体，用于处理 15 分钟的预订流程，并使用 Streamlit UI 封装以提升用户体验，同时添加了基于 Postgres 数据库的后端。

The journey of this AI agent started when I had a chat with a customer service representative for a cleaning service. The agent handles the entire booking process like a real customer service representative. It’s a LangGraph-based agent that orchestrates the following operations:
这个 AI 智能体的旅程始于我与一家清洁服务公司的客服代表的一次对话。该智能体像真正的客服代表一样处理整个预订流程。它是一个基于 LangGraph 的智能体，负责协调以下操作：

* Responds to customer queries and understands their needs.
* Calculates the price for the service and informs the customer.
* Handles the customer’s acceptance or rejection.
* Proposes optimized time slots.
* Confirms and records the appointment.

* 回答客户咨询并理解其需求。
* 计算服务价格并告知客户。
* 处理客户的接受或拒绝。
* 推荐优化的时间段。
* 确认并记录预约。

In this article, we will test the Postgres backend using both Docker and a hosted Postgres. The full source code of this project is available on GitHub at [customer-service-agent](https://github.com/your-repo-link). Feel free to clone the repo and test it yourself.
在本文中，我们将分别使用 Docker 和托管式 Postgres 来测试 Postgres 后端。该项目的完整源代码可在 GitHub 上的 [customer-service-agent](https://github.com/your-repo-link) 获取。欢迎克隆仓库并自行测试。

### Testing the database
### 数据库测试

As I explained in the previous article, the agent has two persistence modes, which are in-memory and Postgres.
正如我在上一篇文章中所解释的，该智能体有两种持久化模式：内存模式和 Postgres 模式。

In-memory is for quick testing and demo purposes. If `DATABASE_URL` is unset, the app uses `InMemoryBookingRepository` and `MemorySaver`. No tables are created.
内存模式用于快速测试和演示。如果未设置 `DATABASE_URL`，应用程序将使用 `InMemoryBookingRepository` 和 `MemorySaver`，且不会创建任何表。

In order to run a local test with Streamlit UI, we first install dependencies with `poetry install` and then create a `.env` file by copying the `.env.example`.
为了使用 Streamlit UI 进行本地测试，我们首先通过 `poetry install` 安装依赖，然后通过复制 `.env.example` 创建一个 `.env` 文件。

```bash
poetry install
cp .env.example .env
```

We need to set `OPENAI_API_KEY` in `.env`. We can leave `DATABASE_URL` empty for this test. Then, we can start the Streamlit UI at `localhost:8501` using the following command:
我们需要在 `.env` 中设置 `OPENAI_API_KEY`。对于此测试，我们可以将 `DATABASE_URL` 留空。然后，使用以下命令在 `localhost:8501` 启动 Streamlit UI：

```bash
poetry run streamlit run customer_service_agent/streamlit_app.py
```

If you haven't read the previous articles, the AI agent can understand if all required information is already present and proceed directly to calculating and presenting a quote. If I don't give the size or address in the first message, agent would ask for these before calculating the price.
如果你还没读过之前的文章，（需要了解）AI 智能体能够判断所有必要信息是否齐全，并直接进行报价计算和展示。如果我在第一条消息中没有提供面积或地址，智能体会先询问这些信息，然后再计算价格。

We can complete a booking in the UI but conversation state disappear when the app restarts. To actually have data stored, we need to use the database options.
我们可以在 UI 中完成预订，但当应用程序重启时，对话状态会消失。要真正实现数据存储，我们需要使用数据库选项。

### Testing with Docker
### 使用 Docker 进行测试

**Why testing with Docker**
**为什么要使用 Docker 进行测试**

We also have the option to test the project with Docker. It allows for testing against Postgres without having to install a real database on our computers. Testing with Docker mimics the same database we would have in production but locally. The app talks to an actual PostgreSQL server.
我们还可以选择使用 Docker 来测试该项目。它允许我们在无需在电脑上安装真实数据库的情况下测试 Postgres。使用 Docker 测试可以在本地模拟生产环境中的数据库，应用程序会与真实的 PostgreSQL 服务器进行通信。

Docker also makes it reproducible for everyone. The URL and credentials live in `docker-compose.yml` / `.env.example`. You get the same setup as I have used.
Docker 还确保了环境的可复现性。URL 和凭据位于 `docker-compose.yml` / `.env.example` 中。你将获得与我所使用的完全相同的设置。

Thanks to Docker, the app will be isolated from the rest of the computer. The database runs in a container. We can stop it (`docker compose down`) or wipe it (`docker compose down -v`) without touching other apps.
得益于 Docker，应用程序将与计算机的其他部分隔离。数据库运行在容器中。我们可以停止它 (`docker compose down`) 或清除它 (`docker compose down -v`)，而不会影响其他应用程序。

So Docker lets us test the durable backend on a real Postgres instance in minutes, with the same connection string every time, and without installing Postgres on our laptop.
因此，Docker 让我们能在几分钟内就在真实的 Postgres 实例上测试持久化后端，每次使用相同的连接字符串，且无需在笔记本电脑上安装 Postgres。

**How to test with Docker**
**如何使用 Docker 进行测试**

This project has a `docker-compose.yml` file that starts a container with PostgreSQL 16:
本项目包含一个 `docker-compose.yml` 文件，用于启动一个 PostgreSQL 16 容器：

```yaml
services:
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: booking
      POSTGRES_PASSWORD: booking
      POSTGRES_DB: booking_agent
    ports:
      - "5432:5432"
    volumes:
      - booking_pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U booking -d booking_agent"]
      interval: 5s
      timeout: 5s
      retries: 10
volumes:
  booking_pgdata:
```

Docker pulls the official Postgres image and runs a database server inside the container. Streamlit app still runs locally and connects to that container over `localhost:5432`.
Docker 会拉取官方 Postgres 镜像并在容器内运行数据库服务器。Streamlit 应用程序仍在本地运行，并通过 `localhost:5432` 连接到该容器。

Database files are stored in a Docker volume (`booking_pgdata`), which is a persistent disk storage managed by Docker. It's not in RAM so data stays in the container unless we delete the volume.
数据库文件存储在 Docker 卷 (`booking_pgdata`) 中，这是由 Docker 管理的持久化磁盘存储。它不在内存中，因此除非我们删除该卷，否则数据会保留在容器中。

In order to test it with Docker, you need to have Docker Desktop installed on your computer. Open Docker Desktop and wait until you see "Engine is running". Then, we can start the container using the following command:
为了使用 Docker 进行测试，你的电脑上需要安装 Docker Desktop。打开 Docker Desktop 并等待看到“Engine is running”。然后，我们可以使用以下命令启动容器：

```bash
docker compose up -d
```

And we need to add `DATABASE_URL` in our `.env` file:
我们需要在 `.env` 文件中添加 `DATABASE_URL`：

```bash
DATABASE_URL=postgresql://booking:booking@localhost:5432/booking_agent
```

Then, we can run the app using the following command:
然后，我们可以使用以下命令运行应用程序：

```bash
poetry run streamlit run customer_service_agent/streamlit_app.py
```

After running this command, Streamlit UI starts. I completed a test booking. To verify it works properly, I open a second browser (`localhost:8501`) and asked for the same service. This time, it did not offer the time slot I previously booked.
运行此命令后，Streamlit UI 启动。我完成了一个测试预订。为了验证它是否正常工作，我打开了第二个浏览器窗口 (`localhost:8501`) 并请求相同的服务。这一次，它没有提供我之前预订的时间段。

We can also see it's running on Docker Desktop. Streamlit and Docker Postgres are separate processes. Restarting Streamlit only restarts the Python app. The Postgres container keeps running unless we stop it. Also, the data lives in the Docker volume, not in Streamlit memory. So when we schedule a new appointment, the app sees the previous bookings in the database.
我们也可以在 Docker Desktop 上看到它正在运行。Streamlit 和 Docker Postgres 是独立的进程。重启 Streamlit 只会重启 Python 应用程序。Postgres 容器会持续运行，除非我们停止它。此外，数据存储在 Docker 卷中，而不是 Streamlit 的内存中。因此，当我们安排新的预约时，应用程序可以看到数据库中之前的预订记录。

We only lose the database if we stop or remove the container and delete the volume (`docker compose down -v`).
只有当我们停止或移除容器并删除卷 (`docker compose down -v`) 时，才会丢失数据库。

### Testing with a hosted Postgres
### 使用托管式 Postgres 进行测试

We don't need to use Docker if we have Postgres in the cloud (e.g. Supabase, RDS). We can simply create a Postgres database in the provider's dashboard and copy the connection string.
如果我们已经在云端拥有 Postgres（例如 Supabase、RDS），则无需使用 Docker。我们只需在服务提供商的仪表板中创建一个 Postgres 数据库并复制连接字符串即可。
