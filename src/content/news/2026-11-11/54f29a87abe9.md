Languages C# 15 C# 15 is the default language version for projects targeting .NET 11. Union types are one of its biggest additions: a value can be one of a declared set of case types, with conversions from those types and exhaustiveness checking in switch expressions. Consider a product lookup that either finds a product or reports that it wasn’t found: ProductLookup result = new Product(42, "Mechanical keyboard"); string message = result switch { Product product => $"Found {product.Name}", ProductNotFound missing => $"No product with ID {missing.Id}", }; Console.WriteLine(message); public sealed record Product(int Id, string Name); public sealed record ProductNotFound(int Id); public union ProductLookup(Product, ProductNotFound); The result type tells a caller which outcomes it needs to handle. There’s no need to use object or an unrelated base class just to put those outcomes behind one return type. C# 15 also adds closed hierarchies. A closed class limits direct derivation to its declaring assembly, giving the compiler the information it needs to check patterns over the hierarchy. Unions are useful when you want to combine existing types; closed hierarchies fit models where you own the inheritance relationship.

语言 C# 15：C# 15 是针对 .NET 11 的项目的默认语言版本。联合类型是其最大的新增功能之一：一个值可以是声明的一组情况类型之一，并支持从这些类型进行转换，以及在 switch 表达式中进行穷举检查。考虑一个产品查找功能，它要么找到产品，要么报告未找到：ProductLookup result = new Product(42, "Mechanical keyboard"); string message = result switch { Product product => $"Found {product.Name}", ProductNotFound missing => $"No product with ID {missing.Id}", }; Console.WriteLine(message); public sealed record Product(int Id, string Name); public sealed record ProductNotFound(int Id); public union ProductLookup(Product, ProductNotFound); 结果类型告诉调用者它需要处理哪些结果。无需为了将这些结果放在一个返回类型之后而使用 object 或不相关的基类。C# 15 还增加了封闭层次结构。封闭类将直接派生限制在其声明程序集中，从而为编译器提供检查层次结构模式所需的信息。当您想要组合现有类型时，联合类型非常有用；封闭层次结构则适用于您拥有继承关系的模型。

Smaller language features help with everyday code, too. Collection expression arguments let you pass constructor or factory arguments without giving up collection expression syntax: HashSet<string> names = [with(StringComparer.OrdinalIgnoreCase), "Alice", "ALICE", "Bob"]; Console.WriteLine(names.Count); This prints 2: the comparer controls equality, so "Alice" and "ALICE" are one entry. Other additions include extension indexers and labeled break and continue. These features don’t require the preview language version. The separate memory safety work remains in preview; see the C# 15 feature documentation for its opt-in requirements.

较小的语言特性也有助于日常编码。集合表达式参数允许您传递构造函数或工厂参数，而无需放弃集合表达式语法：HashSet<string> names = [with(StringComparer.OrdinalIgnoreCase), "Alice", "ALICE", "Bob"]; Console.WriteLine(names.Count); 这将打印 2：比较器控制相等性，因此 "Alice" 和 "ALICE" 是同一个条目。其他新增功能包括扩展索引器以及带标签的 break 和 continue。这些功能不需要预览语言版本。单独的内存安全工作仍处于预览阶段；请参阅 C# 15 功能文档以了解其选择加入要求。

F# 11 F# 11 improves compiler memory use and reduces allocations in FSharp.Core collection operations. It also adds ways to bound concurrent asynchronous work, useful when a collection operation would otherwise start more work than a service or machine can handle comfortably. The F# release notes distinguish the default-language updates from preview capabilities, including Runtime Async support for custom computation-expression builders.

F# 11：F# 11 改进了编译器内存使用，并减少了 FSharp.Core 集合操作中的分配。它还增加了限制并发异步工作的方法，这在集合操作可能启动超出服务或机器处理能力的工作时非常有用。F# 发行说明区分了默认语言更新和预览功能，包括对自定义计算表达式构建器的运行时异步支持。

Platform SDK The SDK now enables a Native AOT CLI host by default. Commands such as help and version queries can run without starting the managed CLI, and tool launches can avoid that startup path too. Commands that need managed execution still use it. The MSBuild server also stays warm between CLI invocations by default, reducing repeated startup work. SDK installers on Linux and macOS are smaller through assembly deduplication. File-based apps can grow across source files with #:include, and solution filters can be created and edited from the CLI. dotnet watch adds Aspire app-host integration, crash recovery, and device selection for mobile projects. For teams using Microsoft.Testing.Platform, dotnet test gains run-level timeouts, failure limits, clearer progress reporting, and per-module results directories. The test runner matters: these switches aren’t interchangeable with the VSTest command-line options.
