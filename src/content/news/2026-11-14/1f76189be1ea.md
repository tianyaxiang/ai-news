llama.cpp v1.0.0 : A stronger foundation for the local AI ecosystem

llama.cpp v1.0.0：本地 AI 生态系统的更强基石

llama.cpp makes it possible to run multi-modal LLMs across a wide range of hardware - from consumer-grade local machines to high-end enterprise servers. Through quantization, optimized backends, and a portable C/C++ implementation, we make AI inference accessible at every level of the software stack. We believe this is the most lightweight, versatile and sensible platform for building cross-platform and private AI products.

llama.cpp 使得在各种硬件上运行多模态大语言模型（LLM）成为可能——从消费级本地机器到高端企业级服务器。通过量化、优化的后端以及可移植的 C/C++ 实现，我们让 AI 推理在软件栈的各个层面都变得触手可及。我们相信，这是构建跨平台和私有 AI 产品最轻量、最通用且最合理的平台。

During the 3.5 years since its inception, the project has grown a lot and many downstream applications already depend on our work. We expect this trend to continue as local AI and privacy become increasingly important in our everyday lives. Every new integration means more developers depending on our library interfaces and therefore having a flexible but stable API is paramount. Today we release libraries v1.0.0, highlighting our responsibility to those developers.

自项目启动以来的 3.5 年里，该项目发展迅速，许多下游应用已经依赖于我们的工作。随着本地 AI 和隐私在我们的日常生活中变得越来越重要，我们预计这一趋势将持续下去。每一次新的集成都意味着有更多的开发者依赖我们的库接口，因此拥有一个灵活且稳定的 API 至关重要。今天我们发布了 v1.0.0 版本的库，彰显了我们对这些开发者的责任。

Moving forward, both llama.cpp and ggml will reflect API and ABI incompatibilities with major-version bumps. As adoption grows, we will be stricter about making those boundaries visible to downstream consumers.

展望未来，llama.cpp 和 ggml 都将通过主版本号的升级来体现 API 和 ABI 的不兼容性。随着采用率的增长，我们将更严格地向下游用户明确这些界限。

Semantic version update rules: The following rules apply to all ggml-org projects using semantic versioning: Change type Bump MAJOR: Breaking change to the public C API in ./include; MINOR: Backward-compatible feature, backend updates, model support, or API addition; PATCH: Bug fix with no API change.

语义版本更新规则：以下规则适用于所有使用语义版本控制的 ggml-org 项目：变更类型 MAJOR 升级：./include 中公共 C API 的破坏性变更；MINOR 升级：向后兼容的功能、后端更新、模型支持或 API 添加；PATCH 升级：无 API 变更的错误修复。

Distribution: We are looking forward to expanding the ways in which ggml-org software is distributed and reaches developers and end-users. For more information about how to add ggml-org projects to your packaging and release pipelines, please check the following discussion.

分发：我们期待扩展 ggml-org 软件的分发方式，使其能够触达更多的开发者和终端用户。有关如何将 ggml-org 项目添加到您的打包和发布流水线中的更多信息，请查看相关讨论。

Development: The project has fostered an amazing open-source community with highly-skilled and talented contributors. With the rapid advance of AI capabilities in the field of software engineering, we continue to adapt and integrate LLMs in our development cycle in a thoughtful and reasonable manner. Maintaining a high quality codebase, staying in control of the architecture and understanding the implementation details will remain our top priorities.

开发：该项目培育了一个拥有高技能和才华横溢贡献者的出色开源社区。随着软件工程领域 AI 能力的飞速发展，我们继续以深思熟虑且合理的方式调整并将 LLM 集成到我们的开发周期中。保持高质量的代码库、掌控架构并理解实现细节仍将是我们的首要任务。

To reinforce the faster pace of development we continue to invest more and more resources in improving the CI infrastructure behind the projects. Thanks to HF technologies such as HF Buckets and HF Jobs we are able to scale the capacity necessary to guarantee correctness for every change that lands on the master branches. With hardware support from NVIDIA, AMD, Qualcomm, Arm, IBM and Intel, we continue to enroll more self-hosted runners across all major hardware platforms.

为了加强更快的开发节奏，我们继续投入越来越多的资源来改进项目背后的 CI 基础设施。得益于 HF Buckets 和 HF Jobs 等 HF 技术，我们能够扩展必要的能力，以确保每次合并到主分支的变更都是正确的。在 NVIDIA、AMD、Qualcomm、Arm、IBM 和 Intel 的硬件支持下，我们继续在所有主流硬件平台上部署更多的自托管运行器。

Backend and model coverage: The underlying machine learning engine of llama.cpp - ggml is designed to run on virtually any hardware in existence. This is achieved by implementing dedicated ggml backends. Each backend can be compiled as a dynamic library and optionally loaded at runtime. A complete list of the currently implemented backends can be found here. We are committed to provide continuous support of all model architectures. Currently, llama.cpp supports more than 150 architecture variants as well as all mainstream speculative decoding methods.

后端和模型覆盖：llama.cpp 的底层机器学习引擎 ggml 旨在运行于几乎所有现有的硬件上。这是通过实现专用的 ggml 后端来实现的。每个后端都可以编译为动态库，并可在运行时选择性加载。当前已实现的后端完整列表可以在此处找到。我们致力于为所有模型架构提供持续支持。目前，llama.cpp 支持超过 150 种架构变体以及所有主流的推测解码方法。

Thanks: The llama.cpp team at Hugging Face is thankful for the incredible support from the community. Special thanks to the long-time maintainers of the project and all contributors. This is a significant milestone which would not have been possible without our joint efforts!

致谢：Hugging Face 的 llama.cpp 团队感谢社区提供的难以置信的支持。特别感谢该项目的长期维护者和所有贡献者。这是一个重要的里程碑，没有我们的共同努力，这一切都不可能实现！
