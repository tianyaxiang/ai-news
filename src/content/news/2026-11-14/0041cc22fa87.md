Nightmare Eclipse, the pseudonym of a researcher with an ongoing, very public beef with Microsoft, has dropped yet another Windows zero-day. On Tuesday, Nightmare Eclipse disclosed SignDrop, a vulnerability that gives local users full System rights on some versions of Windows.

Nightmare Eclipse 是一位与微软存在持续且公开矛盾的研究人员的化名，他再次发布了一个 Windows 零日漏洞。周二，Nightmare Eclipse 披露了 SignDrop，这是一个可以让本地用户在某些 Windows 版本上获得完整系统权限的漏洞。

The vulnerability resides in the Common Log File System, which Microsoft describes as a “general-purpose logging service used by software clients running in user-mode or kernel-mode.” By forcing a privileged process such as Windows Defender to open a crafted CLFS container, an attacker with ordinary user rights can abuse the privileged file creation to elevate privileges to System.

该漏洞存在于通用日志文件系统（CLFS）中，微软将其描述为“供用户模式或内核模式下运行的软件客户端使用的通用日志记录服务”。通过强制 Windows Defender 等特权进程打开一个精心制作的 CLFS 容器，拥有普通用户权限的攻击者可以滥用特权文件创建功能，从而将权限提升至系统级别。

Turning a Windows defense against itself: The attack exploits the interaction of CLFS, Windows Defender, and Windows file permissions. The exploit uses Windows Defender to open a log file created by a standard user by calling ServerMpUpdateEngineSignature, a legitimate Defender function for processing antivirus signature updates.

将 Windows 防御机制反戈一击：该攻击利用了 CLFS、Windows Defender 和 Windows 文件权限之间的交互。攻击利用 Windows Defender 通过调用 ServerMpUpdateEngineSignature（这是 Defender 用于处理杀毒软件签名更新的合法函数）来打开一个由标准用户创建的日志文件。

By manipulating Windows Object Manager symbolic links, the attacker causes Defender to open the CLFS container in the security context of the antimalware engine. If an associated authentication file is missing, CLFS creates it using Defender’s System privileges. Because CLFS assigns the newly created file the Discretionary Access Control List of the original file, the attacker may gain access to a file created with System privileges, allowing the file-creation operation to be abused as part of a privilege-escalation attack.

通过操纵 Windows 对象管理器的符号链接，攻击者诱使 Defender 在反恶意软件引擎的安全上下文中打开 CLFS 容器。如果缺少关联的身份验证文件，CLFS 会使用 Defender 的系统权限创建该文件。由于 CLFS 会将原始文件的自主访问控制列表（DACL）分配给新创建的文件，攻击者可能会获得对以系统权限创建的文件的访问权，从而允许将文件创建操作滥用为权限提升攻击的一部分。

Ironically, the vulnerability stems from a security measure Microsoft introduced in October 2025 to prevent attackers from exploiting other vulnerabilities in CLFS. “If everything is chained correctly, funnily this legit security mitigation can be used against itself and allow an elevation [of] privileges,” Nightmare Eclipse wrote. “Everything is done properly by Microsoft here but the logic allows abuse.”

讽刺的是，该漏洞源于微软在 2025 年 10 月引入的一项安全措施，旨在防止攻击者利用 CLFS 中的其他漏洞。Nightmare Eclipse 写道：“如果一切链条连接正确，有趣的是，这种合法的安全缓解措施可以被反过来利用，从而实现权限提升。微软在这里所做的一切都是正确的，但其逻辑却允许了这种滥用。”

The researcher continued: What makes it funnier is the fact that it can be used against any antimalware engine to bypass their self defense (or tamper protection) mechanism as you can trigger arbitrary file creation in the context of their own antimalware process so from the perspective of their kernel drivers, the file creation request is coming from their own legit process so it passes, this makes this vulnerability unique as it can be used to turn off any antivirus/EDR.

该研究人员继续说道：更可笑的是，它还可以被用来针对任何反恶意软件引擎，以绕过它们的自我防御（或防篡改）机制。因为你可以在它们自己的反恶意软件进程上下文中触发任意文件创建，所以从它们的内核驱动程序角度来看，文件创建请求来自它们自己的合法进程，因此请求会被通过。这使得该漏洞非常独特，因为它可被用于关闭任何杀毒软件或 EDR。

Nightmare Eclipse said the exploit worked against Windows 11 26H2, Windows 11 26H2 Experimental, and Windows Server 2025 Experimental. People can see if their systems are vulnerable by checking the CLFS authentication mode. If it’s in learning mode or enforcement mode, the system is vulnerable, and the PoC supplied in the post should spawn a SYSTEM shell.

Nightmare Eclipse 表示，该漏洞利用程序适用于 Windows 11 26H2、Windows 11 26H2 Experimental 以及 Windows Server 2025 Experimental。用户可以通过检查 CLFS 身份验证模式来查看其系统是否存在漏洞。如果处于学习模式或强制模式，则系统存在漏洞，且文章中提供的概念验证（PoC）代码应能生成一个系统级 Shell。

Researcher Will Dormann said in an interview that he has been able to reproduce the exploit and that it works as described, but not on all versions of Windows 11. But there’s a catch, he said. “The requirements are important in that it seems to require Windows 26H2, and one that has existed for more than 90 days, it seems,” he explained. “That is, you can’t just take a new 26H2 system and install updates and have it work.”

研究人员 Will Dormann 在接受采访时表示，他已经能够重现该漏洞利用程序，且其运行效果与描述一致，但并非在所有 Windows 11 版本上都有效。但他指出其中有一个关键点：“要求很重要，因为它似乎需要 Windows 26H2，而且似乎需要是已经存在超过 90 天的系统。也就是说，你不能仅仅拿一个全新的 26H2 系统并安装更新就能让它生效。”

For a system to be vulnerable, Dormann said, the HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\CLFS\Authentication\Mode value must be 0 or 1. Of the many machines Dormann uses, only a single one met this requirement. Microsoft does staged rollouts of Windows updates, such as 26H2, so it’s not clear how many people have it. You can check by running the “winver” command.

Dormann 表示，要使系统存在漏洞，HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\CLFS\Authentication\Mode 的值必须为 0 或 1。在 Dormann 使用的多台机器中，只有一台符合此要求。微软对 Windows 更新（如 26H2）采取分阶段推送，因此尚不清楚有多少人拥有该版本。你可以通过运行“winver”命令进行检查。

In a statement sent after this post went live, Microsoft said it was investigating the writeup and had no evidence the vulnerability was being exploited in the wild. The company also said Defender blocks potential exploitation attempts.

在本文发布后发送的一份声明中，微软表示正在调查该报告，目前没有证据表明该漏洞在野外被利用。该公司还表示，Defender 可以阻止潜在的利用尝试。
