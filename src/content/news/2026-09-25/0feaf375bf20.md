# What Makes a Terminal-Bench Task Hard? Separating Genuine Hardness from Fake-Hardness on an Adjudicated Agentic Corpus

**终端基准测试任务为何困难？在经裁定的智能体语料库中区分真实难度与虚假难度**

---

Frontier benchmarks need tasks that current models cannot solve. But a task that no model solves is not automatically a hard task. The same zero pass rate can come from a real capability gap, but it can also come from missing context, a broken reference solution, infrastructure failure, or a verifier that can be bypassed.

前沿基准测试需要当前模型无法解决的任务。但没有任何模型能解决的任务，并不自动等同于“困难任务”。同样的零通过率可能源于真正的能力差距，但也可能源于缺失的上下文、损坏的参考解决方案、基础设施故障或可被绕过的验证器。

In this paper, we study this issue using a frozen Terminal-Bench 3 / Frontier-Bench 0.1 production record with 1,081 pull requests, 639 scored tasks, 28,801 trials, and $105,933 in logged agent spend. We ask what an all-fail task actually certifies.

在本文中，我们利用一份冻结的 Terminal-Bench 3 / Frontier-Bench 0.1 生产记录研究了这一问题，该记录包含 1,081 个拉取请求、639 个评分任务、28,801 次试验以及 105,933 美元的记录智能体支出。我们探讨了“全失败任务”究竟证明了什么。

For the 125 tasks with no honest pass, we combine task artifacts, reference-solution runs, empty-solution controls, adversarial trials, trajectories, telemetry, and review records, and apply an ordered validity screen. Only 78 of the 125 tasks survive as certified-unsolved candidates.

针对 125 个没有有效通过记录的任务，我们结合了任务工件、参考解决方案运行、空解控制组、对抗性试验、轨迹、遥测数据和审查记录，并应用了有序的有效性筛选。在这 125 个任务中，仅有 78 个被确认为“经认证的未解任务”。

The remaining tasks include 14 with broken oracles, 8 dominated by infrastructure failures, 4 that are only passable through verifier bypasses, and 21 whose solvability is not certified by the available evidence. Thus, lack of saturation and genuine difficulty are not the same thing.

其余任务中，包括 14 个预言机（oracle）损坏的任务、8 个受基础设施故障主导的任务、4 个仅能通过绕过验证器通过的任务，以及 21 个其可解性无法被现有证据证明的任务。因此，缺乏饱和度与真正的难度并不是一回事。

The certified-unsolved label is also narrow: it means that the authored route passed, infrastructure did not dominate, no strict bypass was observed, and all evaluated agents failed. It does not prove intrinsic hardness, verifier completeness, or failure at the intended capability.

“经认证的未解”这一标签的定义也很狭窄：它意味着预设路径是通畅的、基础设施未造成主导性影响、未观察到严格的绕过行为，且所有被评估的智能体均失败了。这并不能证明任务具有内在难度、验证器是完备的，或智能体在预期能力上存在失败。

We further analyze rejected submissions and passing tasks to show that pass rate alone cannot explain why a task is difficult. Overall, our results suggest that frontier benchmarks should report the evidence behind their all-fail tasks before using them as capability claims.

我们进一步分析了被拒绝的提交和通过的任务，以表明仅凭通过率无法解释任务为何困难。总的来说，我们的研究结果表明，前沿基准测试在将“全失败任务”用作能力声明之前，应先报告其背后的证据。
