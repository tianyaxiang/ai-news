# A NES emulator written in Odin

我用 Odin 编写了一个 NES 模拟器！Github 链接。简介：我于 2024 年 6 月下旬开始了该项目，并在业余时间断断续续地进行开发。我决定在 2025 年 1 月暂停该项目，以便专注于其他事情。我学到了很多关于以下方面的知识：NES 架构，以及可能对游戏机架构的通用理解；位和字节、十六进制表示法以及位运算；Odin 编程语言，我之前从未在严肃项目中使用过它；计算机的工作原理，如 CPU 指令、“周期”等；模拟，这非常困难，向模拟器开发者致敬！这是一段疯狂的旅程，我获得了很多乐趣，但在最后试图让模拟器实现“完全”精确时，我也承受了更多压力。你可以阅读 Github 的自述文件以获取有关该项目的更多信息。

### Features
功能：足以运行《Battletoads》和数百款其他游戏的模拟精度；带有调试功能的调试器视图；用于与模拟器交互的菜单视图；保存状态；控制器支持；CRT 着色器切换（部分）；声音；支持的映射器：NROM, MMC1, UXROM, CNROM, MMC3, GxROM, AxROM。

### Making an emulator
制作模拟器：我看到有些人说制作 NES 模拟器是一个简单的周末项目，坦率地说，我感到很困惑。因为显然并非如此。我花了 7 个月的时间才让我的模拟器达到现在的水平。我认为他们真正想表达的是，让 NES 模拟器“运行起来”只需要很短的时间，比如让《大金刚》跑起来。这确实是真的，你可以很快达到 80% 或 90% 的完成度。但最后的 10% 需要花费很长很长的时间。NES 硬件有许多特性，必须对其进行模拟才能运行某些游戏。许多游戏依赖于非常特定的 NES 行为，如果你没有正确实现，它们就无法运行。

挑战的很大一部分在于时序。CPU 和 PPU（处理 NES 图形渲染的芯片）并行运行并相互通信。这种时序必须非常精确，否则可能会发生许多错误。大多数游戏在精度较低的模拟器上也能运行良好，但很多游戏不行，它们需要你更详细地考虑这些问题。另一个问题是映射器（Mappers）。映射器是我们对卡带类型实现方式的称呼。你看，NES 游戏以卡带形式存在，而卡带不仅仅是数据。它们是具有自身行为和额外资源（如只读存储器和可写存储器）的电路。有些卡带带有额外的音频功能，但我还没有实现这一点。无论如何，如果你想让某个卡带中的游戏在你的模拟器中运行，就必须实现这些映射器。它们完善了 NES 的电路，在某种程度上，它们是 NES 硬件的一部分。映射器有很多种，但你只需实现几种就能支持很多游戏。我在实现某些映射器时遇到了困难，其中一些仍然实现得很糟糕，导致某些游戏无法运行。我发现理解一些映射器文档很困难。

我认为制作模拟器最大的挑战在于知道要实现什么。关于硬件的信息，以及为了让游戏在你的模拟器中运行，需要模拟硬件的哪些部分。值得庆幸的是，NES 在线文档非常完善。我使用了许多资源，例如：Nesdev wiki；Nesdev wiki discord，这里的人们在我的问题上给了我很多帮助；Javidx 的 NES 系列，代码有很多错误，但它是一个很好的起点；这篇关于 NES PPU 的文章；测试 ROM，这些 NES ROM 可以彻底测试你模拟器的特定方面，这是加速模拟器精度开发的非凡工具。如果没有这些资源以及 nesdev discord 中人们的帮助，我将无法完成这一切。

### Odin
Odin：在制作这个项目的过程中，我学到了很多关于 Odin 的知识。我认为它非常适合这个项目。作为一个非常简单、强类型的类 C 语言，它给了我想要的所有自由，我觉得这让制作模拟器比使用其他语言容易得多。有一件事让我感到困惑，那就是 Odin 没有自动整数提升。在对数字进行计算时，Odin 永远不会将类型提升为更大的类型。这导致了一些错误，但我把这归咎于我自己，因为我习惯了 C 语言的整数提升。我学到的一件有趣的事情是内存分配策略。Odin 没有自动内存管理，所以你必须想出聪明的办法来处理内存。我很高兴思考如何最好地处理内存。我不需要做任何复杂的事情。我主要使用一个每帧清除的临时分配器、一个用于需要永久存在对象的全局堆分配器，以及一个用于需要随 NES 会话存在对象的 NES Arena 分配器。我发现内存分配很有趣。

我必须学习的另一件事是如何序列化 Odin 对象。我使用了 CBOR 库，并遇到了一些问题。我以为我的代码行为异常是因为库中的错误，但后来澄清了。它之所以出现问题，只是因为我创建了一些它不知道如何序列化的奇怪类型。一旦我学会了如何正确编写类型的自定义处理程序，一切就完美运行了。这是 cbor 不知道如何序列化的棘手类型之一：

```odin
PpuCtrl :: struct #raw_union { // VPHB SINN
    using flags: bit_field u8 {
        n: u8 | 2,
        i: u8 | 1,
        s: u8 | 1, // sprite pattern table address for 8x8 sprites (0: $0000, 1: $1000)
        b: u8 | 1, // bg pattern table address (0: $0000, 1: $1000)
        h: u8 | 1, // sprite size (0: 8x8, 1: 8x16)
        p: u8 | 1,
        v: u8 | 1, // vblank NMI enable
    },
    reg: u8,
}
```

我喜欢 Odin 允许你这样定义原始联合体（raw unions）以及位域（bit fields）的方式。它非常适合模拟器开发。
