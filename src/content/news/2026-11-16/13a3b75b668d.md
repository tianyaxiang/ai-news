# Readarr title matches show why retired admin consoles still need ownership

Readarr is a book-library automation application with a web UI and an API. It can manage authors, books, indexers, download clients, and files. Even when a product is retired or replaced, an exposed deployment can keep credentials and operational authority in place.

Readarr 是一款图书库自动化应用程序，具有 Web 用户界面和 API。它可以管理作者、书籍、索引器、下载客户端和文件。即使产品已停用或被替换，暴露的部署仍可能保留凭据和操作权限。

The ZoomEye count-only observation on 2026-11-16 found 0 app matches, 8,089 title matches, and 21,784 http.body matches for Readarr. The probes used sub_type=all, page 1, and pagesize 1. The body and title terms are common in package names, tutorials, and fork documentation, so the counts include many pages that are not live instances.

2026 年 11 月 16 日的 ZoomEye 仅计数观察发现，Readarr 有 0 个应用程序匹配项、8,089 个标题匹配项和 21,784 个 http.body 匹配项。探测使用了 sub_type=all、page 1 和 pagesize 1。正文和标题术语在包名称、教程和分支文档中很常见，因此这些计数包含了许多并非实时实例的页面。

The Servarr FAQ recommends authentication whenever the UI is reachable from outside the local network. It describes local-address exceptions, an external authentication mode for deployments behind a trusted proxy, and recovery by editing the application configuration. The settings documentation also identifies the API key and URL base. These fields define a meaningful review: who can log in, what can the proxy bypass, and which integrations hold the API key.

Servarr 常见问题解答建议，只要可以从本地网络外部访问 UI，就应进行身份验证。它描述了本地地址异常、用于受信任代理后方部署的外部身份验证模式，以及通过编辑应用程序配置进行恢复的方法。设置文档还标识了 API 密钥和 URL 基础路径。这些字段定义了有意义的审查内容：谁可以登录、代理可以绕过什么，以及哪些集成持有 API 密钥。

### Find the administration boundary

### 确定管理边界

The UI and API are different entry points. A reverse proxy that protects the UI but leaves /api open gives an integration key a direct path. Test the proxy rules with the owner's authorization and verify that API authentication is enforced at the application. If local-address authentication is disabled, confirm that all clients appear to the application as trusted local addresses only when they arrive through the intended path.

UI 和 API 是不同的入口点。保护 UI 但保持 /api 开放的反向代理会为集成密钥提供直接路径。在获得所有者授权的情况下测试代理规则，并验证应用程序是否强制执行了 API 身份验证。如果禁用了本地地址身份验证，请确认所有客户端仅在通过预期路径到达时，才会被应用程序视为受信任的本地地址。

External authentication can reduce double login behind Authelia, authentik, or NGINX. It also makes the proxy the identity gate. If the proxy is bypassable or accepts a user-supplied identity header, the application may see a trusted request that never passed authentication. Restrict the application port and define which proxy headers are accepted.

外部身份验证可以减少在 Authelia、authentik 或 NGINX 后方的二次登录。它还将代理作为身份网关。如果代理可以被绕过或接受用户提供的身份标头，应用程序可能会看到从未通过身份验证的受信任请求。请限制应用程序端口并定义接受哪些代理标头。

### Inventory credentials and integrations

### 盘点凭据和集成

Readarr may hold indexer API keys, download-client credentials, notification tokens, and its own API key. Each expands the blast radius of an administrative session. Record the owner, purpose, last use, and rotation path. Remove integrations that no longer work. A retired application still needs a decision about its credentials and data because an old instance can continue to expose them.

Readarr 可能持有索引器 API 密钥、下载客户端凭据、通知令牌及其自身的 API 密钥。每一个都会扩大管理会话的影响范围。记录所有者、用途、最后使用时间和轮换路径。删除不再有效的集成。对于已停用的应用程序，仍需对其凭据和数据做出决定，因为旧实例可能会持续暴露这些信息。

The library and download paths need least privilege. Check whether the service account can write outside the intended directories and whether a post-processing command can run arbitrary programs. Backups should include the configuration needed for recovery, but they must be protected like password stores.

库路径和下载路径需要最小权限。检查服务帐户是否可以在预期目录之外写入，以及后处理命令是否可以运行任意程序。备份应包含恢复所需的配置，但必须像保护密码存储一样保护它们。

### Turn the count into an ownership decision

### 将计数转化为所有权决策

The 8,089-title count is not a count of vulnerable hosts. It is a broad discovery lead that needs page validation. For each candidate, record the final URL, product assets, login response, URL base, and version evidence. Ask whether the owner still uses the application, whether the deployment is in a supported state, and whether the console can be retired with its credentials.

8,089 个标题计数并非易受攻击主机的数量。这是一个需要页面验证的广泛发现线索。对于每个候选对象，记录最终 URL、产品资产、登录响应、URL 基础路径和版本证据。询问所有者是否仍在使用该应用程序、部署是否处于受支持状态，以及控制台及其凭据是否可以停用。

A retired service can remain on the internet after the team has moved to a new tool. The review should include DNS, reverse-proxy configuration, containers, system services, API keys, and stored book or account data. Readarr's title count is useful because it keeps those forgotten consoles visible. The fix is an owner, a migration or removal path, and proof that the old service and its credentials are gone.

即使团队已迁移到新工具，已停用的服务仍可能保留在互联网上。审查应包括 DNS、反向代理配置、容器、系统服务、API 密钥以及存储的书籍或帐户数据。Readarr 的标题计数很有用，因为它使那些被遗忘的控制台保持可见。解决方案是确定所有者、制定迁移或删除路径，并证明旧服务及其凭据已彻底清除。
