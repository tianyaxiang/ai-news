Coding-agent CLIs do the work: CodeBuddy, Codex, Claude Code, OpenCode, Cursor CLI, Antigravity, Kimi Code, Pi, DeepSeek Harness and ZCode. LoopForge adds the roles, sandboxes, checkpoints and history around them, all on your own infrastructure under the MIT license.

编程智能体命令行工具（CLI）负责执行工作：CodeBuddy、Codex、Claude Code、OpenCode、Cursor CLI、Antigravity、Kimi Code、Pi、DeepSeek Harness 和 ZCode。LoopForge 在这些工具之上增加了角色、沙箱、检查点和历史记录功能，所有这些均在您自己的基础设施上运行，并采用 MIT 许可证。

Two ways to work: Chat with Main Bot (Best for Exploring, quick fixes, iterating with the agent) or Run an SOP (Repeatable delivery with fixed stages and sign-off).

两种工作方式：与主机器人聊天（最适合探索、快速修复和与智能体迭代）或运行 SOP（具有固定阶段和签字确认的可重复交付）。

How it runs: Main Bot opens a conversation workspace (a Docker sandbox with your repos) on demand and calls project roles as subagents. The engine runs Agent, Script, Human-gate and sub-SOP nodes in order, in their own sandbox. You stay in control by Queuing or steering messages mid-reply, and pausing, resuming or taking over a running SOP from chat. Approving at human gates, sending work back to a chosen step, retrying or rerunning from any node.

运行机制：主机器人按需打开对话工作空间（包含您代码仓库的 Docker 沙箱），并将项目角色作为子智能体调用。引擎在各自的沙箱中按顺序运行智能体、脚本、人工审核和子 SOP 节点。您可以通过在回复过程中排队或引导消息，以及从聊天中暂停、恢复或接管正在运行的 SOP 来保持控制。您可以在人工审核节点进行批准，将工作退回到选定步骤，或从任何节点重试或重新运行。

Delivers: A PR/MR, or a direct merge into a shared branch (mode=direct). Documents, code or a PR, plus per-node artifacts and logs. Both paths track the same requirements, so every change, whether made in chat or by an SOP, links back to what was asked for and counts toward delivery and cost reports.

交付成果：一个 PR/MR，或直接合并到共享分支（模式=direct）。文档、代码或 PR，以及每个节点的产物和日志。两种路径都追踪相同的需求，因此每一次变更，无论是在聊天中还是通过 SOP 完成的，都会关联回原始需求，并计入交付和成本报告。

Why LoopForge: Ask a coding agent to "fix this bug" and the result depends on that run. It might skip the plan, forget the tests, review its own code, or stop halfway without anyone noticing. That's fine for a demo, but it isn't how a team ships. Repeatable. Same SOP, same stages, same checks for every requirement. Start from built-in backend, frontend, bug-fix and product SOPs. Separated roles. Planning, implementation, review and testing each get their own prompt, executor, model, rules, Skills and MCP tools. A role works as an SOP node or as a subagent in chat. Human in the loop. Approval gates where they matter. Read the report, approve, or send the work back to a chosen step. Observable and resumable. Node status, tool traces, logs and artifacts in one place. Pause, retry a failed step, or rerun from any node. Your stack, your servers. Ten coding-agent CLIs as executors, from CodeBuddy, Codex and Claude Code to OpenCode, Cursor CLI and more. GitHub, Skills and MCP as tools. Docker sandboxes or your own machine as the runtime.

为什么选择 LoopForge：要求编程智能体“修复此 Bug”，结果取决于单次运行。它可能会跳过计划、忘记测试、审查自己的代码，或者在无人察觉的情况下中途停止。这对于演示来说没问题，但不是团队交付软件的方式。可重复性：每个需求都使用相同的 SOP、相同的阶段和相同的检查。从内置的后端、前端、Bug 修复和产品 SOP 开始。角色分离：规划、实现、审查和测试各有其提示词、执行器、模型、规则、技能和 MCP 工具。角色既可以作为 SOP 节点，也可以作为聊天中的子智能体。人在回路：在关键环节设置批准节点。阅读报告、批准或将工作退回到选定步骤。可观测且可恢复：节点状态、工具追踪、日志和产物集中管理。暂停、重试失败步骤或从任何节点重新运行。您的技术栈，您的服务器：十种编程智能体 CLI 作为执行器，从 CodeBuddy、Codex 和 Claude Code 到 OpenCode、Cursor CLI 等。GitHub、技能和 MCP 作为工具。Docker 沙箱或您自己的机器作为运行时。

Quick start: Install Git and clone the repository first. The installer checks Docker, Compose, Python 3 and curl and offers to install missing components. Python/curl installation supports apt, dnf and yum on Linux; the Compose plugin supports x86_64/arm64 and verifies the official release SHA-256. macOS needs a working Python 3 and Docker Desktop; Homebrew can install missing components. Ordinary Linux users are supported through Docker group access or sudo. Set LOOPFORGE_YES=1 to accept installation prompts. Package and image downloads require internet access.

快速入门：首先安装 Git 并克隆仓库。安装程序会检查 Docker、Compose、Python 3 和 curl，并提示安装缺失的组件。Python/curl 安装在 Linux 上支持 apt、dnf 和 yum；Compose 插件支持 x86_64/arm64 并验证官方发布的 SHA-256。macOS 需要可用的 Python 3 和 Docker Desktop；Homebrew 可以安装缺失的组件。普通 Linux 用户可以通过 Docker 组访问权限或 sudo 使用。设置 LOOPFORGE_YES=1 以自动接受安装提示。软件包和镜像下载需要互联网连接。

git clone https://github.com/Tencent/LoopForge.git
cd LoopForge
./start.sh

./start.sh pulls the GHCR release image pinned in compose.yaml without building locally (bash scripts/install.sh does the same). It creates the MySQL and platform services, generates configuration and session secrets, and installs the built-in sandboxes, starter SOPs and welcome project. Host Go and Node.js installations are not required. Configure model API keys and GitHub authorization after startup. Use ./start.sh logs, stop, restart or pull to manage it, and ./start.sh dev to build the checkout from source.

./start.sh 会拉取 compose.yaml 中指定的 GHCR 发布镜像，而无需在本地构建（bash scripts/install.sh 执行相同操作）。它会创建 MySQL 和平台服务，生成配置和会话密钥，并安装内置沙箱、入门 SOP 和欢迎项目。无需安装 Go 和 Node.js。启动后配置模型 API 密钥和 GitHub 授权。使用 ./start.sh logs、stop、restart 或 pull 进行管理，使用 ./start.sh dev 从源码构建。

If downloads from ghcr.io stall, set MIRROR to a registry host that can stand in for ghcr.io. ./start.sh pulls from that host and tags the image back to the name pinned in compose.yaml. Setting MIRROR trusts that host, because the download is tagged with the official name. The GitHub Release records the digest; docker image inspect --format '{{index .RepoDigests 0}}' ghcr.io/tencent/loopforge:<pin> should show the same digest after @. Without MIRROR, ./start.sh still pulls ghcr.io directly, and compose.yaml stays unchanged. Upgrade with the same variable and ./start.sh pull. ghcr.nju.edu.cn is one such host. A Docker registry-mirrors entry such as https://docker.nju.edu.cn only accelerates Docker Hub and is not a value for MIRROR. MIRROR=ghcr.nju.edu.cn ./start.sh

如果从 ghcr.io 下载缓慢，请将 MIRROR 设置为可以替代 ghcr.io 的镜像仓库主机。./start.sh 会从该主机拉取镜像，并将其重新标记为 compose.yaml 中指定的名称。设置 MIRROR 意味着信任该主机，因为下载的镜像会被标记为官方名称。GitHub Release 会记录摘要；docker image inspect --format '{{index .RepoDigests 0}}' ghcr.io/tencent/loopforge:<pin> 应该在 @ 之后显示相同的摘要。如果不使用 MIRROR，./start.sh 仍会直接从 ghcr.io 拉取，且 compose.yaml 保持不变。使用相同的变量和 ./start.sh pull 进行升级。ghcr.nju.edu.cn 就是这样一个主机。Docker registry-mirrors 条目（如 https://docker.nju.edu.cn）仅加速 Docker Hub，不能作为 MIRROR 的值。MIRROR=ghcr.nju.edu.cn ./start.sh

Open the address printed by the installer and create your account; the first one becomes the administrator. The service listens on 0.0.0.0:8090 by default. On a cloud host, the installer reads the public IP from the provider's metadata service and prints it; allow the port in your security group, or put an HTTPS reverse proxy in front. Restrict access to your own IP until the administrator account exists. The home page's quick-access guide walks you through adding a model key, connecting a repository and choosing an SOP. For GitLab, Gitea, Gogs and other Git hosts, set up Git SSH to check out and push branches with a personal key. PR/MR and Issue automation requires a hosting API token or a separately configured MCP.

打开安装程序打印的地址并创建您的账户；第一个账户将成为管理员。服务默认监听 0.0.0.0:8090。在云主机上，安装程序会从提供商的元数据服务读取并打印公网 IP；请在安全组中放行该端口，或在前端放置 HTTPS 反向代理。在管理员账户创建之前，请限制访问权限仅限您自己的 IP。主页的快速访问指南将引导您添加模型密钥、连接仓库并选择 SOP。对于 GitLab、Gitea、Gogs 和其他 Git 主机，请设置 Git SSH 以使用个人密钥检出和推送分支。PR/MR 和 Issue 自动化需要托管平台的 API 令牌或单独配置的 MCP。
