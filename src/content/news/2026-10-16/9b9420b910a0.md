Muse Spark Open is an agentic focused model that plans, acts, observes, and self-corrects over long tasks, including browsing the web with images.

Mixture of Experts The language model has 62 layers and a hidden dimension of 8192. Each layer has 128 query heads and 16 key-value heads (grouped-query attention). Each head has 64 dimensions. The attention block has an output gate and an output normalization layer. The model also applies normalization to the queries and the keys (QK-norm). Each block combines its input and its output through a learned residual gate, not through a plain sum. Muse Glimmer uses one dense feed-forward network in each layer. Muse Spark Open replaces this dense network with a Mixture-of-Experts (MoE) block. Each MoE block has 256 experts, and a router selects 8 experts for each token. Each expert is a feed-forward network that projects from 8192 to 4096 dimensions and back to 8192, then applies its own normalization to its output. The experts hold ~97% of the total model parameters. Only 8 experts run per token, so the model computes each token with about 42B parameters. All 256 experts stay in memory, so deployment needs the memory of an 816B-parameter model, but runs at the much faster speed of a 42B model. The BF16 checkpoint is about 1.5 TB in safetensors format. The NVFP4 checkpoint stores the parameters in 4-bit precision with negligible loss in accuracy, specifically for NVIDIA Blackwell GPUs. In transformers, the BF16 checkpoint runs across 4 nodes of 8 H200 GPUs with tensor parallelism (TP=32) and the NVFP4 runs on a single B200 node. If you want to deploy Muse Spark Open, check out the llama.cpp, vLLM, and SGLang recipes below.

混合专家：该语言模型拥有 62 层，隐藏维度为 8192。每一层有 128 个查询头和 16 个键值头（分组查询注意力）。每个头有 64 个维度。注意力模块包含一个输出门和一个输出归一化层。模型还对查询和键应用了归一化（QK-norm）。每个模块通过学习到的残差门结合输入和输出，而不是简单的相加。Muse Glimmer 在每一层使用一个密集前馈网络，而 Muse Spark Open 将其替换为混合专家（MoE）模块。每个 MoE 模块有 256 个专家，路由器为每个 token 选择 8 个专家。每个专家都是一个前馈网络，将维度从 8192 投影到 4096 再回到 8192，然后对其输出应用归一化。专家占据了总模型参数的约 97%。每个 token 仅运行 8 个专家，因此模型计算每个 token 时使用约 420 亿参数。所有 256 个专家都驻留在内存中，因此部署需要 8160 亿参数模型的内存容量，但运行速度却快得多，相当于 420 亿参数模型。BF16 检查点在 safetensors 格式下约为 1.5 TB。NVFP4 检查点以 4 位精度存储参数，精度损失可忽略不计，专为 NVIDIA Blackwell GPU 设计。在 transformers 中，BF16 检查点运行在 4 个节点（每个节点 8 个 H200 GPU）上，采用张量并行（TP=32），而 NVFP4 运行在单个 B200 节点上。如需部署 Muse Spark Open，请查看下方的 llama.cpp、vLLM 和 SGLang 配方。

Perception Encoder A perception encoder converts images and video frames into tokens for the language model, just like Muse Glimmer. The encoder has 1.8B parameters, 50 layers, a hidden dimension of 1536, and 16 attention heads. It splits each image into 14×14 patches and produces features with 4096 dimensions. Position information comes from learned absolute embeddings and 2D RoPE. The feed-forward network in each layer uses LayerNorm and GELU. Every fourth layer and the last layer use full attention, and the other layers use sparse attention. Muse Glimmer 30B uses an encoder with the same architecture. The design follows the Perception Encoder work from Meta. Video input goes through the same encoder as images.

感知编码器：感知编码器将图像和视频帧转换为语言模型的 token，与 Muse Glimmer 一样。该编码器拥有 18 亿参数、50 层、1536 的隐藏维度和 16 个注意力头。它将每张图像分割成 14×14 的补丁，并生成 4096 维的特征。位置信息来自学习到的绝对嵌入和 2D RoPE。每一层的前馈网络使用 LayerNorm 和 GELU。每隔四层以及最后一层使用全注意力机制，其他层使用稀疏注意力。Muse Glimmer 30B 使用了相同架构的编码器。该设计遵循 Meta 的感知编码器研究。视频输入通过与图像相同的编码器进行处理。

Audio Encoder Muse Spark Open accepts audio as input through its audio encoder. An audio tokenizer converts the audio into tokens, and the chat template marks the audio position with <|audio|> tokens. The encoder emits one audio token every 80 ms, which yields 12.5 tokens per second. So let’s say, you have an audio of 10 seconds, the number of input audio tokens would be 125. The encoder itself is a convolutional pyramid where each stage consists of a patch embedder of different patch sizes and 2 convolutional blocks of 1d kernels of size 7 with stride of 1. These stages are repeated for patch sizes of [16, 6, 5, 4]. At the end of the final stage, the temporal frames are fed to a final block of RMSNorm → linear projection → RMSNorm.

音频编码器：Muse Spark Open 通过其音频编码器接收音频输入。音频分词器将音频转换为 token，聊天模板使用 <|audio|> token 标记音频位置。编码器每 80 毫秒发出一个音频 token，即每秒 12.5 个 token。假设你有 10 秒的音频，输入音频 token 的数量将是 125 个。编码器本身是一个卷积金字塔，每一级由不同补丁大小的补丁嵌入器和 2 个 1D 卷积块（核大小为 7，步长为 1）组成。这些阶段针对 [16, 6, 5, 4] 的补丁大小进行重复。在最后阶段结束时，时间帧被馈送到一个最终模块：RMSNorm → 线性投影 → RMSNorm。

Long Context The context window is 1M tokens at inference. The configuration sets max_position_embeddings to 1,048,576. This includes image, video, and audio tokens in the same window as text. Grouped-query attention keeps the KV cache small for a model of this size. Each token adds 2 × 16 heads × 64 dimensions × 62 layers = 126,976 values to the cache.
