# Why long context is expensive: the KV cache bill

你的聊天记录所占用的空间可能比读取它的模型还要大。Llama 3.1 8B 是一个 16 GB 的模型。如果给它一个 100 万 token 的提示词，仅其 KV 缓存就需要 128 GB 的空间。

Your chat history can weigh more than the model that reads it. Llama 3.1 8B is a 16 GB model. Give it a 1M-token prompt and its KV cache alone needs 128 GB.

为什么存在缓存？Transformer 本身没有记忆。RNN 保持一个小的隐藏状态，大小恒定，但它会遗忘信息。Transformer 在每一步都会重新读取整个对话，因此每个 token 在每一层都会被存储为 Key 和 Value 向量。存储一次，永久复用。这个存储空间就是 KV 缓存。

Why the cache exists Transformers have no memory of their own. RNNs kept one small hidden state, constant size, but it forgot things. Transformers re-read the whole conversation at every step, so each token gets stored as Key and Value vectors at every layer. Store once, reuse forever. That store is the KV cache.

账单计算：缓存 = 2 (K 和 V) × 层数 × KV 头数 × 头维度 × token 数 × 2 字节。对于 8B 模型：每个 token 占用 128 KiB。128K 上下文：16 GB，与模型本身大小相同；100 万 token：128 GB，超过了一张 H100 的显存容量。

The bill cache = 2 (K and V) × layers × KV heads × head dim × tokens × 2 bytes For the 8B: 128 KiB per token. 128K context: 16 GB, the same as the model itself 1M tokens: 128 GB, more than one H100 holds

更大的模型代价更高：70B 模型每个 token 需要 320 KiB，在 128K 上下文下为 43 GB，在 100 万 token 下为 344 GB。分组查询注意力（Grouped-query attention）机制让这一切尚可接受（使用 8 个共享 KV 头而不是 32 个），否则这些数值会恶化 4 到 8 倍。

Bigger models pay more: the 70B needs 320 KiB per token, 43 GB at 128K and 344 GB at 1M. Grouped-query attention keeps this livable (8 shared KV heads instead of 32), or these would be 4-8x worse.

注意力的数学运算在顶层是二次方的，因此更长的上下文意味着每个单词需要更多的内存和计算量。长上下文并不是内存的升级，而是一笔存储账单。在某种规模下，对话本身成为了数据中心里最昂贵的对象。

Attention's math is quadratic on top, so longer context means more memory and more work per word. Long context isn't a memory upgrade. It's a storage bill. At some scale the conversation is the most expensive object in the datacenter.
