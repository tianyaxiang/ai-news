# Android apps running native on macOS

在 Apple Silicon Mac 上原生运行 Android 应用。无需模拟器，无需虚拟机，底层也没有 Linux。

Alpha. Mac.apk is early software under active development. Some apps run beautifully, some run partially, and some do not run yet. It is stable enough to use and interesting enough to explore, and it improves with every build.

Mac.apk 是处于早期开发阶段的软件。有些应用运行效果极佳，有些部分可用，还有些尚无法运行。它目前足够稳定，值得探索，并且每个版本都在不断改进。

Mac.apk runs Android apps directly on Apple Silicon. Apps launch as ordinary macOS processes, draw through the Mac's GPU, and execute on the CPU at native speed. They appear in your Dock, get their own windows with a back button next to the traffic lights, resize and rotate like any Mac window, and switch between light and dark along with your Mac. Android TV apps work from the keyboard, and game launchers can start your other installed apps.

Mac.apk 直接在 Apple Silicon 上运行 Android 应用。应用以普通的 macOS 进程启动，通过 Mac 的 GPU 进行渲染，并以原生速度在 CPU 上执行。它们会出现在你的程序坞（Dock）中，拥有独立的窗口，窗口左上角交通灯按钮旁带有返回键，可以像任何 Mac 窗口一样调整大小和旋转，并能随你的 Mac 系统切换深色或浅色模式。Android TV 应用支持键盘操作，游戏启动器也可以启动你安装的其他应用。

There is no emulator here, and no virtual machine. Nothing boots Android in the background, there is no Linux kernel running underneath, and nothing is interpreted instruction-by-instruction. Mac.apk implements the Android application environment on top of macOS directly. How it works →

这里没有模拟器，也没有虚拟机。后台不会启动 Android 系统，底层没有运行 Linux 内核，也没有逐条指令进行解释。Mac.apk 直接在 macOS 之上实现了 Android 应用环境。工作原理 →

The first launch of any app is slow (up to a minute for a large one) while Mac.apk prepares it. Later launches are fast. Full details, updating, and the app stores are in the Installation and App stores pages.

任何应用首次启动时都会较慢（大型应用可能长达一分钟），因为 Mac.apk 需要对其进行准备。后续启动则会很快。完整详情、更新说明以及应用商店信息请参阅“安装”和“应用商店”页面。

Each app's data lives in ~/Library/Application Support/MacApk/<package>, not inside its .app. Dragging an app to the Trash leaves that data behind; Uninstall in the Mac.apk window cleans it up and can keep your saves for a reinstall. More →

每个应用的数据都存储在 ~/Library/Application Support/MacApk/<package> 中，而不是在其 .app 文件内部。将应用拖入废纸篓会保留这些数据；在 Mac.apk 窗口中执行卸载操作则会清理数据，并可选择保留存档以便重装。更多 →

See Known issues for this release, and the compatibility list for every app tested by hand.

请参阅此版本的“已知问题”，以及经人工测试的所有应用的兼容性列表。

Everything that makes Mac.apk work is in this repository: the Android framework reimplementation, the native runtime, the arm64 loader and Bionic shim, the ARM32 recompiler and the macOS app. BUILDING.md explains how to build it, and CONTRIBUTING.md how to send a fix. App reports are just as useful as code.

使 Mac.apk 运行所需的一切都在此仓库中：Android 框架重实现、原生运行时、arm64 加载器和 Bionic 垫片、ARM32 重编译器以及 macOS 应用本身。BUILDING.md 解释了如何构建它，CONTRIBUTING.md 则说明了如何提交修复。应用报告与代码一样有用。

Only install APKs you trust. An Android app running under Mac.apk runs as ordinary native code with your macOS user account's permissions. There is no phone-style app sandbox around it: it can read and write your files the same way any Mac app you run can. Treat an APK exactly as you would any program you download and run yourself, and get it from a source you trust.
