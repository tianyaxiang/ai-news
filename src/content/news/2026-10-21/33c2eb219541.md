1. Goal & Background The target is the announcement list of a provincial government procurement e-marketplace (referred to as "Site J"). I wanted to scrape its notice-list endpoint. Target site: https://www.example.com (a government procurement e-marketplace) Target endpoint: https://www.example.com/<notice-list-endpoint> Fields to reconstruct: nsssjss, sign, time, timestamp — all of them custom request headers Difficulty: ⭐⭐⭐⭐ — one header is RSA-encrypted, another is a "SHA1 wrapped in MD5" nested hash, and the whole JS is obfuscated with a string array. This case has two highlights: The weird name nsssjss is essentially RSA encryption of API path + "$$" + timestamp; sign is not a plain MD5 but a nested hash md5(sha1(...)) — at first I only computed MD5 and could never get it to match.

1. 目标与背景：目标是某省级政府采购电子交易平台（简称“J 站”）的公告列表。我希望爬取其公告列表接口。目标站点：https://www.example.com（某政府采购电子交易平台）。目标接口：https://www.example.com/<notice-list-endpoint>。需要重构的字段：nsssjss, sign, time, timestamp — 均为自定义请求头。难度：⭐⭐⭐⭐ — 其中一个请求头经过 RSA 加密，另一个是“MD5 包裹 SHA1”的嵌套哈希，且整个 JS 代码通过字符串数组进行了混淆。本案例有两个亮点：奇怪的名称 nsssjss 本质上是对 API 路径 + "$$" + 时间戳进行的 RSA 加密；sign 并非简单的 MD5，而是嵌套哈希 md5(sha1(...)) — 起初我只计算了 MD5，导致始终无法匹配。

2. Traffic Analysis Open the notice page, press F12 → Network, filter by Fetch/XHR, and flip pages to capture: POST https://www.example.com/<notice-list-endpoint> Look at the Request Headers — besides the normal ones, a bunch of site-defined headers really stand out: nsssjss: <Base64 ciphertext> sign: <32-hex string> time: <ms timestamp> timestamp: <ms timestamp> sitecode: <SITE_CODE> siteguid: <SITE_GUID> regioncode: <REGION_CODE> regionguid: <REGION_GUID> url: /<notice-list-endpoint> form-token: <FORM_TOKEN> webapp: 1 Now look at the Payload, which is an ordinary JSON: {"regionGuid":"232","regionCode":"<REGION_CODE>","webApp":"1","pageSize":10,"pageNum":4,"noticeType":"0"} Conclusion: the request body is plaintext; all the encryption is in the headers. Specifically: nsssjss is Base64 ciphertext (an RSA signature — a public key starting with MIGf... produces long Base64 when used to encrypt); sign is 32-hex (a hash signature); time / timestamp are two millisecond timestamps whose values are very close, indicating they were taken separately at request time.

2. 流量分析：打开公告页面，按 F12 → Network，过滤 Fetch/XHR，翻页抓包：POST https://www.example.com/<notice-list-endpoint>。查看请求头（Request Headers）——除了常规字段外，还有一堆站点自定义的请求头非常显眼：nsssjss: <Base64 密文>，sign: <32位十六进制字符串>，time: <毫秒时间戳>，timestamp: <毫秒时间戳>，sitecode: <SITE_CODE>，siteguid: <SITE_GUID>，regioncode: <REGION_CODE>，regionguid: <REGION_GUID>，url: /<notice-list-endpoint>，form-token: <FORM_TOKEN>，webapp: 1。再看 Payload，是一个普通的 JSON：{"regionGuid":"232","regionCode":"<REGION_CODE>","webApp":"1","pageSize":10,"pageNum":4,"noticeType":"0"}。结论：请求体是明文的，所有加密都在请求头中。具体来说：nsssjss 是 Base64 密文（一种 RSA 签名——以 MIGf... 开头的公钥加密后会产生较长的 Base64）；sign 是 32 位十六进制（哈希签名）；time / timestamp 是两个毫秒级时间戳，数值非常接近，表明它们是在请求时分别获取的。

3. Locating the Encryption Entry Point This site's JS is string-array obfuscated (javascript-obfuscator style), so a plaintext search for nsssjss finds nothing. My approach: Globally search the endpoint path: search for /<notice-list-endpoint>, which locates the get_arg call site; XHR breakpoint: set an XHR breakpoint on the endpoint in Sources, then inspect the call stack when it pauses to find the header-generating function; Search RSA signatures: search for setPublicKey, JSEncrypt, encrypt to locate the nsssjss generation logic. Once extracted, the structure of get_arg is actually very clear (from the real file — renamed here to js/sign.js, around line 3152): // From the real JS (renamed to js/sign.js in this write-up) function get_arg() { var nsssjss = m("".concat(_, "$$").concat(b)) // nsssjss var timestamp = b.toString() // timestamp var MMMX = BB("6f3c") var vvx = MMMX.default("/<notice-list-endpoint>", "") time = vvx["time"].toString() sign = vvx["sign"] li = {} li["nsssjss"] = nsssjss li["timestamp"] = timestamp li["time"] = time li["sign"] = sign return li } Here _ and b are two variables defined at the bottom of the file: // From the real JS b = (new Date).getTime() _ = "/<notice-list-endpoint>" So: nsssjss = m(path + "$$" + b), and m is RSA encryption; timestamp = b; sign / time come from the default() of the webpack module MMMX = BB("6f3c").
