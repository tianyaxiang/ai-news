# Introducing Kwi, a new KDE terminal emulator

Introducing Kwi, a new KDE terminal emulator
Sunday, 1 November 2026 | Eike Hein
#kde-apps I've started work on a new KDE application. It's called Kwi (pronounced kwee).

介绍 Kwi，一款全新的 KDE 终端模拟器
2026 年 11 月 1 日，星期日 | Eike Hein
#kde-apps 我已经开始着手开发一款新的 KDE 应用程序，它叫 Kwi（发音为 kwee）。

Kwi is designed to provide users of KDE Plasma and other free desktops with a modern and fast terminal, built on a robust tech stack and following the latest KDE HIG and UI conventions.
Here's a screenshot:

Kwi 旨在为 KDE Plasma 及其他自由桌面用户提供一个现代且快速的终端，它基于稳健的技术栈构建，并遵循最新的 KDE 人机交互指南（HIG）和 UI 规范。
以下是截图：

In some sense, the product vision for Kwi is to be kind of unexciting: Just what you want and expect out of a KDE Plasma terminal. Of course, given the powerful nature users generally expect from KDE software, this does not make the project lacking in ambition. :-)

从某种意义上说，Kwi 的产品愿景是保持一种“平淡无奇”：即提供你对 KDE Plasma 终端所期望的一切。当然，考虑到用户通常对 KDE 软件所抱有的强大功能期待，这并不意味着该项目缺乏雄心。:-)

To achieve things, Kwi builds on libghostty-vt from the excellent Ghostty project and familiar, mature KDE Frameworks such as KPty. It has a very speedy GPU-accelerated (Vulkan or OpenGL) renderer powered by the Qt Scene Graph. Its user interface is built with the latest and greatest by Kirigami, making it blend in very well among more recent KDE applications and the Plasma desktop.

为了实现这些目标，Kwi 基于优秀的 Ghostty 项目中的 libghostty-vt 以及熟悉的、成熟的 KDE 框架（如 KPty）构建。它拥有一个由 Qt Scene Graph 驱动的、速度极快的 GPU 加速（Vulkan 或 OpenGL）渲染器。其用户界面由最新、最棒的 Kirigami 构建，使其能够很好地融入较新的 KDE 应用程序和 Plasma 桌面中。

In keeping with the theme, Kwi's icon/logo is a cute little terminal ghost. This is also how it came to bear its name: kwisin, or more typically gwisin, is a romanized form of 귀신 - Korean for ghost. It's pronounced a little bit like kwee-shin.

为了契合主题，Kwi 的图标/Logo 是一个可爱的小终端幽灵。这也是它得名的由来：kwisin，或者更常见的 gwisin，是韩语“귀신”（意为幽灵）的罗马化拼写。它的发音有点像 kwee-shin。

Things Kwi has to offer
Compared to the venerable and mature Konsole, Kwi is young and new. At the moment it offers a more streamlined feature set than Konsole, carefully realized using KDE's latest HIG patterns. The way forward will be to build on this slowly and carefully, using everything we've learned as a community about running mature design processes over the last decade or so (hello, VDG!). It's a chance to canvass the scene, take stock of how other terminals implement more recent innovations in this space, and compete with a KDE spin on things.

Kwi 提供的功能
与古老而成熟的 Konsole 相比，Kwi 还很年轻。目前，它提供的功能集比 Konsole 更精简，并使用 KDE 最新的 HIG 模式精心实现。未来的发展方向将是缓慢而谨慎地在此基础上构建，利用我们在过去十年左右作为社区在运行成熟设计流程方面所学到的一切（向 VDG 致敬！）。这是一个审视行业现状、评估其他终端如何实现该领域最新创新，并以 KDE 的特色进行竞争的机会。

Konsole is very intertwined with the older of the two user interface tech stacks in Qt, QWidget. QWidget typically renders using the CPU, and so does Konsole. Newer KDE software (including Plasma itself) typically uses Qt Quick and benefits from GPU acceleration via Vulkan or OpenGL instead. This is what Kwi does as well. For certain terminal applications the performance gain (3x-35x faster than Konsole depending on what's being benchmarked) can make an actual big difference in the user experience, but generally it should also help reduce battery usage.

Konsole 与 Qt 中两种用户界面技术栈中较旧的一种——QWidget 紧密交织在一起。QWidget 通常使用 CPU 进行渲染，Konsole 也是如此。较新的 KDE 软件（包括 Plasma 本身）通常使用 Qt Quick，并受益于通过 Vulkan 或 OpenGL 实现的 GPU 加速。Kwi 也是这样做的。对于某些终端应用程序，性能提升（根据基准测试的不同，比 Konsole 快 3 到 35 倍）可以在用户体验上产生巨大的实际差异，而且通常也有助于降低电池消耗。

Kwi is built on libghostty-vt, a project that describes itself as an ecosystem play - provide a headless lib that takes care of all the gnarly terminal parsing and state, enable downstream projects and become sort of a rising tide that lifts all boats. It's starting to really deliver on this promise lately, outpacing other terminal implementations on support for modern TUI features and not hoarding all this good only for itself. While the library will only make an ABI/API stable v1.0 promise at some point in the next 4-6 months, it's already slowly being adopted by big and popular projects, including Neovim, Ghostel and many more. Here's a list.

Kwi 基于 libghostty-vt 构建，该项目自称为一种生态系统策略——提供一个处理所有复杂终端解析和状态的无头库，赋能下游项目，并成为一种“水涨船高”的力量。最近，它开始真正兑现这一承诺，在对现代 TUI 特性的支持上超越了其他终端实现，并且没有将这些优势据为己有。虽然该库预计在未来 4 到 6 个月内才会做出 ABI/API 稳定的 v1.0 承诺，但它已经开始被 Neovim、Ghostel 等大型热门项目缓慢采用。这里有一个列表。

Why make this, continued - a little bit about architecture
Why make this? First of all, to deliver the marked advantages detailed above! But there are also a few deeper motivations at play.
There's a gap we currently have in our developer offerings: Konsole, being strongly tied into the older QWidget tech stack, offers an embeddable component used in various QWidget-based KDE apps, for example Dolphin, Kate and Yakuake (the Kwi project offers a drop-in replacement solution for these apps). It doesn't offer anything similar to KDE apps written in Qt Quick/Kirigami, however, nor can it easily. This is a (minor) factor increasing the friction to move these KDE apps to the new tech stack. It also leaves new Qt Quick/Kirigami apps without a well-realized KDE terminal component to use.
