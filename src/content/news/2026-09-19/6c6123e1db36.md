### 📌 Overview / 概览

Octop is a self-hosted AI assistant platform for households and small teams. It runs a single process that serves a web dashboard, a CLI, IM channels (Feishu, DingTalk, QQ, Discord, WeCom, and more), and cron automation — all sharing one control-plane database under `~/.octop/` (SQLite by default; PostgreSQL optional). Octop's design goal: keep every conversation, workspace, and credential on your own machine, while giving each user a personal team of specialized agents they can switch between per task.

Octop 是一个面向家庭和小团队的自托管 AI 助手平台。它通过单一进程运行，提供 Web 仪表盘、CLI、IM 频道（飞书、钉钉、QQ、Discord、企业微信等）以及定时任务自动化——所有功能共享 `~/.octop/` 下的一个控制平面数据库（默认为 SQLite，可选 PostgreSQL）。Octop 的设计目标是：将每一次对话、工作区和凭据都保留在你的机器上，同时为每个用户提供一个专属的专家智能体团队，用户可以根据任务需求在不同智能体之间切换。

### 🧠 Core Technology / 核心技术

| Layer | Technology |
| :--- | :--- |
| **Language** | Python 3.12+ |
| **Web framework** | FastAPI + uvicorn |
| **Agent runtime** | harness-agent |
| **Gateway** | harness-gateway |
| **Control plane DB** | SQLite (WAL, default) or PostgreSQL (optional) |
| **Frontend** | React 18 + TypeScript + Vite + Ant Design |
| **Scheduling** | APScheduler |
| **ACP** | agent-client-protocol |
| **Build / quality** | hatchling · ruff · mypy · pytest |

Octop is built on the Harness stack — a set of focused runtimes that Octop composes into one process:
Octop 基于 Harness 技术栈构建——这是一套专注于运行时的组件，Octop 将它们组合成一个进程：

*   **harness-agent:** Agent runtime: model routing, tools, skills, and conversation checkpointing.
    **harness-agent：** 智能体运行时：模型路由、工具、技能和对话检查点。
*   **harness-gateway:** multi-platform IM channel bridge that normalizes incoming messages into a single processing pipeline.
    **harness-gateway：** 多平台 IM 频道桥接器，将传入的消息标准化为单一处理流水线。
*   **harness-memory:** hierarchical recall with full-text search, so an agent's memory travels with its workspace.
    **harness-memory：** 具备全文搜索的分层回溯功能，使智能体的记忆随工作区同步。
*   **harness-browser:** CDP-based browser automation with persistent profiles for web tasks.
    **harness-browser：** 基于 CDP 的浏览器自动化，支持网页任务的持久化配置。

Instead of an external queue or message broker, Octop routes every surface — Web UI, IM, and cron — through one in-process `HarnessProcessor`. The result is a single, restart-safe process whose entire state is rebuilt from the control-plane database on boot (local SQLite by default; PostgreSQL optional).

Octop 不依赖外部队列或消息代理，而是通过一个进程内的 `HarnessProcessor` 路由所有交互界面（Web UI、IM 和定时任务）。其结果是一个单一的、支持重启的进程，启动时会从控制平面数据库（默认为本地 SQLite，可选 PostgreSQL）重建所有状态。
