### 2. Executive Summary
A vulnerability in Drupal allows an unauthenticated attacker to re-execute core/install.php under specific conditions and attempt to reinstall Drupal, potentially leading to site takeover or remote code execution (RCE).

### 2. 执行摘要
Drupal 中的一个漏洞允许未经身份验证的攻击者在特定条件下重新执行 core/install.php 并尝试重新安装 Drupal，这可能导致站点接管或远程代码执行 (RCE)。

### 3. Attack Flow
Path from Installer Re-Execution to Site Takeover or RCE: An attacker sends a request to an externally accessible /core/install.php. The attacker uses the installer under specific conditions to attempt a Drupal reinstallation. Depending on the applicable path and configuration, this leads to site takeover or remote code execution (RCE).

### 3. 攻击流程
从安装程序重新执行到站点接管或 RCE 的路径：攻击者向外部可访问的 /core/install.php 发送请求。攻击者在特定条件下使用安装程序尝试重新安装 Drupal。根据适用的路径和配置，这会导致站点接管或远程代码执行 (RCE)。

### 4. Attacker Position and Execution Location
An unauthenticated remote attacker who can reach the Drupal installer.

### 4. 攻击者位置与执行地点
能够访问 Drupal 安装程序的未经身份验证的远程攻击者。

### 5. Visibility for Victims and Administrators
This may appear as service disruption, authentication anomalies, configuration tampering, or data access. Administrators should review requests, processes, files, and account changes along the same timeline.

### 5. 受害者与管理员的可见性
这可能表现为服务中断、身份验证异常、配置篡改或数据访问。管理员应审查同一时间线内的请求、进程、文件和账户变更。

### 6. Success and Failure Conditions
Success Conditions: Running an affected version of Drupal; The installer is reachable from the web; Site state and permission conditions permit reinstallation.
Failure and Mitigation Conditions: Updated to Drupal 10.6.22 or later for 10.6.x, 11.3.22 or later for 11.3.x, and 11.4.13 or later for 11.4.x. End-of-life versions (10.5.x and earlier, 11.2.x and earlier) require migration to a supported series. If the web server can neither write to settings.php nor change its permissions, some exploitation paths are mitigated. This alone may not prevent all exploitation paths. /core/install.php is blocked.

### 6. 成功与失败条件
成功条件：运行受影响的 Drupal 版本；安装程序可从 Web 访问；站点状态和权限条件允许重新安装。
失败与缓解条件：对于 10.6.x 更新至 Drupal 10.6.22 或更高版本，对于 11.3.x 更新至 11.3.22 或更高版本，对于 11.4.x 更新至 11.4.13 或更高版本。已停止支持的版本（10.5.x 及更早版本，11.2.x 及更早版本）需要迁移到受支持的系列。如果 Web 服务器既不能写入 settings.php 也不能更改其权限，则某些利用路径会得到缓解。仅此一项可能无法阻止所有利用路径。/core/install.php 被阻止。

### 7. What Happens Upon Success
Site takeover; Tampering with content, accounts, and configurations; Code execution with web server process privileges.

### 7. 成功后的后果
站点接管；篡改内容、账户和配置；以 Web 服务器进程权限执行代码。

### 8. Observable Logs
External access to /core/install.php; Installer-related POST requests and rapid configuration changes; Changes to the mtime (modification time) or permissions of settings.php; New administrator accounts, modules, themes, or suspicious PHP files. Installer access is confirmed via web server request logs, configuration changes via file auditing, and new administrators via authentication records.

### 8. 可观测日志
对 /core/install.php 的外部访问；与安装程序相关的 POST 请求和快速配置更改；settings.php 的 mtime（修改时间）或权限更改；新的管理员账户、模块、主题或可疑的 PHP 文件。通过 Web 服务器请求日志确认安装程序访问，通过文件审计确认配置更改，通过身份验证记录确认新管理员。

### 9. Attack Success Determination
Attempt: Crafted requests to vulnerable endpoints or protocols. Execution: Generation of unexpected processes, accounts, files, or commands. Impact: Data access, privilege acquisition, persistence, service disruption. Request attempts alone do not confirm a successful compromise. Observing requests targeting the installer does not automatically indicate that reinstallation, site takeover, or code execution succeeded.

### 9. 攻击成功判定
尝试：针对易受攻击端点或协议的精心构造请求。执行：生成意外的进程、账户、文件或命令。影响：数据访问、权限获取、持久化、服务中断。仅有请求尝试并不能确认攻击成功。观察到针对安装程序的请求并不自动意味着重新安装、站点接管或代码执行已成功。

### 10. Investigation Playbook
Verify the version, configuration, patch status, and external reachability. Preserve raw logs, process trees, file metadata, and changes to accounts or credentials. Build a timeline linking crafted requests to code execution and privilege acquisition. Search all assets for lateral movement, data access, and outbound communication. Isolate and update the target, and rotate associated credentials and tokens.

### 10. 调查手册
验证版本、配置、补丁状态和外部可达性。保留原始日志、进程树、文件元数据以及账户或凭据的变更。建立将精心构造的请求与代码执行和权限获取相关联的时间线。搜索所有资产以查找横向移动、数据访问和出站通信。隔离并更新目标，并轮换相关的凭据和令牌。

### 11. Defense and Detection Ideas
Single Event: External access to /core/install.php. Timeline: Correlate anomalous requests with subsequent process or account changes. Hunting: Search across environments for identical IOCs, source IPs, accounts, and file hashes. Priority Action: Update to Drupal 10.6.22, 11.3.22, or 11.4.13. If immediate updating is not possible, block /core/install.php and review settings.php permissions.

### 11. 防御与检测思路
单一事件：对 /core/install.php 的外部访问。时间线：将异常请求与随后的进程或账户变更相关联。狩猎：在整个环境中搜索相同的 IOC、源 IP、账户和文件哈希。优先行动：更新至 Drupal 10.6.22、11.3.22 或 11.4.13。如果无法立即更新，请阻止 /core/install.php 并审查 settings.php 权限。
