2. Quick Summary
Pre-authentication RCE as the worker user has been demonstrated on unpatched NGINX instances with a reachable HTTP/2 listener, originating from a flow-control memory corruption or a use-after-free during proxy processing. Furthermore, researchers showed that container escape and host root privileges can be achieved by chaining this with a separate Linux SCTP vulnerability.

2. 快速摘要
在未打补丁且具有可访问 HTTP/2 监听器的 NGINX 实例上，已演示了以 worker 用户身份进行的预身份验证 RCE，其源于流量控制内存损坏或代理处理期间的释放后使用 (use-after-free) 漏洞。此外，研究人员表明，通过将其与另一个 Linux SCTP 漏洞进行链式攻击，可以实现容器逃逸和主机 root 权限获取。

3. Attack Flow
Attack vectors A, B, D, E, and F are independent. Phase C is a verification path demonstrated by Xint, which chains another Linux SCTP vulnerability after the success of A. The following describes exploitation paths explained by the researchers; it does not indicate observed exploitation in the wild.
Attack Vector A: HTTP/2 RCE via CVE-2026-123007
Send crafted frame sequences to the HTTP/2 handler in affected versions. Trigger out-of-bounds copying and heap corruption due to flow-control calculation inconsistencies. Successful exploitation executes code with NGINX worker privileges.
Attack Vector B: HTTP/2 Proxy RCE via CVE-2026-123633
Send fragmented HEADERS frames to the HTTP/2 proxy in affected versions. Force the release of connection memory currently in use under conditions such as backend connection slot exhaustion. Leverage the use-after-free condition to execute code with NGINX worker privileges upon successful exploitation.
Phase C: Host Root Acquisition via Linux SCTP Vulnerability Following Success of A
Start from the code execution achieved with NGINX worker privileges inside the container. Exploit a separate SCTP vulnerability on an affected kernel reachable via SCTP. Gain control of the host kernel, crossing the container boundary to escalate to host root privileges.
Attack Vector D: HTTP/3 Proxy Path via CVE-2026-121810
Send crafted traffic to affected configurations forwarding to a backend via HTTP/3. Leverage the HTTP/3 use-after-free to execute code with NGINX worker privileges upon successful exploitation.
Attack Vector E: Resolver Path via CVE-2026-123634
Trigger request-driven name resolution and subrequests in affected configurations. Leverage the resolver response handling use-after-free to execute code with NGINX worker privileges upon successful exploitation.
Attack Vector F: Mail Proxy Path via CVE-2026-113425
Send crafted authentication traffic to affected mail proxies using proxy on and auth_http. Leverage the use-after-free to execute code with NGINX worker privileges upon successful exploitation.

3. 攻击流程
攻击向量 A、B、D、E 和 F 是独立的。阶段 C 是由 Xint 演示的验证路径，它在 A 成功后链式利用了另一个 Linux SCTP 漏洞。以下描述了研究人员解释的利用路径；这并不代表在野外观察到的利用情况。
攻击向量 A：通过 CVE-2026-123007 进行 HTTP/2 RCE
向受影响版本中的 HTTP/2 处理程序发送精心构造的帧序列。由于流量控制计算不一致，触发越界复制和堆损坏。成功利用后将以 NGINX worker 权限执行代码。
攻击向量 B：通过 CVE-2026-123633 进行 HTTP/2 代理 RCE
向受影响版本中的 HTTP/2 代理发送分片的 HEADERS 帧。在后端连接槽耗尽等条件下，强制释放当前正在使用的连接内存。利用释放后使用条件，在成功利用后以 NGINX worker 权限执行代码。
阶段 C：在 A 成功后通过 Linux SCTP 漏洞获取主机 Root 权限
从容器内以 NGINX worker 权限实现的代码执行开始。利用可通过 SCTP 访问的受影响内核上的另一个 SCTP 漏洞。获取主机内核控制权，跨越容器边界以提升至主机 root 权限。
攻击向量 D：通过 CVE-2026-121810 的 HTTP/3 代理路径
向通过 HTTP/3 转发到后端的受影响配置发送精心构造的流量。利用 HTTP/3 的释放后使用漏洞，在成功利用后以 NGINX worker 权限执行代码。
攻击向量 E：通过 CVE-2026-123634 的解析器路径
在受影响的配置中触发请求驱动的名称解析和子请求。利用解析器响应处理中的释放后使用漏洞，在成功利用后以 NGINX worker 权限执行代码。
攻击向量 F：通过 CVE-2026-113425 的邮件代理路径
使用 proxy on 和 auth_http 向受影响的邮件代理发送精心构造的身份验证流量。利用释放后使用漏洞，在成功利用后以 NGINX worker 权限执行代码。

4. Attacker Position and Execution Location
The attacker is an unauthenticated remote actor who can reach the HTTP/2 listener. CVE-2026-123633 also requires a backend proxy configuration. Attack vectors D, E, and F involve attackers who can reach the HTTP/3 proxy, resolver path, and mail proxy, respectively.

4. 攻击者位置与执行地点
攻击者是能够访问 HTTP/2 监听器的未经身份验证的远程参与者。CVE-2026-123633 还需要后端代理配置。攻击向量 D、E 和 F 涉及能够分别访问 HTTP/3 代理、解析器路径和邮件代理的攻击者。

5. Victim and Administrator Perspective
May appear as service disruptions, authentication anomalies, configuration tampering, or data access. Administrators correlate requests, processes, files, and account changes along the same timeline.

5. 受害者与管理员视角
可能表现为服务中断、身份验证异常、配置篡改或数据访问。管理员需在同一时间线上关联请求、进程、文件和账户变更。

6. Success and Failure Conditions
Success Conditions
Unpatched NGINX
Reachable HTTP/2 listener
Backend proxy configuration for CVE-2026-123633
Failure/Mitigation Conditions
Open Source stable 1.30.x upgraded to 1.30.7 or later, mainline 1.31.x upgraded to 1.31.9 or later, or Plus fixed versions (37.0.7.1/37.2.0.1 or later for CVE-2026-123633, 37.0.8.1/37.3.0.1 or later for CVE-2026-123007)
Disabling HTTP/2 mitigates the two main vectors
Backported packages provided by vendors
For CVE-2026-123633, in addition to the HTTP/2 proxy, the release of in-progress connections due to reasons such as connection slot exhaustion is involved. The SCTP chain requires an affected kernel and reachability to SCTP; NGINX RCE alone does not grant host root privileges.

6. 成功与失败条件
成功条件
未打补丁的 NGINX
可访问的 HTTP/2 监听器
针对 CVE-2026-123633 的后端代理配置
失败/缓解条件
Open Source 稳定版 1.30.x 升级至 1.30.7 或更高版本，主线版 1.31.x 升级至 1.31.9 或更高版本，或 Plus 修复版本（CVE-2026-123633 为 37.0.7.1/37.2.0.1 或更高，CVE-2026-123007 为 37.0.8.1/37.3.0.1 或更高）
禁用 HTTP/2 可缓解两个主要攻击向量
供应商提供的向后移植补丁包
对于 CVE-2026-123633，除 HTTP/2 代理外，还涉及因连接槽耗尽等原因导致的进行中连接的释放。SCTP 链式攻击需要受影响的内核以及对 SCTP 的可访问性；仅 NGINX RCE 本身不会授予主机 root 权限。

7. What Happens Upon Success
Code execution or DoS with NGINX worker privileges
Access to web content or upstream credentials
Container escape and host root acquisition when chained with another kernel vulnerability

7. 成功后的后果
以 NGINX worker 权限执行代码或导致拒绝服务 (DoS)
访问 Web 内容或上游凭据
与另一个内核漏洞链式利用时，实现容器逃逸和主机 root 权限获取

8. Observable Logs
Worker crashes and restarts associated with HTTP/2 processing
Segmentation faults, heap corruption, and core dumps
Unknown processes, shell spawning, or outbound communications immediately following HTTP/2 sessions
Because HTTP/2 control frames are not logged as requests in standard access logs, the absence of crafted requests in logs does not rule out attack attempts. Worker abnormal terminations and child process generation are general investigation indicators and not IOCs specific to these CVEs.

8. 可观察日志
与 HTTP/2 处理相关的 worker 崩溃和重启
段错误、堆损坏和核心转储
HTTP/2 会话后立即出现的未知进程、shell 生成或出站通信
由于 HTTP/2 控制帧不会作为请求记录在标准访问日志中，因此日志中没有精心构造的请求并不能排除攻击尝试。Worker 异常终止和子进程生成是通用的调查指标，而非针对这些 CVE 的特定入侵指标 (IOC)。

9. Determining Attack Success
Attempt: Crafted requests to vulnerable endpoints or protocols.
Execution: Spawning of unexpected processes, accounts, files, or commands.
Impact: Data access, privilege escalation, persistence, or service disruption.
Attempt logs alone do not confirm successful compromise. For attack vectors D, E, and F, no active exploitation attempts or successful compromises have been confirmed in the wild.

9. 确定攻击是否成功
尝试：向易受攻击的端点或协议发送精心构造的请求。
执行：生成意外的进程、账户、文件或命令。
影响：数据访问、权限提升、持久化或服务中断。
仅凭尝试日志无法确认攻击是否成功。对于攻击向量 D、E 和 F，目前尚未确认在野外有活跃的利用尝试或成功入侵案例。
