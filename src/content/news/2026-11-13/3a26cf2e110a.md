### 3. Attack Flow
**3. 攻击流程**

Cairn Autonomous Orchestration: The operator provides a root domain, objectives, and optionally VPN and credential information. Cairn performs asset mapping and generates a 3 to 7-step plan. The system uses Reason to determine the next action, executes one action via Explore, and adds findings to a blackboard. It iteratively probes for known vulnerabilities, identity and configuration weaknesses, and weak credentials. Depending on the target, successful paths lead to subsequent actions such as authentication, data retrieval, admin account or API token creation, and document modification (reach varies by target).
Cairn自主编排：操作员提供根域名、目标以及可选的VPN和凭据信息。Cairn执行资产映射并生成3到7步的计划。系统使用“推理”来确定下一步行动，通过“探索”执行一个动作，并将发现结果添加到黑板上。它迭代探测已知漏洞、身份和配置弱点以及弱凭据。根据目标的不同，成功的路径会导致后续行动，如身份验证、数据检索、管理员账户或API令牌创建以及文档修改（影响范围因目标而异）。

Authentication Success via Password Attacks: Conducts password spraying or brute-force attacks against public-facing applications using weak passwords. In cases where production credential brute-forcing succeeded, access was established using legitimate accounts. Pre-shared passwords were provided as input for certain targets, though successful use of this input was not reported. Following successful brute-forcing of a production credential on a semiconductor company's partner-integration application, the attackers created unauthorized administrator accounts and a persistent API token.
通过密码攻击实现身份验证成功：使用弱密码对面向公众的应用程序进行密码喷洒或暴力破解攻击。在生产凭据暴力破解成功的情况下，攻击者使用合法账户建立了访问权限。某些目标被提供了预共享密码作为输入，但未报告成功使用该输入的情况。在成功暴力破解某半导体公司合作伙伴集成应用程序的生产凭据后，攻击者创建了未经授权的管理员账户和持久性API令牌。

Access via Unauthenticated Storage and APIs: Accesses unauthenticated, writable cloud storage or exposed cloud APIs. Reads or writes data depending on the target, without acquiring an intermediate session (reach varies by target).
通过未经身份验证的存储和API访问：访问未经身份验证、可写的云存储或暴露的云API。根据目标读取或写入数据，无需获取中间会话（影响范围因目标而异）。

Access via CMS and Registration API Authorization Flaws: The framework exploits account-creation bypasses in CMS platforms, mass-assignment flaws, and authorization flaws in registration APIs. Reports indicate successful acquisition of valid sessions and member information in CMS, as well as exposed user records via identity registration endpoints (reach varies by target).
通过CMS和注册API授权缺陷访问：该框架利用CMS平台中的账户创建绕过、批量赋值缺陷以及注册API中的授权缺陷。报告显示，攻击者成功获取了CMS中的有效会话和成员信息，并通过身份注册端点获取了暴露的用户记录（影响范围因目标而异）。

### 4. Attacker Positioning and Prerequisites
**4. 攻击者定位与先决条件**

Attacker Positioning: A remote attacker capable of reaching internet-facing applications, APIs, and VPNs, potentially holding pre-collected shared credentials. Success Conditions: Presence of known vulnerabilities, authorization flaws, weak credentials, or exposed endpoints in public applications or APIs. Continuous network connectivity from Cairn workers to the target. For authenticated paths, acquired credentials and sessions must successfully reach data or administrative functions. For unauthenticated paths, endpoints must permit direct read or write operations.
攻击者定位：能够访问面向互联网的应用程序、API和VPN的远程攻击者，可能持有预先收集的共享凭据。成功条件：公共应用程序或API中存在已知漏洞、授权缺陷、弱凭据或暴露的端点。Cairn工作节点与目标之间保持持续的网络连接。对于已验证路径，获取的凭据和会话必须成功访问数据或管理功能。对于未经验证的路径，端点必须允许直接读取或写入操作。

Prevention and Failure Conditions: Inventory the attack surface and remediate known CVEs and identity or authorization flaws. Eliminate default and shared passwords, and apply MFA and rate limiting where appropriate (effectiveness depends on the vector). Block unauthorized requests for admin creation, bulk exports, and cloud writes (auditing alone cannot block actions).
预防与失败条件：盘点攻击面并修复已知的CVE以及身份或授权缺陷。消除默认和共享密码，并在适当的情况下应用多因素身份验证（MFA）和速率限制（有效性取决于攻击向量）。阻止未经授权的管理员创建、批量导出和云写入请求（仅靠审计无法阻止这些操作）。

### 5. Visibility for Victims and Administrators
**5. 受害者与管理员的可见性**

Victims: Accounts, records, and documents may be accessed or modified in the background while standard services appear operational. Administrators: Visible as prolonged enumeration, weak-password attempts, arbitrary account creation, bulk reads, admin and token creation, and cloud storage writes.
受害者：账户、记录和文档可能在后台被访问或修改，而标准服务看起来仍在正常运行。管理员：可见的迹象包括长时间的枚举、弱密码尝试、任意账户创建、批量读取、管理员和令牌创建以及云存储写入。
