# Compromised LiteLLM 1.107.0 on PyPI Installs a Credential Stealer and Backdoor

Protect your projects from malicious packages.
保护您的项目免受恶意软件包的侵害。

The LiteLLM 1.107.0 release on PyPI carries a credential stealer and a remote code execution backdoor. All seven wheels (Linux, macOS, Windows) install them as three files in site-packages. Both run when any Python process starts on the host, even one that never imports litellm. The upstream GitHub source does not contain them. PyPI has since removed the release.
PyPI 上的 LiteLLM 1.107.0 版本携带了一个凭据窃取程序和一个远程代码执行后门。所有七个 wheel 包（Linux、macOS、Windows）都会将它们作为三个文件安装到 site-packages 中。无论主机上的 Python 进程是否导入了 litellm，只要该进程启动，这两个恶意程序就会运行。上游 GitHub 源码中并不包含这些文件。PyPI 现已删除了该版本。

Versions 1.106.2, 1.107.0rc1, and 1.107.0rc2 are clean. The companion packages that 1.107.0 pins, litellm-proxy-extras==0.4.110 and litellm-enterprise==0.1.78, are also clean.
1.106.2、1.107.0rc1 和 1.107.0rc2 版本是干净的。1.107.0 所锁定的配套软件包 litellm-proxy-extras==0.4.110 和 litellm-enterprise==0.1.78 也同样是干净的。

Installing litellm==1.107.0 places three files in site-packages. Python loads two of them each time it starts.
安装 litellm==1.107.0 会在 site-packages 中放置三个文件。Python 每次启动时都会加载其中的两个。

The pyproject.toml in the 1.107.0 source distribution (sdist) has one extra line in the maturin build section:
1.107.0 源码分发包（sdist）中的 pyproject.toml 在 maturin 构建部分多出了一行：

The maturin data = "cook" setting copies a cook/ folder into litellm-1.107.0.data/purelib/ in the wheel. pip installs that folder into site-packages.
maturin 的 data = "cook" 设置会将一个 cook/ 文件夹复制到 wheel 包的 litellm-1.107.0.data/purelib/ 中。pip 会将该文件夹安装到 site-packages 中。

The sdist leaves out the cook/ folder, so this line is the only visible change. No public commit in BerriAI/litellm contains data = "cook" or a cook/ folder.
sdist 中并未包含 cook/ 文件夹，因此这一行是唯一可见的改动。BerriAI/litellm 的任何公开提交中都不包含 data = "cook" 或 cook/ 文件夹。

SafeDep assesses, with moderate to high confidence, that BerriAI’s private release pipeline built these wheels from an attacker-modified git source. The attacker could have used a compromised maintainer or bot credential, a private branch or mirror, or the reference the pipeline builds from. A stolen PyPI token used from the attacker’s own machines fits the evidence less well. Only BerriAI’s pipeline logs can confirm the cause.
SafeDep 以中等到较高的置信度评估认为，BerriAI 的私有发布流水线是基于攻击者修改过的 git 源码构建了这些 wheel 包。攻击者可能使用了被入侵的维护者或机器人凭据、私有分支或镜像，或者是流水线所构建的引用。从攻击者自己的机器上使用被盗的 PyPI 令牌这一假设与证据不太吻合。只有 BerriAI 的流水线日志才能确认原因。

The attacker can point the daemon at a new server by editing domain.txt. Each infected host runs whatever that server returns as codepy.
攻击者可以通过编辑 domain.txt 将守护进程指向新的服务器。每个受感染的主机都会运行该服务器返回的任何 codepy 代码。

At 13:40 UTC, the GitHub account letters9813 and its repository returned 404, about two hours after the release. The backdoor now finds no server address and does nothing. Hosts that ran the daemon before the deletion could have received and run second-stage code. SafeDep could not recover the server address.
UTC 时间 13:40，即发布约两小时后，GitHub 账户 letters9813 及其存储库返回了 404 错误。后门现在找不到服务器地址，因此不再执行任何操作。在删除之前运行过该守护进程的主机可能已经接收并运行了第二阶段代码。SafeDep 无法恢复该服务器地址。
