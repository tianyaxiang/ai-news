CVE-2026-107891: musl libc: multiple integer overflow in regcomp, possibly leading to incorrect allocation sizes and out-of-bounds heap writes Overview: The regcomp function in musl libc is affected by multiple integer overflow issues which can lead to incorrectly-sized allocations and possibly out-of-bounds heap writes. The conditions for overflow are triggered by the size and complexity of the regular expression passed to regcomp, not the data to be matched. In order to be vulnerable, an application must be processing regular expressions from an untrusted source using the libc regcomp function.

CVE-2026-107891：musl libc：regcomp 中存在多个整数溢出，可能导致分配大小错误及堆内存越界写入。概述：musl libc 中的 regcomp 函数受到多个整数溢出问题的影响，这可能导致分配大小错误，并可能引发堆内存越界写入。溢出条件是由传递给 regcomp 的正则表达式的大小和复杂性触发的，而非由待匹配的数据触发。要受到此漏洞影响，应用程序必须使用 libc 的 regcomp 函数处理来自不可信来源的正则表达式。

Impact: At least denial-of-service in the form of a predictable crash is possible. Depending on the application and its use of objects on the heap and of concurrent execution, arbitrary code execution may be possible. Affected versions: The vulnerable code has been present since version 0.5.0. All subsequent versions up through 1.2.6 are affected.

影响：至少可能导致可预测的崩溃，从而引发拒绝服务。根据应用程序及其对堆上对象的使用情况以及并发执行情况，可能实现任意代码执行。受影响版本：该漏洞代码自 0.5.0 版本起便已存在。截至 1.2.6 版本的所有后续版本均受影响。

Mitigation: All users should apply the attached patch, or upgrade to 1.2.7 once it becomes available. In contexts where patching is not an option, measures should be taken to prevent the processing of regular expressions from untrusted sources. Credits: The first of these issues was reported in private by Julien Voisin. Subsequent analysis by Szabolcs Nagy and Rich Felker found a pattern of similar overflows.
