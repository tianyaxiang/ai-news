### The Future of CSS

For the past few years, all of the major browser vendors (Google, Apple, Microsoft, and Mozilla, along with Igalia and Bocoup) have been working together on Interop, a project to improve universal browser support on web technologies. It’s been a remarkably successful effort; when a focus area gets added to Interop, it often winds up reaching near-100% support across all major browsers within a year. ✨

在过去的几年里，所有主要的浏览器厂商（Google、Apple、Microsoft 和 Mozilla，以及 Igalia 和 Bocoup）一直在合作开展 Interop 项目，旨在改善对 Web 技术的通用浏览器支持。这是一项非常成功的举措；当一个重点领域被加入 Interop 后，它通常会在一年内就在所有主流浏览器中实现近乎 100% 的支持。✨

CSS Subgrid is a good example. Subgrid is a super-powerful extension to CSS Grid which enables entirely new layouts. It was implemented in Firefox back in 2019, but there wasn’t much movement with other browsers for years. It got added to Interop 2023, and by the end of that year, it was widely available across all modern browsers.

CSS Subgrid 就是一个很好的例子。Subgrid 是 CSS Grid 的一个超强扩展，它实现了全新的布局方式。它早在 2019 年就在 Firefox 中实现了，但多年来在其他浏览器中进展缓慢。它在 2023 年被加入 Interop，到那年年底，它已在所有现代浏览器中得到广泛支持。

As we reach the end of 2026, Interop 2027 is currently being planned, and the team at Mozilla has created a ranking system for us to upvote our most-requested features. They plan on using the ranking data to decide what to include for next year’s Interop!

随着 2026 年接近尾声，Interop 2027 目前正在规划中，Mozilla 团队创建了一个排名系统，供我们投票选出最需要的功能。他们计划利用这些排名数据来决定明年 Interop 的包含内容！

In this blog post, I want to dig into the top 10 features I voted for, to offer a bit of a preview of what CSS might look like within the next year. There will also be some little tips and tricks you can start using today!

在这篇博文中，我想深入探讨我投票选出的前 10 大功能，为大家预览一下明年 CSS 的样子。文中还会包含一些你现在就可以开始使用的小技巧！

In CSS, we can use the border-radius property to round off the edges of our DOM nodes to create rounded rectangles. This property effectively adds a quarter-circle to each corner, connecting the 4 straight sides.

在 CSS 中，我们可以使用 `border-radius` 属性来圆化 DOM 节点的边缘，从而创建圆角矩形。该属性实际上是在每个角添加了一个四分之一圆，连接起 4 条直线边。

I recently published a blog post on Anchor Positioning, one of the most exciting modern CSS features (which was actually prioritized in Interop 2026, and is now widely available!).

我最近发表了一篇关于锚点定位（Anchor Positioning）的博文，这是最令人兴奋的现代 CSS 功能之一（它实际上在 Interop 2026 中被优先考虑，现在已广泛可用！）。

The Anchor Positioning API allows us to anchor one element to another. For example, we might anchor a floating tooltip element to its trigger, so that no matter where that trigger is on the page, the tooltip will always be connected to it.

锚点定位 API 允许我们将一个元素锚定到另一个元素上。例如，我们可以将浮动工具提示元素锚定到其触发器上，这样无论触发器在页面上的什么位置，工具提示都将始终与其连接。

If you’ve ever tried to solve this sort of problem yourself, you know it’s surprisingly tricky. For example, we might want our tooltip to float above the anchor, but what if the anchor is near the top of the viewport?

如果你曾经尝试过自己解决这类问题，你就会知道这出奇地棘手。例如，我们可能希望工具提示浮动在锚点上方，但如果锚点靠近视口顶部怎么办？

The tooltip fits comfortably.

工具提示可以舒适地放置。

The tooltip’s getting cut off!

工具提示被截断了！

The original Anchor Positioning API gave us most of the tools needed to solve this problem easily in CSS. It allows us to specify fallback positions; if the target element doesn’t fit above the anchor, it can flip automatically to the bottom.

最初的锚点定位 API 为我们提供了在 CSS 中轻松解决此问题所需的大部分工具。它允许我们指定回退位置；如果目标元素无法放置在锚点上方，它可以自动翻转到底部。

The only thing missing was the ability to tell whether or not the target had flipped. We had no way to know, in CSS, whether the target element is currently sitting above or below the anchor, whether it’s using the default or fallback position. For tooltips, this is a problem because we typically want to add a little protrusion that points towards the anchor.

唯一缺少的是判断目标是否已经翻转的能力。在 CSS 中，我们无法知道目标元素当前是位于锚点上方还是下方，也无法知道它使用的是默认位置还是回退位置。对于工具提示来说，这是一个问题，因为我们通常希望添加一个指向锚点的小突起。

The “Level 2” version of the Anchor Positioning API includes a new type of container query that allows us to check whether the target element is using a fallback position or not. You can learn more about it in my Anchor Positioning blog post, or check out the Interop 2027 proposal.

锚点定位 API 的“Level 2”版本包含一种新型容器查询，允许我们检查目标元素是否正在使用回退位置。你可以在我的锚点定位博文中了解更多信息，或者查看 Interop 2027 提案。

So honestly, I had never heard of this proposal, and as far as I can tell, it isn’t implemented in any browsers. It’s not even listed on caniuse.

老实说，我以前从未听说过这个提案，据我所知，它在任何浏览器中都没有实现。它甚至没有在 caniuse 上列出。
