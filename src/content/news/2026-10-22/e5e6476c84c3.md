This document is a style guide for the usage of the Rust programming language at Google. In this context, “style” refers to more than just formatting; it includes guidance on API and implementation design. Rust is used in many places, including google3, Android, ChromeOS, Fuchsia, and Chrome, and we’d like for Rust usage at Google to be consistent both within and across codebases. In addition to bringing consistency to our Rust code, style guidance also helps establish a standard of quality.

Goals of the style guide By and large, we have this document for the same reasons we have a C++ style guide. Most style rules come from one or more of the goals listed below. Style rules should prioritize readability and maintainability over writeability We expect our code to be around for long periods of time, and we consider a little bit of extra effort applied during code writing to be worth it in the long run if the style rule improves readability. Style rules should favor better automation Large-Scale Changes (LSCs) are common at Google, and consistency helps make LSCs easier to carry out. Style rules should be consistent with the wider Rust ecosystem where possible The broader Rust ecosystem already has a pretty good amount of consistency in style, and we should rely on that where possible to reduce surprise and make it less work to learn Google’s Rust style. Style rules should pull their weight Every Rust developer and reviewer at Google has to keep these style rules in mind: as such, we should be careful to include rules that have a tangible benefit. Style rules may help avoid minor style disagreements There are many cases where reasonable people may disagree about a style, and we expect that disagreement to show up often on CLs. Having a style rule helps avoid having to rehash this each time. Rules in this category that do not have other benefits should be kept to a minimum.

风格指南的目标：我们制定这份文档的原因与制定 C++ 风格指南的原因大致相同。大多数风格规则源于以下一个或多个目标：风格规则应优先考虑可读性和可维护性而非编写速度；风格规则应有利于自动化，一致性有助于简化 Google 常见的大规模变更（LSC）；风格规则应尽可能与更广泛的 Rust 生态系统保持一致，以减少学习成本；风格规则应具有实际价值，确保每条规则都能带来切实的好处；风格规则有助于避免琐碎的风格争议，通过预先设定规则，减少在代码审查（CL）中反复讨论风格问题的必要。

Follow public Rust style rules Follow the official public Rust style rules to the extent they don’t conflict with this style guide. Rust Style Guide Most code formatting conventions are enforced automatically by rustfmt. Rust API Guidelines A “conflict” would be a case where this style guide suggests a pattern that is discouraged, or counter to the primary encouraged pattern in the Rust style guide. Why does the guidance in this style guide deviate from regular Rust style rules? Most style guides have three goals: consistency, readability, and encouraging good API design. Regardless of the specific choices made, it helps everyone to have these choices made beforehand to limit bikeshedding. This style guide shares those goals, but it also has an additional goal not seen as often: smoothing the way for Large-Scale Changes (LSCs).
