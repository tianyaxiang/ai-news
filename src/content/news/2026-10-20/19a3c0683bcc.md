[prev in list] [next in list] [prev in thread] [next in thread] 列表：openbsd-ports 主题：emulators/wine 发件人：Thomas Frohwein <tfrohwein () fastmail ! com> 日期：2026-10-18 22:08:43 消息ID：20261018150843.271e0c06 () babcom6 ! home ! arpa [下载原始消息或正文] 大家好，我很高兴能为大家带来一个新的 Wine 移植版本，这可能是今年最令人惊讶的移植提案。

This has been a collective effort, after some of the prodding at the %gs/gsbase question (see thread [1]). The gates swung open with Andrii's software solution to the %gs issue - explanation to me: "can't set gsbase, so we are emulating %gs prefix on commands". Overall, the heavy lifting was done by Andrii and Fabien - kudos.

这是集体努力的成果，此前我们针对 %gs/gsbase 问题进行了一些探讨（见线程 [1]）。随着 Andrii 针对 %gs 问题提出的软件解决方案，大门终于敞开了——他向我解释道：“无法设置 gsbase，所以我们正在模拟指令上的 %gs 前缀”。总的来说，繁重的工作是由 Andrii 和 Fabien 完成的，向他们致敬。

Turns out there is a ground-swell with interest in wine [2], different than even 5-10 years ago because a lot of Windows software has since moved to being 64bit. We have since tested several dozens of 64-bit Windows software, mostly successfully. See screenshots at [3][4][5], livestream recordings at [6] for example.

事实证明，人们对 Wine 的兴趣正在高涨 [2]，这与 5-10 年前有所不同，因为许多 Windows 软件现在已经转向 64 位。我们已经测试了几十款 64 位 Windows 软件，大部分都成功运行了。例如，请参阅 [3][4][5] 处的截图和 [6] 处的直播录像。

Even the Remaster of The Witcher 3 which released just last month runs, and runs well (requires adding in vkd3d-proton; see README; livestream at [7] which looks less fluent than it is due to the on-system recording with ffmpeg). Biggest limitation is that WoW64 doesn't work, so 32bit Windows software is still a no-op. You can check .exe/.dll easily with file(1) - if it says something like "MS-DOS executable PE for MS Windows (GUI) Intel 80386 32-bit", then it's 32-bit.

甚至上个月刚发布的《巫师 3》重制版也能运行，而且运行良好（需要添加 vkd3d-proton；请参阅 README；[7] 处的直播看起来不够流畅，这是因为使用了 ffmpeg 进行系统内录制）。最大的限制是 WoW64 无法工作，因此 32 位 Windows 软件仍然无法运行。你可以使用 file(1) 轻松检查 .exe/.dll 文件——如果它显示类似“MS-DOS executable PE for MS Windows (GUI) Intel 80386 32-bit”的内容，那么它就是 32 位的。

The builtin-tests are disabled for now. Enabling them is pretty involved as they need access to the X server and multiple tests still hang, however that was not observed in the real life testing with a good number of games. This is still being worked on. For those who wish to test it, I suggest Notepad++ as a small, fairly straightforward piece of 64-bit Windows software [8].

内置测试目前已禁用。启用它们非常复杂，因为它们需要访问 X 服务器，而且多个测试仍然会挂起，不过在对大量游戏进行的实际测试中并未观察到这种情况。目前相关工作仍在进行中。对于那些希望进行测试的人，我建议使用 Notepad++，这是一个小巧且相当直接的 64 位 Windows 软件 [8]。

Note that this is (as always) run-at-your-own-risk software (see [9]). Consider setting up a separate, non-privileged user for this until we can explore if some fencing in, potentially with unveil(2) can be done. Appreciate testing of the port draft and contributions by: brynet@, bentley@, pertho (on irc.libera.chat #openbsd-gaming), vl_ms ok?

请注意，这（一如既往）是风险自负的软件（见 [9]）。在我们可以探索是否可以通过 unveil(2) 等方式进行隔离之前，请考虑为此设置一个单独的非特权用户。感谢 brynet@、bentley@、pertho（在 irc.libera.chat #openbsd-gaming 上）、vl_ms 对移植草案的测试和贡献，可以吗？
