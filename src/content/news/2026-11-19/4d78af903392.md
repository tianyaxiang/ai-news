### Executive Summary

Wiz Research, Ikotas Labs, Metnir, Rapid7, and Xint independently uncovered two critical remote code execution vulnerabilities in NGINX, software used to receive and route traffic to production applications and APIs. NGINX is a common default for the front door of modern web architectures, where it handles HTTPS and routes incoming traffic to the right application or API. As the world's most widely used open-source web server, it powers more than 225 million websites.

Wiz Research、Ikotas Labs、Metnir、Rapid7 和 Xint 独立发现了 NGINX 中的两个严重远程代码执行漏洞。NGINX 是一款用于接收和路由生产应用程序及 API 流量的软件，也是现代 Web 架构前端的常用默认配置，负责处理 HTTPS 并将传入流量路由至正确的应用程序或 API。作为全球使用最广泛的开源 Web 服务器，它为超过 2.25 亿个网站提供支持。

Successful exploitation could let attackers take control of affected NGINX servers, steal sensitive data, tamper with websites, or disrupt services. The vulnerabilities, tracked as CVE-2026-123633 and CVE-2026-123007, are both rated Critical, with a CVSS 4.0 score of 9.2. The flaws are in NGINX itself. Websites and APIs can be exposed even when their own application code is secure. Both vulnerabilities require HTTP/2 to be enabled on the affected NGINX server. Additional conditions are described below. CVE-2026-123007 affects versions dating back to NGINX 1.9.5 in 2015.

成功利用这些漏洞可能使攻击者能够控制受影响的 NGINX 服务器、窃取敏感数据、篡改网站或中断服务。这些漏洞被追踪为 CVE-2026-123633 和 CVE-2026-123007，均被评为“严重”级别，CVSS 4.0 评分为 9.2。缺陷存在于 NGINX 本身，即使网站和 API 的应用程序代码是安全的，它们也可能面临风险。这两个漏洞都需要在受影响的 NGINX 服务器上启用 HTTP/2。其他条件详见下文。CVE-2026-123007 影响自 2015 年 NGINX 1.9.5 版本以来的多个版本。

We reported our findings to F5, the company behind NGINX, and collaborated with its security team on remediation and coordinated disclosure. Organizations should identify affected deployments and apply the security updates when released. We recommend updating affected NGINX deployments to the latest release which includes multiple security fixes.

### Overview

Wiz Research, Ikotas Labs, Metnir, Rapid7, and Xint independently uncovered CVE-2026-123633 and CVE-2026-123007, two critical unauthenticated remote code execution vulnerabilities in NGINX, and reported them to F5, the company behind NGINX. Successful exploitation can compromise the server running NGINX, allowing attackers to execute code, steal sensitive data, tamper with websites, or disrupt services. NGINX often handles traffic for several applications, so a single affected deployment can put multiple services at risk.

### 概述

Wiz Research、Ikotas Labs、Metnir、Rapid7 和 Xint 独立发现了 CVE-2026-123633 和 CVE-2026-123007，这是 NGINX 中两个严重的未经身份验证的远程代码执行漏洞，并将其报告给了 NGINX 背后的公司 F5。成功利用这些漏洞可以攻破运行 NGINX 的服务器，使攻击者能够执行代码、窃取敏感数据、篡改网站或中断服务。NGINX 通常处理多个应用程序的流量，因此单个受影响的部署可能会使多个服务面临风险。

The flaws are in NGINX itself and can affect websites even when their own application code is secure. Both vulnerabilities require HTTP/2 to be enabled on the affected NGINX server. Our testing of CVE-2026-123007 demonstrated code execution on NGINX serving ordinary static files, without a backend application or third-party modules. Wiz Research used Wiz Atlas, the harness powering Wiz’s AI Code scanning solution, to discover both vulnerabilities. Our researchers used Gemini 4 Carbon and ChatGPT 5.6 Sol to validate the impact of both vulnerabilities, confirming that each could allow an unauthenticated attacker to execute code on the server.

这些缺陷存在于 NGINX 本身，即使网站自身的应用程序代码是安全的，它们也可能受到影响。这两个漏洞都需要在受影响的 NGINX 服务器上启用 HTTP/2。我们对 CVE-2026-123007 的测试表明，在没有后端应用程序或第三方模块的情况下，仅提供普通静态文件的 NGINX 也能被执行代码。Wiz Research 使用了 Wiz Atlas（驱动 Wiz AI 代码扫描解决方案的工具）发现了这两个漏洞。我们的研究人员使用 Gemini 4 Carbon 和 ChatGPT 5.6 Sol 验证了这两个漏洞的影响，确认每个漏洞都允许未经身份验证的攻击者在服务器上执行代码。
