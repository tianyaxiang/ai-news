# DaisyRose-27B: Pushing the Frontier of Post-Training Efficiency

Back to Articles DaisyRose-27B: Pushing the Frontier of Post-Training Efficiency Team Article Published November 18, 2026 Upvote 8 +2 Jason Chen jzsc Follow RadixArk Today we are releasing DaisyRose-27B, RadixArk’s first model, built on Qwen3.8-27B and trained with reinforcement learning using Miles. We trained it on long-horizon agent tasks with sessions up to 1M tokens, with just 1,200 curated tasks in 18 days on 144 H200 GPUs.

DaisyRose-27B improves Terminal-Bench 4.1 pass@1 from 5.6% to 12.0%. Beyond Terminal-Bench 4.1, it also delivers gains on a variety of other reasoning, instruction following, and coding benchmarks. The checkpoints are available under Apache 2.0: BF16 FP8 NVFP4 The model retains Qwen3.8-27B’s architecture, tokenizer, chat template, image understanding, and 256K-token context window. The longer training sessions use harness summarization to span multiple trajectories. See the model card for model properties and inference settings.

DaisyRose-27B 将 Terminal-Bench 4.1 的 pass@1 从 5.6% 提升至 12.0%。除了 Terminal-Bench 4.1，它在其他各种推理、指令遵循和编码基准测试中也取得了进展。检查点以 Apache 2.0 协议提供：BF16、FP8、NVFP4。该模型保留了 Qwen3.8-27B 的架构、分词器、聊天模板、图像理解能力和 256K token 的上下文窗口。更长的训练会话使用 harness 摘要来跨越多个轨迹。有关模型属性和推理设置，请参阅模型卡。

Three parts of the training setup made this release possible: carefully designed tasks, an efficient training backend, and reliable sandboxes. High-quality training data We built the tasks in partnership with Eigent AI, starting from its large pool of tasks in machine learning, software engineering, science, and other fields. Together we built thousands of candidates. About 1,200 made it into the final training set. We selected tasks using three criteria: Each task targets a mistake the original model makes. We ran Qwen3.8-27B on every task and redesigned each one around the mistakes we wanted the model to stop making.

训练设置的三个部分使此次发布成为可能：精心设计的任务、高效的训练后端以及可靠的沙箱。高质量训练数据方面，我们与 Eigent AI 合作构建了这些任务，从其在机器学习、软件工程、科学及其他领域的大量任务池中筛选。我们共同构建了数千个候选任务，其中约 1,200 个进入了最终训练集。我们使用三个标准来选择任务：每个任务都针对原始模型所犯的错误。我们在每个任务上运行了 Qwen3.8-27B，并围绕我们希望模型停止犯的错误重新设计了每一个任务。

We then adjusted the difficulty until the solve rate fell within a useful learning range. Each task requires several interdependent steps. The agent has to reason, plan, and execute across a long job. Each attempt gets up to 1.5 hours in a sandbox, with more than 100 tool calls and more than 256K output tokens. Tasks must reward actually solving the problem. We reviewed every task alongside the model’s attempts. Tasks that could be passed without solving the intended problem, or that contained a design flaw, were fixed or removed.

随后，我们调整了难度，直到解决率处于有效的学习范围内。每个任务都需要几个相互依赖的步骤。智能体必须在长任务中进行推理、规划和执行。每次尝试在沙箱中最多可获得 1.5 小时的时间，包含超过 100 次工具调用和超过 256K 的输出 token。任务必须奖励真正解决问题的行为。我们审查了每一个任务以及模型的尝试。那些无需解决预期问题即可通过的任务，或包含设计缺陷的任务，都被修复或移除。

Efficient training backend RadixArk trained DaisyRose-27B with Miles, our open-source reinforcement learning framework for large-scale model post-training, in fully asynchronous mode: the agent keeps working while the model learns, and neither waits for the other. While 128 H200s run the inference on agent tasks, 16 more run the trainer and learn from the trajectories. After every step, the updated model goes out to the 128 GPUs that run the agent. The learning runs on our internal training backend, which is built for agent training: each step learns from a handful of very long sessions, some as long as 1M tokens, folded into multiple trajectories via harness summarization.

高效训练后端方面，RadixArk 使用 Miles（我们用于大规模模型后训练的开源强化学习框架）以完全异步模式训练了 DaisyRose-27B：智能体在模型学习时持续工作，两者互不等待。当 128 块 H200 GPU 在智能体任务上运行推理时，另外 16 块运行训练器并从轨迹中学习。每一步之后，更新后的模型都会发送到运行智能体的 128 块 GPU 上。学习过程在我们为智能体训练构建的内部训练后端上运行：每一步都从少数几个非常长的会话中学习，有些长达 100 万 token，并通过 harness 摘要折叠成多个轨迹。

57% lower training cost. On this release, 37% of each GPU’s peak compute went into useful training work (model FLOPs utilization, or MFU) on our backend. The open-source trainer, built on Megatron, reached 16% on comparable runs. So the same training needs 57% less GPU time. The gain is even larger on mixture-of-experts models: 6.2× on Qwen3.6-35B-A3B, and more than 10× on the roughly 300B-parameter GLM-5.3-Flash. 2× faster end to end. Counting the time the agent spends on its tasks, the release run trained on about 16,800 tokens per second across its 144 GPUs. The open-source trainer reached about 8,300 on the same GPUs.

训练成本降低 57%。在此次发布中，我们后端上每块 GPU 的峰值计算能力有 37% 用于有效的训练工作（模型 FLOPs 利用率，即 MFU）。基于 Megatron 构建的开源训练器在同类运行中仅达到 16%。因此，同样的训练所需的 GPU 时间减少了 57%。在混合专家模型上的增益更大：在 Qwen3.6-35B-A3B 上提升了 6.2 倍，在约 300B 参数的 GLM-5.3-Flash 上提升了超过 10 倍。端到端速度提升 2 倍。计算智能体在任务上花费的时间，此次发布运行在 144 块 GPU 上以每秒约 16,800 个 token 的速度进行训练。而开源训练器在相同的 GPU 上仅达到约 8,300 个 token。

Stable over weeks. The release run trained for weeks on 144 H200s, 63,000 GPU-hours in total. From the first step to the last, its speed and efficiency held steady. Robust sandbox service Every training attempt runs in a sandbox: a fresh copy of the task’s environment where the agent runs commands, edits files, and is then graded. Our service is built on the open-source AgentENV project, to which we also contribute fixes.

数周内保持稳定。此次发布运行在 144 块 H200 上进行了数周的训练，总计 63,000 个 GPU 小时。从第一步到最后一步，其速度和效率保持稳定。DaisyRose-27B 发布运行在 144 块 H200 上的每个训练步骤与总训练时间的对比图。虚线表示同类运行中的开源训练器。强大的沙箱服务方面，每次训练尝试都在沙箱中运行：这是任务环境的一个全新副本，智能体在其中运行命令、编辑文件，然后进行评分。我们的服务基于开源的 AgentENV 项目构建，我们也为其贡献了修复程序。

Between mid-September and mid-November, it ran about 944,000 sandboxes for this project, with up to 1,566 running concurrently. The service grew from one machine to as many as 12. We shipped ten upgrades to it, nearly all while training was running. Across all nine weeks, 99% of sandbox creations succeeded; since late October, that figure has exceeded 99.95%. 在 9 月中旬至 11 月中旬期间，该项目运行了约 944,000 个沙箱，最多有 1,566 个并发运行。该服务从一台机器扩展到多达 12 台。我们为其发布了十次升级，几乎都是在训练进行时完成的。在全部九周内，99% 的沙箱创建成功；自 10 月下旬以来，这一数字已超过 99.95%。该项目沙箱的云基础设施成本大约降低了 80%。
