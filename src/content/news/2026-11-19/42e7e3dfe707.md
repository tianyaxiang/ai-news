Microsoft’s Ignite announcements this week went beyond the Office-in-Copilot overhaul with the reveal of the Windows Server 2028 Public Preview and its new security-by-default stance and what Microsoft calls Hardened Server Core.

微软本周在 Ignite 大会上发布的公告不仅限于 Office-in-Copilot 的全面改革，还揭示了 Windows Server 2028 公共预览版，以及其全新的“默认安全”立场和微软所谓的“强化服务器核心”（Hardened Server Core）。

Windows Server 2028 will implement a default security framework that Microsoft says is aligned with hardened DoD benchmarks, such as the Defense Information Systems Agency’s (DISA) Security Technical Implementation Guide (STIG). STIGs work by providing a standard security framework for system administrators to follow recommended guidance.

Windows Server 2028 将实施一套默认的安全框架，微软称该框架与美国国防部（DoD）的强化基准保持一致，例如国防信息系统局（DISA）的安全技术实施指南（STIG）。STIG 通过提供标准的安全框架，供系统管理员遵循推荐的指导方针。

In the past, Windows Server admins were left to start from a blank canvas and then implement hardening configurations for operations. Secure baselines were available but not the default. Microsoft says that concern is now managed: “The secure configuration is the starting state, not a project you run after setup. That closes the window where a newly deployed server sits exposed while it waits to be hardened.”

过去，Windows Server 管理员必须从零开始，然后为操作实施强化配置。虽然当时已有安全基准，但并非默认设置。微软表示，这一问题现已得到解决：“安全配置是初始状态，而不是安装后才运行的项目。这消除了新部署的服务器在等待强化期间处于暴露状态的窗口期。”

The new Windows Server 2028 hardened-by-default state will only be available for the Server Core installs. Windows Server Desktop Experience installs do not include the changed stance. This isn’t to say that system administrators won’t still have the final say on which security protocols are activated, just that the default package now ships in a pre-hardened state.

Windows Server 2028 的这种默认强化状态仅适用于 Server Core 安装。Windows Server 桌面体验版安装不包含此项变更。这并不是说系统管理员不能决定激活哪些安全协议，只是默认软件包现在以预强化状态发布。

Kerberos is now the default over NTLM, with protections added to LSASS; TLS is automatically restricted to modern cipher suites; key exchange uses “hybrid post-quantum key exchange” based on the quantum-safe ML-KEM; and remote desktop authentication and PowerShell script block logging get stricter as well.

Kerberos 现在取代 NTLM 成为默认协议，并增加了对 LSASS 的保护；TLS 自动限制为现代密码套件；密钥交换使用基于量子安全 ML-KEM 的“混合后量子密钥交换”；远程桌面身份验证和 PowerShell 脚本块日志记录也变得更加严格。

Microsoft’s native NVMe storage stack was originally introduced via an update to Windows Server 2025, but it required administrators to enable it manually. The update eliminated NVMe translation through a SCSI stack while improving speeds and reducing overhead. The redesigned stack will now be default-on in Windows Server 2028.

微软的原生 NVMe 存储堆栈最初是通过 Windows Server 2025 的更新引入的，但需要管理员手动启用。该更新消除了通过 SCSI 堆栈进行的 NVMe 转换，同时提高了速度并降低了开销。重新设计的堆栈现在将在 Windows Server 2028 中默认开启。

Microsoft is upfront, noting that the new hardened security settings may break things due to software compatibility issues with older protocols, legacy authentication, or management tools and scripts. The company encourages users to try things and provide feedback about what goes wrong.

微软坦言，由于与旧协议、传统身份验证或管理工具和脚本的软件兼容性问题，新的强化安全设置可能会导致故障。该公司鼓励用户进行尝试，并反馈出现的问题。

“We want to hear where a hardened default gets in the way of a real workload: which setting, which application, and what you had to change to get it working,” the Windows Server Team said in a blog post. “That is how the defaults get better before general availability.”

“我们希望了解默认强化设置在哪些实际工作负载中造成了阻碍：具体是哪个设置、哪个应用程序，以及您必须做出什么更改才能使其正常工作，”Windows Server 团队在博客文章中表示。“这就是在正式发布前改进默认设置的方法。”

Microsoft suggests that users use the preview build as a test bed to determine where issues like compatibility still arise. This is not a release candidate build and shouldn’t be treated as such. Despite the new security stance that comes with the preview build, hardware-backed protections like Secure Boot and DMA requirements won’t be enforced until a later preview build.

微软建议用户将预览版作为测试平台，以确定兼容性等问题在何处仍然存在。这不是发布候选版本，不应将其视为候选版本。尽管预览版采用了新的安全立场，但安全启动（Secure Boot）和 DMA 要求等硬件支持的保护措施要到以后的预览版中才会强制执行。

Kerberos is now the default preference over NTLM, but NTLM blocking itself will still have to wait for a later preview release. Beyond those limitations, the current build has a known issue that cuts into its hardened goals. According to the release notes, “A race condition in the TLS hybrid key exchange implementation may cause the LSASS service to crash when hybrid groups are negotiated by a TLS server.”

Kerberos 现在是优于 NTLM 的默认首选项，但 NTLM 的拦截功能仍需等待后续的预览版本。除了这些限制外，当前版本还存在一个影响其强化目标的问题。根据发行说明，“TLS 混合密钥交换实现中的竞争条件可能导致 LSASS 服务在 TLS 服务器协商混合组时崩溃。”

Microsoft recommends disabling hybrid-key exchange groups until the problem is addressed. System administrators and curious homelabbers interested in testing the new Windows Server 2028 can do so by registering with the Microsoft Windows Insider Program.

微软建议在问题解决之前禁用混合密钥交换组。有兴趣测试新版 Windows Server 2028 的系统管理员和好奇的家庭实验室用户可以通过注册 Microsoft Windows Insider 项目来进行测试。
