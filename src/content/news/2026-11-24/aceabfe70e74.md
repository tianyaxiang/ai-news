When I started building multi-agent demos, my first instinct was to connect the agents to one another. If one specialist found something useful, surely it should message the next specialist. Then I pictured debugging that conversation after an agent summarized the evidence incorrectly. For two separate hackathon projects—one in AI-platform security and one in fraud and AML—I explored a different idea: give the specialists a shared, typed case board. Let each agent add evidence-backed work to the board. Keep verification and consequential decisions outside the agents. The pattern is called a blackboard architecture. GraphQL is one way to expose the board as a typed API. The important point is not that GraphQL makes agents intelligent. It gives the application a defined place to store, read, and authorize shared work.

当我开始构建多智能体演示时，我的第一直觉是将智能体相互连接。如果一位专家发现了有用的东西，它肯定应该通知下一位专家。随后，我设想了在智能体错误地总结证据后调试该对话的场景。针对两个独立的黑客马拉松项目——一个关于人工智能平台安全，另一个关于欺诈和反洗钱（AML）——我探索了一个不同的想法：为专家们提供一个共享的、类型化的案例板。让每个智能体将有证据支持的工作添加到板上。将验证和后续决策保留在智能体之外。这种模式被称为黑板架构。GraphQL 是将该板作为类型化 API 公开的一种方式。重点不在于 GraphQL 让智能体变得智能，而在于它为应用程序提供了一个定义明确的地方来存储、读取和授权共享工作。

Start with a case, not a conversation Imagine a security alert that needs identity context, network context, and change history. A conversation-based design might ask one model to call each specialist, pass summaries between them, and decide when enough has been said. That can be a reasonable design. It also makes the coordinator a central dependency: it chooses the order, carries the context, and can distort a finding as it relays it. With a blackboard, each specialist receives a bounded task and posts a structured result to shared state. Other components can read the result from the board without relying on a private agent-to-agent conversation. The durable work-delivery path is separate from best-effort notifications to the analyst interface.

从案例开始，而不是从对话开始。想象一个需要身份上下文、网络上下文和变更历史的安全警报。基于对话的设计可能会要求一个模型调用每位专家，在他们之间传递摘要，并决定何时讨论已足够。这可能是一个合理的设计。但它也使协调者成为一个核心依赖项：它选择顺序、携带上下文，并可能在传递过程中扭曲发现结果。使用黑板，每位专家接收一个有界任务，并将结构化结果发布到共享状态。其他组件可以从板上读取结果，而无需依赖私有的智能体间对话。持久的工作交付路径与发送给分析师界面的尽力而为通知是分开的。

What the board actually contains A useful board is more than a place to paste chat messages. It needs a small vocabulary that the application can validate: the case and its current revision; typed findings and claims; references to the records an agent used; the verifier’s verdict; any proposed action and the human decision history. For example, a claim might say that a runner is not registered and cite a runner inventory record. The board stores that as data, not as a paragraph that a second model must interpret. The verifier can then check whether the record exists, is in scope for this case, and supports the claimed value. GraphQL helps express that contract: queries can expose the case and its claims, mutations can constrain how claims are posted, and subscriptions can notify a user interface that the case changed.

黑板实际上包含什么？一个有用的黑板不仅仅是粘贴聊天信息的地方。它需要一个应用程序可以验证的小型词汇表：案例及其当前修订版本；类型化的发现和主张；智能体所用记录的引用；验证者的结论；任何提议的行动以及人类决策历史。例如，一个主张可能指出某个运行器未注册，并引用一份运行器库存记录。黑板将其存储为数据，而不是第二个模型必须解释的段落。验证者随后可以检查该记录是否存在、是否在当前案例范围内，以及是否支持所主张的值。GraphQL 有助于表达这种契约：查询可以公开案例及其主张，变更（mutations）可以限制主张的发布方式，订阅可以通知用户界面案例已发生更改。

Those features do not automatically provide authorization or durable work delivery. The server still has to enforce roles and scopes, and the underlying store still has to be the source of truth. In the NVIDIA prototype, the durable outbox and Redis Streams dispatch specialist work. GraphQL subscriptions are viewer notifications. After reconnecting, the UI refetches the current case from persisted state. Keeping those jobs distinct avoids treating a best-effort notification as a durable queue. A blackboard is not “no orchestration” The application still coordinates work. It authenticates the caller, records a case, creates scoped work items, routes those items, retries failures, and enforces who may approve an action. What it removes is a central model acting as the conversation manager. That can reduce repeated prompt handoffs and make each specialist’s contribution easier to inspect.

这些功能并不能自动提供授权或持久的工作交付。服务器仍然必须强制执行角色和范围，底层存储仍然必须是事实来源。在 NVIDIA 的原型中，持久发件箱和 Redis Streams 用于分派专家工作。GraphQL 订阅仅用于查看者通知。重新连接后，UI 会从持久化状态重新获取当前案例。保持这些任务的独立性，避免了将尽力而为的通知视为持久队列。黑板并非“无需编排”。应用程序仍然协调工作。它验证调用者、记录案例、创建有范围的工作项、路由这些项、重试失败并强制执行谁可以批准行动。它所消除的是充当对话管理器的核心模型。这可以减少重复的提示词移交，并使每位专家的贡献更容易检查。

它还改变了复杂性的存在位置：设计问题、黑板可见的内容、仍需工程化处理的内容。智能体主张了什么？类型化、持久化的主张；模式变更和冲突的主张。什么证据支持它？明确的来源引用；来源质量、时效性和访问控制。工作完成了吗？案例状态和工作项状态；重试、幂等性和死信处理。谁可以采取行动？基于角色的审批路径；身份集成和职责分离。黑板本身并不能消除智能体的蔓延。一个小型、合理的名单会有所帮助。狭窄的工作范围、受限的工具，以及明确的规则（即专家不能在没有明确应用程序决策的情况下创建更多专家或进行委派）也同样有帮助。

The trust boundary matters more than the diagram An agent’s statement is a proposal. A deterministic verifier checks supported claim types against records. If a reference is missing, outside the alert’s scope, or inconsistent with the typed value, the claim should remain unverified or be marked contradicted. That verifier has a limited job. It can check properties encoded in its handlers; it cannot prove that the source systems are complete or decide whether a true fact is persuasive. The final action boundary should be separate again. The model can suggest an action, but only an authenticated human role can approve it. That restriction belongs in server-side authorization and the data flow—not in a sentence in the model prompt.

信任边界比图表更重要。智能体的陈述是一个提议。确定性验证者根据记录检查受支持的主张类型。如果引用缺失、超出警报范围或与类型化值不一致，则该主张应保持未验证状态或被标记为矛盾。该验证者的工作有限。它可以检查其处理程序中编码的属性；它无法证明源系统是完整的，也无法决定一个事实是否具有说服力。最终的行动边界应该再次分离。模型可以建议一个行动，但只有经过身份验证的人类角色才能批准它。该限制属于服务器端授权和数据流，而不是模型提示词中的一句话。

In both hackathon prototypes, the data is synthetic and actions are simulated. Those examples show the shape of the boundary; they are not evidence of production readiness. Two domains, one architectural question The NVIDIA project applies the pattern to AI-platform security alerts: identity, runner/network, and change/asset specialists contribute to a GraphQL board, while the verifier checks synthetic evidence and a human retains containment approval. The Microsoft Case Board applies a related pattern to fraud and AML: transaction, KYC/watchlist, and link-analysis specialists contribute claims; a deterministic verifier re-runs assertions against synthetic systems of record; a human decides whether to hold, file, or clear. Its evidence pack and SAR draft have AML-specific rules and risks.

在两个黑客马拉松原型中，数据都是合成的，行动也是模拟的。这些例子展示了边界的形状；它们不是生产就绪的证据。两个领域，一个架构问题。NVIDIA 项目将该模式应用于 AI 平台安全警报：身份、运行器/网络以及变更/资产专家向 GraphQL 板贡献内容，而验证者检查合成证据，人类保留遏制审批权。Microsoft 案例板将相关模式应用于欺诈和反洗钱：交易、KYC/观察名单和链接分析专家贡献主张；确定性验证者针对合成记录系统重新运行断言；人类决定是否扣留、归档或清除。其证据包和可疑活动报告（SAR）草案具有反洗钱特定的规则和风险。

These projects do not share a codebase, model stack, evaluation set, or benchmark. They are two separate applications of the same design question: how can agents collaborate without making a model the authority for evidence or action?
