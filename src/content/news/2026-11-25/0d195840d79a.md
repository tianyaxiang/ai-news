# RagLeap Core v0.13.8 & v0.13.9: Strengthening Subagent Integrity and Telegram Security

RagLeap Core 持续演进，重点关注安全性、可靠性和受控的自主性。在 v0.13.8 和 v0.13.9 版本中，我们引入了针对签名子代理执行记录、数据库级完整性保护、签名密钥轮换以及更安全的 Telegram 轮询的改进。这些版本遵循 RagLeap 背后的一个重要原则：AI 代理应具备能力，但其执行必须保持可追溯，且访问权限必须受到控制。

### v0.13.8: Strengthening Subagent Integrity
One of the key changes in v0.13.8 is how RagLeap stores and validates child-agent execution records. 
1. Dedicated append-only execution records: RagLeap now stores signed child-agent start records in a dedicated `agent_run_starts` database table. Database triggers prevent these records from being updated, deleted, or truncated through ordinary database operations. This provides a stronger integrity boundary for child-agent execution history.
2. Execution record validation: When a subagent runs or resumes, RagLeap validates its signed start record and checks that the record matches the live execution data, including: Parent execution, Agent role, and Execution depth. This helps detect inconsistencies between the signed record and the current execution state.
3. Signing-key rotation: The release adds support for signing-key rotation: `SPAWN_SIGNING_KEY` is the primary key. `SPAWN_SIGNING_KEY_PREVIOUS` supports validation of records signed with a previous key. `ADDON_ENCRYPTION_KEY` remains the fallback when the primary spawn signing key is not configured. A read-only diagnostic command is also available: `python -m core.spawn_keys`. It reports key-related requirements without changing the configuration.
4. Telegram long polling: v0.13.8 introduces opt-in Telegram long polling through: `TELEGRAM_POLLING=true`. This allows a Telegram bot to receive messages without requiring a publicly accessible webhook endpoint. The polling process runs through the scheduler leader, and message delivery follows an at-least-once model. Webhook model processing was also moved into a worker thread to avoid blocking the event loop.

### v0.13.9: 更安全的 Telegram 轮询默认设置
下一个版本专注于一项重要的访问控制改进。当启用 Telegram 轮询时，默认情况下仅接受所有者的私聊消息。来自其他用户和群组的消息将被忽略，且不会触发模型调用、文档查找或常规消息处理。所有者检查也采用“默认拒绝”策略：如果 RagLeap 无法确定消息是否来自已配置的所有者，则该消息将被忽略。

### Explicit public polling opt-in
For deployments that intentionally need a public bot, the behavior can be explicitly enabled using: `TELEGRAM_POLLING_PUBLIC=true`. This makes public polling a deliberate configuration choice rather than the default. The Telegram webhook model remains unchanged.

### 升级说明
升级前有几点事项非常重要。从 v0.13.7 升级到 v0.13.9：在启动升级后的应用程序之前，请应用 v0.13.8 的数据库架构更改。该迁移添加了 `agent_run_starts` 表、一个函数和两个触发器。此迁移是累加且幂等的。从 v0.13.8 升级到 v0.13.9：无需额外的架构迁移。如果 v0.13.8 中启用了 Telegram 轮询，请在依赖它之前升级到 v0.13.9，或者在升级前禁用轮询。轮询默认保持禁用状态，现有部署不会自动启用它。

### What Has Not Yet Been Production-Validated?
We believe in distinguishing implemented functionality from verified production behavior. These releases introduce the polling implementation and its access-control safeguards, but real Telegram bot polling has not yet been validated in production. Likewise, the new database-backed subagent record flow still needs validation with real-model subagent execution. The integrity protections also do not prevent a database administrator with sufficient privileges from dropping the triggers or changing the database structure.

### 为什么这些改进很重要
随着 AI 系统变得越来越自主，执行历史记录和访问控制变得愈发重要。一个可靠的 AI 员工平台需要的不仅仅是模型能力，它还需要：可验证的执行记录、代理之间的受控委托、更强的完整性保护、明确的访问边界、安全的默认设置以及清晰的升级和配置行为。RagLeap 正围绕这些原则进行开发。我们的方向很简单：开源的 AI 员工，在行动前会先征求意见。RagLeap 是一个开源、自托管的 AI 员工平台。这些版本是使代理执行更加受控、可追溯和可靠的又一步。
