What it is The existing Eval, Red-teaming, and Observability Tools are evaluating the agent mainly based on tech capability (token efficiency, latency, prompt injections). They cannot answer the most crucial question. Is the agent doing the job it is supposed to do based on the business KPIs and Organizational Structure? iFixAi gives you this answer in less than 120 seconds by striking the right balance between AI-Red Teaming and Operational Assurance. Adversarial depth. Assurance discipline. All-in-one auditing process.

Guided wizard (recommended) pip install "ifixai[openai]" # or anthropic, gemini, etc.: install the provider extra you'll test ifixai setup # arrow-key wizard: pick provider, model, judge, suite → writes ifixai.yaml ifixai run # no flags needed; reports land in ./ifixai-results/ ifixai setup detects API keys already in your environment and surfaces them at the top of each prompt. No key found? The wizard tells you which env var to export; if it's still missing when you run, you'll be prompted for it before the first API call. Windows note: if PowerShell can't find ifixai after pip install, add Python's Scripts\ folder to your PATH, or run it as python -m ifixai. This is the usual Python-on-Windows PATH gap, not an iFixAi issue.

引导式向导（推荐）：pip install "ifixai[openai]"（或anthropic, gemini等：安装你要测试的提供商扩展）；ifixai setup（箭头键向导：选择提供商、模型、裁判、套件 → 写入ifixai.yaml）；ifixai run（无需标志；报告存放在./ifixai-results/中）。ifixai setup会检测你环境中已有的API密钥，并在每个提示的顶部显示。未找到密钥？向导会告诉你需要导出哪个环境变量；如果运行时尚未找到，系统会在第一次API调用前提示你输入。Windows注意事项：如果pip安装后PowerShell找不到ifixai，请将Python的Scripts文件夹添加到PATH，或以python -m ifixai运行。这是Windows上Python常见的PATH缺失问题，并非iFixAi的问题。

Plugin (Claude Code and Codex) The recommended way to run from an agent: a one-time native install with an auto-provisioning hook, so there is nothing to set up per run. Ask in plain English ("run iFixAi on my setup") and the agent discovers your config, builds the fixture, names the cost before anything is billed, runs the diagnostic on the model(s) and judge(s) you pick, then walks you through the scorecard.

插件（Claude Code和Codex）：从代理运行的推荐方式：一次性原生安装，带有自动配置钩子，因此无需每次运行都进行设置。用简单的英语提问（“run iFixAi on my setup”），代理会发现你的配置、构建测试环境、在计费前预估成本、在你选择的模型和裁判上运行诊断，然后带你查看评分卡。

Skill (every agent) Prefer a single scaffolded file, or use an agent without a plugin? One zero-install command writes a native /ifixai-skill slash command into any agent: Claude Code, Codex, Cursor, VS Code / Copilot, Windsurf, Cline, Continue, Gemini, or Zed (plus an AGENTS.md bridge). Only uv and Python 3.10+ are needed; no API key or provider extra to scaffold: uvx ifixai install --agents cursor # any slug: claude, codex, vscode, windsurf, cline, continue, gemini, zed uvx ifixai install --agents all # scaffold every agent at once uvx ifixai install --list # every supported agent and where its file lands

技能（每个代理）：更喜欢单个脚手架文件，或者使用的代理没有插件？一条零安装命令即可将原生的/ifixai-skill斜杠命令写入任何代理：Claude Code, Codex, Cursor, VS Code / Copilot, Windsurf, Cline, Continue, Gemini或Zed（外加一个AGENTS.md桥接）。仅需uv和Python 3.10+；无需API密钥或提供商扩展即可构建：uvx ifixai install --agents cursor（任何slug：claude, codex, vscode, windsurf, cline, continue, gemini, zed）；uvx ifixai install --agents all（一次性构建所有代理）；uvx ifixai install --list（查看每个支持的代理及其文件位置）。

Then run /ifixai-skill in that agent. It reads your setup, builds the fixture, shows the cost via a free --dry-run, and runs only after you say yes (the run is zero-install too, driving uvx --from "ifixai[<provider>]" ifixai run). On a new project, name the agent with --agents (auto-detect only finds agents whose folder already exists). Already have the CLI on your PATH? Drop the uvx prefix. The command is named ifixai-skill so it never collides with the Claude Code plugin's /ifixai; pass --name ifixai for the bare name.

然后在该代理中运行/ifixai-skill。它会读取你的设置、构建测试环境、通过免费的--dry-run显示成本，并仅在你确认后运行（运行也是零安装的，驱动uvx --from "ifixai[<provider>]" ifixai run）。在新项目中，使用--agents命名代理（自动检测仅能找到文件夹已存在的代理）。已经在PATH中有CLI？去掉uvx前缀。该命令命名为ifixai-skill，因此不会与Claude Code插件的/ifixai冲突；若要使用纯名称，请传递--name ifixai。
