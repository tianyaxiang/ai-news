# FinOps na AWS: configurando o FinOps Agent e integrando com o Slack

### 1. Introdução
Este artigo tem como objetivo documentar a configuração do AWS FinOps Agent e sua integração com o Slack, desde a habilitação dos pré-requisitos até o recebimento das mensagens no canal. O FinOps Agent foi lançado em junho de 2026, com o objetivo de investigar os custos na conta da AWS, sendo possível integrá-lo às ferramentas de trabalho Slack e Jira.

**中文翻译：**
本文旨在记录 AWS FinOps Agent 的配置及其与 Slack 的集成过程，涵盖从启用先决条件到在频道中接收消息的完整步骤。FinOps Agent 于 2026 年 6 月发布，旨在调查 AWS 账户成本，并支持与 Slack 和 Jira 等工作工具集成。

Em ambientes corporativos, os dados de custo da AWS normalmente são consultados nas ferramentas nativas Cost Explorer, Compute Optimizer e Cost Optimization Hub. Esses ferramentas normalmente são acessadas apenas pelo time de FinOps ou de infraestrutura, enquanto os times de desenvolvimento que provisionam os recursos raramente as consultam. Sem monitoramento ativo, o time pode demorar para identificar quando um custo sobe. A integração do FinOps Agent com o Slack ou Jira atende esse ponto, pois o agente consolida as análises das 3 ferramentas e publica o resultado no canal ou em um ticket, onde o time trabalha diariamente. Isso aproxima a informação de custo de quem provisiona os recursos e reduz a chance de uma anomalia passar despercebida.

**中文翻译：**
在企业环境中，AWS 成本数据通常通过原生的 Cost Explorer、Compute Optimizer 和 Cost Optimization Hub 进行查询。这些工具通常仅由 FinOps 或基础设施团队访问，而负责配置资源的开发团队很少查看。如果没有主动监控，团队可能无法及时发现成本上涨。FinOps Agent 与 Slack 或 Jira 的集成解决了这一问题，因为它整合了上述三个工具的分析结果，并将其发布到团队日常工作的频道或工单中。这使得成本信息更贴近资源配置者，从而降低了异常情况被忽视的风险。

### 2. O AWS FinOps Agent
O agente é construído com base no Amazon Bedrock e oferece 4 recursos principais:
* Consulta de custo em linguagem natural, utilizando os dados reais de custo e uso da conta.
* Investigação de anomalia disparada por evento. Quando o AWS Cost Anomaly Detection identifica um desvio, o agente investiga a causa raiz e pode publicar um relatório consolidado em um canal do Slack, ou criar um ticket no Jira com o resultado.
* Consolidação das recomendações do Cost Optimization Hub e do Compute Optimizer.
* Relatórios recorrentes agendados, em periodicidade diária, semanal ou mensal, nos formatos HTML, PDF ou PPT.

**中文翻译：**
该代理基于 Amazon Bedrock 构建，提供 4 项主要功能：
* 使用账户实际成本和使用数据进行自然语言成本查询。
* 事件触发的异常调查。当 AWS Cost Anomaly Detection 识别出偏差时，代理会调查根本原因，并将汇总报告发布到 Slack 频道或在 Jira 中创建工单。
* 整合 Cost Optimization Hub 和 Compute Optimizer 的建议。
* 定期生成的报告（按日、周或月），支持 HTML、PDF 或 PPT 格式。

Para isso, o agente lê 5 serviços da conta: AWS Cost Explorer, AWS Cost Anomaly Detection, AWS Cost Optimization Hub, AWS Compute Optimizer e AWS CloudTrail. Neste caso, o CloudTrail permite correlacionar o aumento de custo com a ação que o originou, identificando qual usuário ou role executou a alteração e em que momento.

**中文翻译：**
为此，代理会读取账户中的 5 项服务：AWS Cost Explorer、AWS Cost Anomaly Detection、AWS Cost Optimization Hub、AWS Compute Optimizer 和 AWS CloudTrail。其中，CloudTrail 允许将成本增加与触发该成本的操作相关联，从而识别出是哪个用户或角色在何时执行了更改。

### 3. Pré-requisitos
Para a implementação, alguns recursos precisam estar configurados:
* Conta da AWS com acesso administrativo, ou permissão para criação de IAM roles.
* Console na região us-east-1, única região disponível durante a fase de public preview.
* AWS Cost Optimization Hub e AWS Compute Optimizer habilitados.
* Workspace do Slack com permissão para autorizar aplicativos.
* Conta com volume de custos suficiente para gerar recomendações.

**中文翻译：**
实施前，需要配置以下资源：
* 拥有管理权限或创建 IAM 角色权限的 AWS 账户。
* 控制台需位于 us-east-1 区域（公共预览阶段仅支持该区域）。
* 已启用 AWS Cost Optimization Hub 和 AWS Compute Optimizer。
* 拥有授权应用程序权限的 Slack 工作区。
* 账户需有足够的成本规模以生成建议。

### 4. Passo a passo

#### 4.1. Habilitando o Cost Optimization Hub e o Compute Optimizer
Os dois serviços são gratuitos. Após a habilitação, a AWS pode levar algumas horas para gerar as recomendações, sendo assim, os dashboards podem aparecer vazios no primeiro acesso.

**中文翻译：**
这两项服务均免费。启用后，AWS 可能需要几个小时来生成建议，因此首次访问时仪表板可能为空。

#### 4.2. Criação do agente
1. Alterar a região do console para us-east-1.
2. Pesquisar o serviço AWS FinOps Agent e clicar em “Get started”.
3. Definir o nome e descrição.
4. Configurar as permissões (recomenda-se “Auto-create a new FinOps Agent role”).
5. Configurar a permissão de acesso da aplicação web (recomenda-se “Auto-create a new FinOps Operator role”).

**中文翻译：**
1. 将控制台区域更改为 us-east-1。
2. 搜索 AWS FinOps Agent 服务并点击“Get started”。
3. 设置名称和描述。
4. 配置权限（建议选择“Auto-create a new FinOps Agent role”）。
5. 配置 Web 应用程序的访问权限（建议选择“Auto-create a new FinOps Operator role”）。

#### 4.3. Integração com o Slack
1. Selecionar “Connect with Slack” e clicar em “Add integration”.
2. Autorizar o acesso ao workspace do Slack.
3. Criar um canal no Slack (ex: “aws-finops”), adicionar o app do FinOps Agent ao canal.
4. Copiar o “Channel ID” (deve começar com a letra C).
5. Colar o Channel ID na tela de integração e finalizar a criação.

**中文翻译：**
1. 选择“Connect with Slack”并点击“Add integration”。
2. 授权访问 Slack 工作区。
3. 在 Slack 中创建一个频道（例如“aws-finops”），并将 FinOps Agent 应用添加到该频道。
4. 复制“Channel ID”（必须以字母 C 开头）。
5. 将 Channel ID 粘贴到集成界面并完成创建。
