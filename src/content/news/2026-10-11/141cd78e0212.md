# Unity VFX to Cocos Creator: a visual workflow

An effect can look right in one frame and still behave differently in motion. Here is the workflow I use to move Unity VFX into Cocos Creator for the browser.
一个特效在单帧画面中看起来可能没问题，但在运动时表现却可能完全不同。以下是我将 Unity VFX 迁移到 Cocos Creator（用于浏览器端）时所采用的工作流程。

The workflow at a glance Start with one effect. If the comparison shows a mismatch, fix it and replay the same case. What gets translated Check the behaviour in Cocos: blending, simulation space and timing can change the result.
工作流程概览：从一个特效开始。如果对比发现不匹配，则进行修复并重新运行同一案例。关于转换内容：检查在 Cocos 中的表现，混合模式、模拟空间和时间设置都可能改变最终结果。

How I check the port Align the camera and playback clock. Use differences to guide frame review, then check browser performance and input separately. A low average difference can hide a short missing flash.
我如何检查移植效果：对齐摄像机和播放时钟。利用差异来指导逐帧审查，然后分别检查浏览器性能和输入。较低的平均差异可能会掩盖短暂的闪烁缺失。

Inspect motion, bursts and trails, and check warnings for empty or frozen captures. See it move Cocos Creator capture of a ported 3D Lasers effect. Original Unity asset: Hovl Studio, 3D Lasers.
检查运动、爆发和拖尾效果，并查看关于空捕获或冻结捕获的警告。查看动态效果：这是移植后的 3D Lasers 特效在 Cocos Creator 中的捕获画面。原始 Unity 资源：Hovl Studio, 3D Lasers。

The full captures support validation; this GIF shows motion. AI-assisted tools help with inspection and repetitive conversion. Repeatable captures make the result reviewable.
完整的捕获内容支持验证；此 GIF 展示了运动效果。AI 辅助工具有助于检查和重复性转换。可重复的捕获使结果具备可审查性。

Explore the current browser demos: https://unity2cocosporting.web.app Which part should the next visual guide unpack: materials, timing or trails?
探索当前的浏览器演示：https://unity2cocosporting.web.app 下一个视觉指南应该拆解哪一部分：材质、时间还是拖尾？
