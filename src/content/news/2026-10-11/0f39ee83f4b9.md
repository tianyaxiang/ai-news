Example answer · based on the findings

After +, the % button takes a percentage of the first number.

在加号之后，百分号按钮会取第一个数字的百分比。

Let's try two examples. Change a game's speed, then return to Calculator and rebuild its % button.

Example 01 · Chrome’s dinosaur game

示例 01 · Chrome 恐龙游戏

Play the reconstruction

运行重构版本

Original rule: start at 6, then increase toward 13.

原始规则：从 6 开始，然后增加到 13。

The script actually running in the page. The agent reads its update function and speed settings, then uses that rule in a new game.

脚本实际上是在页面中运行的。代理读取其更新函数和速度设置，然后在新的游戏中使用该规则。

›Use REA to inspect this dinosaur game. Why does it get faster? Show the speed rule, then build a small version with an adjustable speed.

›使用 REA 检查这个恐龙游戏。为什么它会变快？展示速度规则，然后构建一个具有可调速度的小版本。

Inspected target: wayou’s Chromium-derived browser edition.

检查目标：wayou 基于 Chromium 的浏览器版本。

Start at 6. Add 0.001 each update without a collision, while speed is below 13.

从 6 开始。在没有碰撞的情况下，每次更新增加 0.001，直到速度低于 13。

REA inspected the HTTP browser edition through a local debugging connection and returned the loaded index.js, including its source and digest.

REA 通过本地调试连接检查了 HTTP 浏览器版本，并返回了加载的 index.js，包括其源代码和摘要。

We called the original game’s update function in a controlled browser check, with obstacles and automatic scheduling disabled. After 4,000 updates, speed was 10.0; after 10,000, it was 13.0, rounded to one decimal.

我们在受控的浏览器检查中调用了原始游戏的更新函数，并禁用了障碍物和自动调度。经过 4,000 次更新后，速度为 10.0；经过 10,000 次更新后，速度为 13.0（四舍五入到小数点后一位）。

The new mini-game keeps that speed rule. Its drawing, jumping and collision code are a small teaching implementation. Open the lab to see the new code and run the same speed check.

新的迷你游戏保留了该速度规则。其绘图、跳跃和碰撞代码是一个小型教学实现。打开实验室查看新代码并运行相同的速度检查。

示例 02 · Windows 计算器

We saw why 200 + 10% gives 220. Now let’s recover the rules for both + and ×, and try them.

我们了解了为什么 200 + 10% 等于 220。现在让我们恢复 + 和 × 的规则，并进行尝试。

One branch divides by 100. The other also multiplies by the first number. The agent uses both to recreate the % button.
