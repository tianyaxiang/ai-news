Changing an Nginx setting does not automatically mean you should restart the service. For a valid configuration update, a graceful reload is usually the better choice; use a full restart when you specifically need to stop and start the process. If Nginx runs in Docker, manage it as a container rather than as a host systemd service.

更改 Nginx 设置并不意味着您必须重启服务。对于有效的配置更新，平滑重载（reload）通常是更好的选择；仅当您确实需要停止并启动进程时，才使用完全重启（restart）。如果 Nginx 运行在 Docker 中，请将其作为容器进行管理，而不是作为宿主机的 systemd 服务。

Linux: reload for config changes, restart for a full cycle. On a systemd-managed Linux server, these commands do different things:
`sudo systemctl reload nginx`
`sudo systemctl restart nginx`
A reload asks the running service to apply its configuration without a full stop. A restart stops and starts the service, which can interrupt active connections during the transition.

Linux：配置变更使用重载，完整周期使用重启。在由 systemd 管理的 Linux 服务器上，这些命令的作用不同：
`sudo systemctl reload nginx`
`sudo systemctl restart nginx`
重载会要求正在运行的服务应用其配置，而无需完全停止。重启则会停止并启动服务，这可能会在转换过程中中断活动的连接。

For routine configuration edits, test the configuration first, then reload only if the test succeeds:
`sudo nginx -t && sudo systemctl reload nginx`
The && matters: the reload runs only when nginx -t exits successfully. If the test reports a syntax or configuration error, fix that problem and test again rather than reloading a configuration you already know is invalid.

对于常规的配置编辑，请先测试配置，仅在测试成功后才进行重载：
`sudo nginx -t && sudo systemctl reload nginx`
“&&”非常重要：只有当 `nginx -t` 成功退出时，重载才会执行。如果测试报告了语法或配置错误，请修复该问题并再次测试，而不是重载一个您已知无效的配置。

A reload is not a universal fix for a broken process. If Nginx needs a full process restart, or your setup does not support reloading the service this way, use restart instead.

重载并不是解决进程故障的万能方案。如果 Nginx 需要完全重启进程，或者您的设置不支持以这种方式重载服务，请改用重启。

Confirm the service came back. After a restart, check what systemd reports:
`sudo systemctl status nginx`
If the service is not active or the command fails, inspect recent service logs:
`sudo journalctl -u nginx --no-pager -n 50`

确认服务已恢复。重启后，检查 systemd 的报告：
`sudo systemctl status nginx`
如果服务未激活或命令失败，请检查最近的服务日志：
`sudo journalctl -u nginx --no-pager -n 50`

Docker: restart the container, not a host service. First find the container's name or ID:
`docker ps`
Then restart it, substituting the actual name or ID:
`docker restart nginx-container`

Docker：重启容器，而非宿主机服务。首先找到容器的名称或 ID：
`docker ps`
然后重启它，替换为实际的名称或 ID：
`docker restart nginx-container`

For a Compose-managed service, run this from the directory containing the Compose file. Replace nginx with the service name in that file:
`docker compose restart nginx`
A Compose restart restarts the existing service; it does not apply changes to the Compose service definition. If you edited compose.yaml, use the appropriate Compose update workflow, such as `docker compose up -d`, when the service needs to be recreated.

对于由 Compose 管理的服务，请在包含 Compose 文件的目录中运行此命令。将 nginx 替换为该文件中的服务名称：
`docker compose restart nginx`
Compose 重启只会重启现有服务；它不会应用对 Compose 服务定义的更改。如果您编辑了 compose.yaml，当需要重新创建服务时，请使用适当的 Compose 更新工作流，例如 `docker compose up -d`。

There is another distinction when you edit Nginx's configuration. If the file is bind-mounted into the container, restarting the container is not a substitute for checking and gracefully reloading Nginx's configuration. When the container setup supports it, test and reload the process inside the container:
`docker exec nginx-container nginx -t`
`docker exec nginx-container nginx -s reload`

编辑 Nginx 配置时还有另一个区别。如果文件是通过绑定挂载（bind-mount）进入容器的，重启容器并不能替代检查并平滑重载 Nginx 配置的操作。当容器设置支持时，请在容器内测试并重载进程：
`docker exec nginx-container nginx -t`
`docker exec nginx-container nginx -s reload`

A quick decision guide:
Changed Nginx configuration on Linux: run `sudo nginx -t`; if it passes, use `sudo systemctl reload nginx`.
Need a full restart of a systemd-managed service: use `sudo systemctl restart nginx`, then check `systemctl status` if needed.
Nginx runs in Docker: restart the container or Compose service, not a host-level Nginx service.

快速决策指南：
在 Linux 上更改了 Nginx 配置：运行 `sudo nginx -t`；如果通过，使用 `sudo systemctl reload nginx`。
需要对 systemd 管理的服务进行完全重启：使用 `sudo systemctl restart nginx`，必要时检查 `systemctl status`。
Nginx 运行在 Docker 中：重启容器或 Compose 服务，而不是宿主机级别的 Nginx 服务。
