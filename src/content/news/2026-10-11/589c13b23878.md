There are few AI harnesses that dare to state directly on their own website that they do not support MCP. Pi was one of them. Then, on October 1, 2026, the Earendil team released Pi 1.0, which contradicted their previous announcement because, in this version, MCP has become part of the core. The interesting question is not "how they did it," but "how can a team that once rejected something change their mind without losing their original principles?"

มี agent harness ไม่กี่ตัวที่กล้าเขียนลงหน้าเว็บตัวเองตรง ๆ ว่า ไม่รองรับ MCP Pi คือหนึ่งในนั้น แล้ววันที่ 1 ตุลาคม 2026 ทีม Earendil ก็ออก Pi 1.0 พร้อมกับสิ่งที่ตรงข้ามกับคำประกาศเดิม เพราะในเวอร์ชันนี้ MCP กลายเป็นส่วนหนึ่งของแกนกลางไปแล้ว คำถามที่น่าสนใจจึงไม่ใช่ "ทำไมเขาถึงทำได้" แต่เป็น "ทีมที่เคยปฏิเสธอะไรบางอย่าง จะเปลี่ยนใจโดยไม่เสียหลักการเดิมได้ยังไง"

What is Pi and how popular is it? Pi is an AI harness written in TypeScript, published on GitHub under the MIT license. The term "harness" here refers to a software layer that provides an environment for AI models to operate within, while running a loop that allows them to call tools. The Earendil team defines it differently in the "Pi Durable" article: it is a data store combined with the necessary mechanisms to run conversations with multiple models simultaneously, including the tools the models call and the environments in which those tools run.

Pi คืออะไร และดังแค่ไหน Pi เป็น agent harness ที่เขียนด้วย TypeScript เผยแพร่บน GitHub ภายใต้สัญญาอนุญาต MIT คำว่า harness ในที่นี้หมายถึงชั้นซอฟต์แวร์ที่จัดสภาพแวดล้อมให้โมเดล AI ทำงานอยู่ข้างใน พร้อมเดินลูปให้มันเรียกเครื่องมือได้ ทีม Earendil ให้คำนิยามไว้อีกแบบในบทความ Pi Durable ว่ามันคือที่เก็บข้อมูล บวกกับกลไกที่จำเป็นสำหรับรันบทสนทนากับโมเดลหลายชุดพร้อมกัน ทั้งเครื่องมือที่โมเดลเรียกใช้และสภาพแวดล้อมที่เครื่องมือเหล่านั้นรันอยู่

The selling point the team emphasizes is minimalism and flexibility, which sounds contradictory. However, they explain that it means tools small enough to be fully understood and open to extensions at almost every layer. In the Pi 1.0 launch article, it is stated that there are hundreds of thousands of Pi users worldwide each week, without specifying an exact number. As for the numbers on GitHub, as of the writing of this article, the repo has 113,973 stars, 14,485 forks, and 325 open issues. The Pi 1.0 announcement thread on Hacker News reached number one with 1,687 points and 609 comments.

จุดขายที่ทีมย้ำตลอดคือความมินิมอลกับความยืดหยุ่น ซึ่งฟังดูขัดกันในตัว แต่เขาอธิบายว่าหมายถึงเครื่องมือที่เล็กพอจะเข้าใจได้ทั้งตัว และเปิดให้ต่อเติมได้แทบทุกชั้น ในบทความประกาศเปิดตัว Pi 1.0 ระบุว่ามีผู้ใช้ Pi หลายแสนคนทั่วโลกในแต่ละสัปดาห์ โดยไม่ระบุตัวเลขชัดเจน ส่วนตัวเลขบน GitHub ตรวจได้ตรง ๆ ว่า ณ วันที่เขียนบทความนี้ repo นี้มีดาว 113,973 ดวง ฟอร์ก 14,485 และ issue ที่ยังเปิดอยู่ 325 รายการ กระทู้ประกาศ Pi 1.0 บน Hacker News ขึ้นอันดับหนึ่งด้วยคะแนน 1,687 คะแนน และ 609 ความเห็น

What is Codemode? The term "Codemode" appears many times in the article, and this is the heart of the matter. When a harness calls a tool, it works on two sides: the side where bash runs and the side where the agent loop runs. Both sides have very different levels of trust, as the harness loop is usually in a trusted environment, while the tools it calls are often in less trustworthy sandboxes. Codemode chooses to reside on the latter side: running where the harness runs and acting as a coordinator to combine multiple tool calls into a single set.

แล้วอะไรคือ Codemode คำว่า Codemode โผล่มาหลายครั้งในบทความนั้น และนี่คือหัวใจของเรื่องทั้งหมด เมื่อ harness เรียกใช้เครื่องมือ มันทำงานได้สองฝั่ง คือฝั่งที่ bash รันอยู่ กับฝั่งที่ agent loop รันอยู่ ทั้งสองฝั่งมีระดับความน่าเชื่อถือต่างกันมาก เพราะลูปของ harness มักอยู่ในสภาพแวดล้อมที่เชื่อถือได้ ขณะที่เครื่องมือที่มันเรียกมักอยู่ในแซนด์บ็อกซ์ที่ไม่น่าไว้ใจเท่า Codemode เลือกอยู่ฝั่งหลังคือ รันตรงที่ harness รัน และทำหน้าที่ประสานการเรียกเครื่องมือหลายตัวให้เป็นชุดเดียว
