# 11 year old unsoundness bugs found in Rust borrow checker

Given that this issue has been shared online and is currently getting quite a few visitors, here's some additional context.

鉴于此问题已在网上分享并吸引了相当多的访问者，以下是一些补充背景信息。

Rust's type system is intended to prevent memory unsafety. Upholding this promise is something we take very seriously, which is why we've been working on things like the next-generation trait solver, the region constraint rework, and more generally Project Zero. It is a large priority of the Types Team to fix all type system unsoundnesses and to work towards there being a solid foundation to minimize the risk of unknown ones.

Rust 的类型系统旨在防止内存不安全。我们非常认真地对待这一承诺，这也是我们致力于开发下一代特征求解器、区域约束重构以及更广泛的“零号项目”（Project Zero）的原因。修复所有类型系统的不健全之处并努力建立稳固的基础以最大限度地降低未知风险，是类型团队的首要任务。

This bug is a P-high issue and would have been P-critical regardless of whether people encountered it in the wild. The reason that it is "only P-high" is that it's 11 years old. A bug like this which has not been found during the last 11 years cannot actually be that easy to hit.

此漏洞属于 P-high（高优先级）问题，无论人们是否在实际应用中遇到它，它本应被定为 P-critical（关键优先级）。它之所以“仅为 P-high”，是因为它已经存在 11 年了。像这样在过去 11 年中都未被发现的漏洞，实际上并不容易触发。

Looking at the bug itself, it is also very likely that this unsoundness has not caused memory unsafety by accident. While it looks easy to trigger, to exploit this you need an intentionally malicious Drop implementation.

从漏洞本身来看，这种不健全性极有可能并未意外导致内存不安全。虽然它看起来很容易触发，但要利用它，你需要一个蓄意恶意的 `Drop` 实现。
