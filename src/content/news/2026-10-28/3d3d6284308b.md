CVE-2026-116692: Remote Code Execution in MLflow via Third-Party Scorer Deserialization. Vulnerability ID: CVE-2026-116692. CVSS Score: 9.8. Published: 2026-10-27. CVE-2026-116692 (GHSA-26p8-2jq9-3vq9) is a remote code execution vulnerability in MLflow affecting versions 3.12.0rc0 prior to 3.17.0.

CVE-2026-116692：通过第三方评分器反序列化在 MLflow 中实现远程代码执行。漏洞 ID：CVE-2026-116692。CVSS 评分：9.8。发布日期：2026-10-27。CVE-2026-116692 (GHSA-26p8-2jq9-3vq9) 是 MLflow 中的一个远程代码执行漏洞，影响 3.12.0rc0 到 3.17.0 之前的版本。

The flaw stems from an overly permissive module prefix check during the deserialization of third-party GenAI evaluation scorers in mlflow/genai/scorers/base.py. By setting an experiment's artifact root to a local package directory within the Python module search path and uploading a crafted Python file as a run artifact, an attacker can invoke the /ajax-api/3.0/mlflow/scorer/invoke endpoint to dynamically import and execute arbitrary code on the MLflow tracking server.

该缺陷源于在 mlflow/genai/scorers/base.py 中对第三方 GenAI 评估评分器进行反序列化时，模块前缀检查过于宽松。通过将实验的工件根目录设置为 Python 模块搜索路径内的本地包目录，并上传一个精心制作的 Python 文件作为运行工件，攻击者可以调用 /ajax-api/3.0/mlflow/scorer/invoke 端点，从而在 MLflow 跟踪服务器上动态导入并执行任意代码。

TL;DR An insecure module prefix check in MLflow's third-party GenAI scorer deserialization allows attackers to upload malicious Python artifacts into writable package directories and execute arbitrary code via dynamic module importation on unauthenticated or authenticated MLflow servers. ⚠️ Exploit Status: POC.

简而言之：MLflow 第三方 GenAI 评分器反序列化中不安全的模块前缀检查，允许攻击者将恶意 Python 工件上传到可写的包目录中，并通过动态模块导入在未经身份验证或已身份验证的 MLflow 服务器上执行任意代码。⚠️ 利用状态：POC（概念验证）。
