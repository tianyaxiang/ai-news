Ghost staff authentication is part of the public-site attack surface. A Ghost site can serve public pages while exposing a staff administration route for content, members, integrations, and site settings. The public website and the staff login share infrastructure, but they do not have the same risk. An exposure inventory should identify where the staff path is reachable and whether the site's identity controls are ready for a compromised or departed staff account.

Ghost 平台的员工身份验证是公共站点攻击面的一部分。Ghost 站点在提供公共页面服务的同时，可能会暴露用于管理内容、成员、集成和站点设置的员工管理路径。公共网站和员工登录界面共享基础设施，但它们面临的风险并不相同。暴露清单应明确员工路径的可访问位置，并评估站点的身份控制措施是否足以应对员工账户被盗用或离职的情况。

A ZoomEye query for app="Ghost" returned 32,357 matches on 28 October 2026, using sub_type=all and a page size of one. A title query returned 19,267. Those counts describe potential Ghost services, not a count of unprotected admin panels. Many sites can be public by design, so the review must separate the content site from the staff login and API.

2026 年 10 月 28 日，使用 sub_type=all 和页面大小为 1 的参数对 app="Ghost" 进行 ZoomEye 查询，返回了 32,357 个匹配项。标题查询返回了 19,267 个结果。这些统计数字描述的是潜在的 Ghost 服务，而非未受保护的管理面板数量。许多站点在设计上就是公开的，因此审查时必须将内容站点与员工登录界面及 API 分开。

Review the staff account lifecycle. Ghost added device verification and email-based two-factor authentication for staff logins in April 2025. Those controls reduce the value of a password alone, but they depend on a working email path and a sound device-verification process. Confirm that administrators cannot disable the control for themselves where policy requires it, and monitor failed verification and recovery attempts.

审查员工账户生命周期。Ghost 于 2025 年 4 月为员工登录增加了设备验证和基于电子邮件的双重身份验证。这些控制措施降低了仅凭密码的风险，但它们依赖于有效的电子邮件路径和健全的设备验证流程。在政策要求的情况下，需确认管理员无法自行禁用这些控制措施，并监控失败的验证和恢复尝试。

Account removal needs session awareness. Ghost's authentication reset help page says that rotating site authentication resets API keys, resets staff passwords, and signs out existing sessions, including the session of the person performing the reset. That is a strong containment action after suspected credential exposure. It is disruptive, so the runbook should name the approver, the communications path, and the steps to reissue integration keys.

账户移除需要具备会话感知能力。Ghost 的身份验证重置帮助页面指出，轮换站点身份验证会重置 API 密钥、重置员工密码并注销现有会话，包括执行重置操作的人员的会话。这是在怀疑凭据泄露后的一种强有力的遏制措施。由于该操作具有破坏性，操作手册应明确审批人、沟通路径以及重新颁发集成密钥的步骤。

Inventory integrations and custom apps that use staff or API credentials. A site may have newsletter providers, analytics, SSO, or publishing automation connected through long-lived keys. Rotate them with the account that owns them, not with an unrelated administrator account. Store secrets outside the theme repository and deployment logs.

盘点使用员工或 API 凭据的集成和自定义应用程序。站点可能通过长期有效的密钥连接了时事通讯提供商、分析工具、单点登录（SSO）或发布自动化工具。应使用拥有这些凭据的账户进行轮换，而不是使用不相关的管理员账户。将密钥存储在主题存储库和部署日志之外。

Turn count into ownership. Use the Ghost measurement as a candidate list, then match the hostnames to the organization's domains and certificate inventory. A match with an unknown owner can be a customer site, a marketing test, or a stale deployment. Do not probe a third-party Ghost installation just because its fingerprint appears in a public search.

将统计数据转化为所有权归属。使用 Ghost 的测量结果作为候选列表，然后将主机名与组织的域名和证书清单进行匹配。如果匹配到未知所有者，那可能是客户站点、营销测试或过时的部署。不要仅仅因为第三方 Ghost 安装的指纹出现在公共搜索中就对其进行探测。

For owned sites, test a normal staff login, an expired invite, a removed user, and a rotating API key. Confirm that removal ends the session or that the containment procedure does. Review reverse-proxy access rules for the staff path and make sure the website cache does not expose authenticated pages. The final record should list the site owner, staff count, MFA policy, reset procedure, and external reachability.

对于自有站点，应测试正常的员工登录、过期的邀请、已移除的用户以及轮换 API 密钥的情况。确认移除操作或遏制程序能够终止会话。审查员工路径的反向代理访问规则，并确保网站缓存不会暴露已验证的页面。最终记录应列出站点所有者、员工数量、多因素身份验证（MFA）政策、重置程序以及外部可访问性。

Ghost's public content may be intentionally open. The staff control plane needs a tighter boundary. A useful review follows the path from public hostname to staff login, then to the API and integrations that can change the site.

Ghost 的公共内容可能是故意公开的。员工控制平面需要更严格的边界。有效的审查应遵循从公共主机名到员工登录，再到能够更改站点的 API 和集成的路径。
