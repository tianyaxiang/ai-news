### NVIDIA Kubernetes Engine (NVKE)

NVIDIA Kubernetes® Engine (NVKE) provides the management plane that platform teams install to create and operate Kubernetes clusters for their customers. Each workload cluster has its own Kubernetes control plane, etcd and node pools. You operate the NVKE management plane; your customers use their clusters through the Kubernetes API and kubectl.

NVIDIA Kubernetes® Engine (NVKE) 提供了一个管理平面，平台团队可以通过安装该平面来为客户创建和运维 Kubernetes 集群。每个工作负载集群都拥有独立的 Kubernetes 控制平面、etcd 和节点池。您负责运维 NVKE 管理平面，而您的客户则通过 Kubernetes API 和 kubectl 使用他们的集群。

### Preview: NVKE is available as a preview.

APIs, configuration and behavior can change between releases, and we do not recommend NVKE for production workloads. See Preview status and known limitations.

预览版：NVKE 目前以预览版形式提供。API、配置和行为可能会在不同版本之间发生变化，因此我们不建议将 NVKE 用于生产工作负载。请参阅“预览状态”和“已知限制”。

### The local quickstart

The local quickstart runs on a Linux host or VM, amd64 or arm64, with at least 6 CPUs, 12 GiB of free memory and 100 GiB of free disk. It requires Docker, virtual TPM support and the tools listed in the guide. Follow its setup through workload-cluster creation and confirm the cluster's nodes report Ready. On macOS, use the local site guide, which runs the evaluation inside a Colima virtual machine.

本地快速入门

本地快速入门在 Linux 主机或虚拟机（amd64 或 arm64 架构）上运行，要求至少具备 6 个 CPU、12 GiB 可用内存和 100 GiB 可用磁盘空间。它需要 Docker、虚拟 TPM 支持以及指南中列出的工具。请按照设置步骤完成工作负载集群的创建，并确认集群节点显示为“就绪”（Ready）状态。在 macOS 上，请使用本地站点指南，该指南在 Colima 虚拟机内运行评估环境。

### For a real installation

For a real installation, you supply the machines, networking, node images and registries, and configure access to NVIDIA Infra Controller (NICo). NICo is the sole compatible infrastructure provider at preview. The platform and version reference lists validated combinations and pinned dependencies.

对于实际安装，您需要提供机器、网络、节点镜像和注册表，并配置对 NVIDIA Infra Controller (NICo) 的访问权限。在预览阶段，NICo 是唯一兼容的基础设施提供商。平台和版本参考文档列出了经过验证的组合和固定的依赖项。

### What NVKE does

Creates independent workload clusters. Request clusters through the NVKE API or nvkectl; NVKE provisions machines through NICo and forms Kubernetes clusters with their own control planes. Manages workload cluster lifecycle. Create, scale and delete node pools, upgrade Kubernetes and replace nodes. See the node pool guide for the manual steps and preview limits on replacement and upgrades.

NVKE 的功能

创建独立的工作负载集群。通过 NVKE API 或 nvkectl 请求集群；NVKE 通过 NICo 配置机器，并组建拥有独立控制平面的 Kubernetes 集群。管理工作负载集群生命周期。创建、扩展和删除节点池，升级 Kubernetes 并替换节点。有关手动步骤以及替换和升级方面的预览限制，请参阅节点池指南。

### Establishes node identity

Nodes attest through SPIFFE/SPIRE using their TPM before receiving join credentials. Encryption of etcd data is available per cluster. Connects builds to deployment. Its companion project, NVIDIA Kubernetes Recipes (NVKR), builds node images and NVKE components from pinned inputs. NVKE deploys those artifacts; NVKR owns their build and release evidence.

建立节点身份

节点在接收加入凭据之前，会通过 TPM 使用 SPIFFE/SPIRE 进行身份验证。每个集群均可启用 etcd 数据加密。将构建与部署连接起来。其配套项目 NVIDIA Kubernetes Recipes (NVKR) 使用固定的输入构建节点镜像和 NVKE 组件。NVKE 负责部署这些制品，而 NVKR 则负责其构建和发布证据。

### The preview needs explicit operator configuration

API authentication is off and the API uses plain HTTP after installation. Configure API authentication and protected access before admitting callers. The management cluster does not upgrade, scale or replace itself, and there is no management-plane upgrade or backup/restore procedure. FDE node images are for evaluation and provide no data-at-rest confidentiality. Read the known limitations before choosing an evaluation or installation path.

预览版需要明确的操作员配置

安装后，API 身份验证处于关闭状态，且 API 使用明文 HTTP。在允许调用者访问之前，请配置 API 身份验证和受保护的访问权限。管理集群不会自动升级、扩展或替换自身，且目前没有管理平面的升级或备份/恢复流程。FDE 节点镜像仅供评估使用，不提供静态数据保密性。在选择评估或安装路径之前，请阅读已知限制。

### Overview

The diagram shows the NVKE product family, how it sits on NICo and your GPU machines, and which components talk to each other. NVKE is not a Kubernetes distribution and not a Cluster API flavour. It is a self-hosting factory for Kubernetes clusters: a throwaway seed cluster stands up a management cluster, and the management plane on it then provisions and lifecycle-manages many isolated workload clusters on demand.

概述

该图展示了 NVKE 产品系列、它如何运行在 NICo 和您的 GPU 机器之上，以及各组件之间的通信方式。NVKE 既不是 Kubernetes 发行版，也不是 Cluster API 的变体。它是一个用于 Kubernetes 集群的自托管工厂：一个一次性的种子集群用于建立管理集群，随后该管理平面按需配置并管理多个隔离的工作负载集群的生命周期。

### An installation has two kinds of Kubernetes cluster

The management cluster runs the NVKE management plane and infrastructure controllers. nvkectl forms it using a temporary seed cluster; installing the management-plane services is a separate step. Workload clusters run customer applications. The management plane creates and operates them through NICo, Cluster API and the node agent. Read What is NVKE for the operator workflow and Architecture for the implementation and data flows.

安装包含两种 Kubernetes 集群

管理集群运行 NVKE 管理平面和基础设施控制器。nvkectl 使用临时种子集群来组建它；安装管理平面服务是一个独立的步骤。工作负载集群运行客户应用程序。管理平面通过 NICo、Cluster API 和节点代理来创建和运维这些集群。请阅读“什么是 NVKE”以了解操作员工作流程，并阅读“架构”以了解实现细节和数据流。

### Build from source

Use Go 1.27.3, the version pinned in go.work, and GNU Make 4 or later. Public Go modules must be reachable on the first build. Flox is optional and supplies the repository's development tools; on macOS, it also supplies GNU Make 4. See Development for toolchain setup.

从源码构建

使用 go.work 中固定的 Go 1.27.3 版本以及 GNU Make 4 或更高版本。首次构建时必须能够访问公共 Go 模块。Flox 是可选的，它提供仓库的开发工具；在 macOS 上，它还提供 GNU Make 4。请参阅“开发”以了解工具链设置。

### Build commands

git clone https://github.com/dsx-ai-factory/nvke.git
cd nvke
make build

This builds the workspace and writes nine binaries to bin/: agent, updater, controller, nvkectl, capd-reboot-controller, nvke-os-image-check, management-engine, tenant-api and operator-api. Building does not start a management plane or create a cluster. The node agent runs on Linux. The workspace guide explains the modules and outputs. For local services and test environments, see Local development setup. Before submitting a change, follow CONTRIBUTING.md and run make preflight; it selects checks for the modules you changed.

构建命令

git clone https://github.com/dsx-ai-factory/nvke.git
cd nvke
make build

这将构建工作区并将九个二进制文件写入 bin/ 目录：agent、updater、controller、nvkectl、capd-reboot-controller、nvke-os-image-check、management-engine、tenant-api 和 operator-api。构建过程不会启动管理平面或创建集群。节点代理在 Linux 上运行。工作区指南解释了模块和输出。有关本地服务和测试环境，请参阅“本地开发设置”。在提交更改之前，请遵循 CONTRIBUTING.md 并运行 make preflight；它会为您更改的模块选择相应的检查。
