**systemd loves Rust**

systemd 最近合并了对 Rust 的支持。展望未来，除了 C 语言之外，使用 Rust 编写 systemd 组件将成为可能。将另一种核心语言集成到一个大型且成熟的项目中总是充满争议的。当 Rust 被采纳为 Linux 内核的附加语言时，我们也看到了同样的情况。正如我们现在所知，那次尝试大体上是成功的。systemd 中的 Rust 支持有两种可能的含义：叶子组件（独立的二进制文件）和根组件（Rust 本身存在于基础的 libsystemd-shared.so 共享库中）。该项目得出的结论是，(1) 是可以接受的，而 (2) 目前尚不可行，因为这两种选择之间的范围和要求截然不同。

**Rust in systemd Shared Libraries 🥺**

选项 (2) 很复杂。细节最好留到另一篇博文中讨论，但要点是我们要求 Rust 提供一流的共享库支持。在 Rust 社区中，这通常被称为“稳定 ABI 问题”，这是一个众所周知且长期存在的问题。在解决这个问题之前，我们无法将 Rust 集成到根组件中，否则每个共享库和许多二进制文件都会因重复的 Rust 代码而变得臃肿。对于像 systemd 这样拆分为许多微小组件（目前超过 180 个二进制文件）的项目来说，静态链接既不实用也不可取。通常，静态链接适用于操作系统的叶子部分，但核心部分往往有不同的要求。

**Rust in systemd Binaries 😍**

选项 (1) 意味着共享代码保持为纯 C 语言，我们将这些功能封装为 Rust crate。然后，这些 crate 被用于 Rust 二进制文件。这使我们能够跨所有组件统一使用核心 API 函数，而无需考虑它们是用 Rust 还是 C 编写的。

**Key Design Decisions**

当 Rust 被 systemd 采纳时，该项目采用了以下原则：对核心 API 的统一访问。systemd 共享库拥有广泛的辅助程序，提供了远超 libc 或任何 Rust crate 所能提供的功能和安全性。最明显的例子是 systemd 的 chase*() 函数族。这是一个纯粹基于文件描述符（fd）的路径查找 API，整个树都在使用它。任何改进路径查找安全性和可靠性的新内核特性都会被立即采用并进行安全抽象。核心 Rust 中没有任何与之等效的功能。

**Uniform Behavior.**

C 和 Rust 编写的二进制文件在解析选项、显示帮助和输出错误消息的方式上看起来和表现得完全一致。Rust 二进制文件与 systemd 的 C 二进制文件产生不必要的差异是本质上不可接受的。用户永远不应该关心二进制文件是用哪种特定语言实现的。它根本不应该影响行为。

**Uniform Build System.**

像大多数现代编程语言一样，Rust 自带其构建和依赖管理生态系统：cargo。与内核非常相似，systemd 明确选择不依赖 cargo 来构建 Rust。systemd 使用 meson 作为其构建系统，在我们看来，在它旁边集成第二个构建系统是一个糟糕的主意，也是让发行版维护者的生活变得复杂的好方法。与 cargo 相关的安全和供应链攻击问题也已被提出作为担忧。

**Controlled Dependencies.**

systemd 对其他项目保持严格的松散依赖。如今，systemd 仅链接到 libc。所有其他依赖项都通过 dlopen() 提供，并使用 ELF 注释来标记依赖关系。接受新的依赖项是一个谨慎的过程，涉及根据维护和安全性对各个项目进行审查。虽然 systemd 原则上不反对使用外部 crate，但它有意保持保守，在项目对更广泛的 Rust 生态系统和社区有一定经验之前，不会接受任何对它们的依赖。

**No-std Rust.**

systemd 也不使用 Rust 标准库。我们目前不需要使用标准库提供的任何东西。为了重申之前的一个例子，Rust 提供的任何路径查找功能目前在 systemd 提供的安全敏感系统组件中都是不可接受的。

**Fallible Allocations.**

Rust 中失败的分配会导致恐慌（panic）。systemd 总是将分配视为可能失败的，并尽可能优雅地处理它们。因此，systemd 提供了自己的分配器 crate，使得整个 systemd 代码库的内存处理保持统一。同样，这与内核的做法非常相似。

**No Gratuitous Rewrites.**

长期建立且可靠的 C 语言代码库部分不会无故进行重写。如果说新语言有一个缺点，那就是它们会导致为了使用该语言而不是为了解决实际问题而重写既定且稳定的项目。最明显的例子之一是重写那些内在攻击面是基于路径的查找而不是内存安全的组件。移植到另一种语言的项目需要的不仅仅是错误兼容的重写，才能真正从重写中受益。专注于消除它们的核心攻击面要重要得多。

**Rust Remains Optional.**

现有用户可用的功能集不会倒退。我们意识到 Rust 尚未支持所有可能的架构，并且在某些地方引入 Rust 会很复杂，因此至少目前，Rust 仍然是可选的，没有 Rust 的 systemd 仍然完全可用并受支持。
