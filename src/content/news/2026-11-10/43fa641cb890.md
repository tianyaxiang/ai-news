Hackers are actively exploiting a recently discovered critical vulnerability that allows them to log in to privileged accounts on many Linux systems, multiple researchers are reporting. The vulnerability, tracked under the name *sshole, arises from the interaction between OpenSSH and a code library known as musl. Linux systems that use both of these packages and meet certain other requirements can be hacked to give unauthenticated access to high-privilege accounts in a matter of seconds. *sshole became publicly known last Thursday and quickly stoked concerns it could lead to widespread compromise of Linux machines. Four days later, the prediction shows signs of becoming real.

多位研究人员报告称，黑客正在积极利用一个新发现的关键漏洞，该漏洞允许他们登录许多 Linux 系统上的特权账户。这个被追踪为 *sshole 的漏洞源于 OpenSSH 与名为 musl 的代码库之间的相互作用。同时使用这两个软件包并满足其他特定要求的 Linux 系统，可能在几秒钟内被黑客入侵，从而获得高权限账户的未经授权访问权限。*sshole 于上周四公开，并迅速引发了人们对其可能导致 Linux 机器大范围受损的担忧。四天后，这一预测已显现出成为现实的迹象。

Security firm Greynoise said Monday that honeypots it maintains in Southeast Asia have come under attack by a group it’s tracking as GT10. The group conducted “mature intrusions” into the systems, which Greynoise uses to detect attempted or successful attacks in real time. Greynoise subsequently gained access to a GT10 server that revealed potential other victims and some of the tools used in the campaign. A backdoor the group is using in the attacks contains Chinese language comments and appears to be generated with the use of AI. Greynoise said that GT10 is also installing the Python3 release on machines that don’t already have it because the package is required to run the hacker’s backdoor, which is tracked under the name TAC Agent. TAC Agent supports a wide range of functions, including shell commands, system reconnaissance, and persistence.

安全公司 Greynoise 周一表示，其在东南亚维护的蜜罐系统遭到了一个被其追踪为 GT10 的组织的攻击。该组织对这些系统进行了“成熟的入侵”，Greynoise 正利用这些系统实时检测攻击尝试或成功攻击。Greynoise 随后获得了 GT10 服务器的访问权限，揭示了其他潜在受害者以及该行动中使用的一些工具。该组织在攻击中使用的后门包含中文注释，且似乎是利用人工智能生成的。Greynoise 表示，GT10 还在没有安装 Python3 的机器上安装该版本，因为运行该黑客后门（被追踪为 TAC Agent）需要此软件包。TAC Agent 支持多种功能，包括 shell 命令、系统侦察和持久化。

OpenSSH has released a fix that prevents attacks from working. Researchers at security firm watchTowr said Friday that they, too, were seeing exploitation activity, which was related to botnets and cryptocurrency. Security firm Previdian has also reported similar activity. It said its company’s sensors have seen 20 exploitation attempts from 13 unique attacker IP addresses geolocated to nine countries.

OpenSSH 已经发布了一个补丁，可以防止此类攻击生效。安全公司 watchTowr 的研究人员周五表示，他们也观察到了相关的利用活动，这些活动与僵尸网络和加密货币有关。安全公司 Previdian 也报告了类似活动。该公司称，其传感器已监测到来自 9 个国家、13 个不同攻击者 IP 地址的 20 次利用尝试。

The vulnerability, tracked as CVE-2026-123158, resides in OpenSSH, when it runs alongside musl, a Linux alternative to the widely used libc code library. Further, OpenSSH must not use PAM (pluggable authentication modules), a framework that handles user authentication and account access checks. Additionally, SSH configurations must (1) have at least one account that’s accessible using a password that is hashed using the SHA256 or SHA512 function and (2) also be set to use passwordless accounts by way of specifying a “*” in the password field in the /etc/shadow file. Passwordless configurations are standard for certain types of accounts.

该漏洞被追踪为 CVE-2026-123158，存在于与 musl（一种广泛使用的 libc 代码库的 Linux 替代品）同时运行的 OpenSSH 中。此外，OpenSSH 必须不使用 PAM（可插拔认证模块），这是一个处理用户认证和账户访问检查的框架。另外，SSH 配置必须满足：(1) 至少有一个账户可以使用通过 SHA256 或 SHA512 函数哈希的密码进行访问；(2) 通过在 /etc/shadow 文件的密码字段中指定“*”来设置为使用无密码账户。无密码配置对于某些类型的账户是标准做法。

Exploits are triggered when an attacker enters passwords with more than 256 characters for a passwordless account. This step occurs when the OpenSSH server hashes the supplied password and checks it against the hash stored in /etc/shadow. The oversized password produces an error that causes musl’s password hashing function to return “*”. The attacks exploit the “misinterpretation of whether a string is intended to be a password hash,” Red Hat said.

当攻击者为无密码账户输入超过 256 个字符的密码时，漏洞利用就会被触发。这一步骤发生在 OpenSSH 服务器对提供的密码进行哈希处理并将其与存储在 /etc/shadow 中的哈希值进行比对时。超长的密码会产生一个错误，导致 musl 的密码哈希函数返回“*”。红帽公司表示，这些攻击利用了“对字符串是否旨在作为密码哈希的误解”。

Despite the multiple conditions necessary, CVE-2026-123158 poses a serious threat to a large base of machines, most notably those running Alpine, a lightweight distribution of Linux. The ease of exploitation allows hackers to direct malicious commands to any of the millions of SSH servers exposed to the Internet and identify potentially vulnerable ones in seconds. Anyone using OpenSSH should install the update promptly. Those using musl should investigate further.

尽管需要满足多个条件，但 CVE-2026-123158 对大量机器构成了严重威胁，尤其是那些运行轻量级 Linux 发行版 Alpine 的机器。利用的简易性使得黑客能够向暴露在互联网上的数百万台 SSH 服务器中的任何一台发送恶意命令，并在几秒钟内识别出潜在的易受攻击目标。任何使用 OpenSSH 的用户都应立即安装更新。使用 musl 的用户应进行进一步调查。
