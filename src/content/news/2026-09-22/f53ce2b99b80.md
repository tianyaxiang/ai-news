# I Built an MCP Server That Tracks AI Quota Resets — Here's How
# 我构建了一个追踪 AI 配额重置的 MCP 服务器——实现方案如下

**TL;DR:** I built a Model Context Protocol server that lets AI assistants like Claude and Cursor query real-time AI quota reset signals across 15+ products.
**简而言之：** 我构建了一个模型上下文协议（MCP）服务器，让 Claude 和 Cursor 等 AI 助手能够查询 15 个以上 AI 产品中实时的配额重置信号。

**The Problem**
If you're paying for AI subscriptions (OpenAI Codex at $20-200/mo, Claude Pro, Gemini Advanced), quota resets are money. When your quota resets, you want to know immediately. The problem: resets are scattered across multiple status pages, happen at unpredictable times, and there's no unified API to track them.
**问题所在**
如果你正在支付 AI 订阅费用（如每月 20-200 美元的 OpenAI Codex、Claude Pro、Gemini Advanced），配额重置就意味着金钱。当配额重置时，你希望第一时间知晓。问题在于：重置信息分散在多个状态页面上，发生时间不可预测，且没有统一的 API 来追踪它们。

**The Solution**
I built Reset Beer — a dashboard that aggregates official status pages from 15+ AI products and sends alerts when quota reset signals drop. The MCP integration is what makes it interesting. Instead of just receiving emails, Pro users can connect Reset Beer to their AI assistants and ask: "Any recent quota resets for Codex?"
**解决方案**
我构建了 Reset Beer——一个聚合了 15 个以上 AI 产品官方状态页面的仪表板，并在配额重置信号出现时发送提醒。MCP 集成是其最有趣的地方。专业版用户无需仅仅依赖电子邮件，可以将 Reset Beer 连接到他们的 AI 助手，并询问：“Codex 最近有配额重置吗？”

**Architecture**
The MCP server is a single Next.js API route that implements JSON-RPC 2.0 over HTTP (Streamable HTTP transport per MCP spec 2025-03-26). Three tools are exposed:
*   `list_recent_resets` — Query reset events by time range, product, and limit
*   `get_product_status` — Get the latest event for a specific product
*   `list_products` — List all tracked AI products
**架构**
该 MCP 服务器是一个单一的 Next.js API 路由，通过 HTTP 实现 JSON-RPC 2.0（遵循 2025-03-26 版 MCP 规范的可流式 HTTP 传输）。它公开了三个工具：
*   `list_recent_resets` — 按时间范围、产品和数量限制查询重置事件
*   `get_product_status` — 获取特定产品的最新事件
*   `list_products` — 列出所有被追踪的 AI 产品

**API Key Authentication**
Each Pro user gets a cryptographically random API key (rb_ prefix, 64 hex chars). The key is stored as SHA-256 hash in the database.
**API 密钥认证**
每位专业版用户都会获得一个加密随机生成的 API 密钥（以 `rb_` 为前缀，包含 64 个十六进制字符）。该密钥以 SHA-256 哈希值形式存储在数据库中。

**What I Learned**
*   MCP is easier than expected — The spec is well-designed
*   API key auth > OAuth for first-party tools — Bearer tokens are simpler
*   Calendar rules ≠ actionable signals — Filter predictable events
*   Static generation + cookies don't mix — Use client components with Suspense
**我的心得**
*   MCP 比预想中更容易——规范设计得非常出色
*   对于第一方工具，API 密钥认证优于 OAuth——Bearer Token 更简单
*   日历规则不等于可操作的信号——需要过滤掉可预测的事件
*   静态生成与 Cookie 不兼容——应使用带有 Suspense 的客户端组件
