When I was working on Cheapskate, I realized after a few weeks that there was a fundamental issue. The app relies on Supabase for the unsexy parts of its architecture: authentication and a SQL datastore. All of it is bog-standard and all of it I happily handed off to be someone else’s problem. To be clear, I love Supabase – if I had to run all that boilerplate myself, I never would have made Cheapskate. But… the shape of it is wrong. I don’t want to own this data. This is a person’s financial details! Shouldn’t that live with them, and not with me?

当我在开发 Cheapskate 时，几周后我意识到存在一个根本性问题。该应用依赖 Supabase 来处理其架构中枯燥的部分：身份验证和 SQL 数据存储。这一切都是标准配置，我很乐意将其交给别人去处理。需要说明的是，我喜欢 Supabase——如果我必须自己运行所有这些样板代码，我永远不会做出 Cheapskate。但是……它的模式不对。我不想拥有这些数据。这是个人的财务细节！难道不应该由他们自己保存，而不是由我来保存吗？

Is it even possible to make a web app like this, with anything close to the same convenience and functionality (durable, works across devices, shareable with friends) as Supabase allows? Well, I really wanted to. I spent a lot of time trying. Here are all the things that don’t work:

是否有可能制作出这样一款网络应用，既能拥有与 Supabase 相当的便利性和功能（持久化、跨设备运行、可与朋友共享），又能实现上述目标？好吧，我真的很想做到。我花了很多时间尝试。以下是所有行不通的方法：

localStorage: the easiest one to try, and doesn’t require user accounts, but the inability to access data across devices or share with someone else makes it a non-starter. showDirectoryPicker: cool, and durable (unlike localStorage), but not yet supported by all browsers, and sharing (while possible) requires an extra service, e.g. Dropbox or iCloud. CloudKit Private Database: Apple’s obscure BaaS! Locks us into Apple SSO, requires a $99 Apple Developer subscription, and the JS library doesn’t implement sharing anyway.

localStorage：最容易尝试，不需要用户账户，但无法跨设备访问数据或与他人共享，因此不可行。showDirectoryPicker：很酷且持久（不像 localStorage），但并非所有浏览器都支持，而且共享（虽然可能）需要额外的服务，例如 Dropbox 或 iCloud。CloudKit Private Database：苹果晦涩的 BaaS！将我们锁定在 Apple SSO 中，需要 99 美元的苹果开发者订阅，而且其 JS 库根本没有实现共享功能。

SQLite in Google Drive: cute, but it similarly locks us into Google SSO, and I actually tried this, it was miserable to set up both as a user and a developer. B-Y-O-DynamoDB: this is actually how I made Cardi a few years ago! It works great… other than how it is insane to ask people to “log in” using AWS keys lol. remoteStorage: really cool, and the Platonic ideal of this concept, but support is thin, and the docs explicitly call out collaboration as unsupported.

Google Drive 中的 SQLite：很有趣，但同样将我们锁定在 Google SSO 中，我实际上尝试过，无论是作为用户还是开发者，设置起来都很痛苦。B-Y-O-DynamoDB：这实际上是我几年前制作 Cardi 的方式！它运行得很好……除了要求人们使用 AWS 密钥“登录”简直是疯了，哈哈。remoteStorage：非常酷，是这一概念的理想典范，但支持力度薄弱，文档明确指出不支持协作。

CRDT / “local-first”: again cool, but I haven’t seen a mature “Firebase for CRDTs” like the one proposed, and it’s unclear if it would even solve the privacy aspect. Besides, all of these options compromise on the data model anyway, being KV or blob storage when all I really want is an API to run SQL queries. You know, like any normal app? Argh!
