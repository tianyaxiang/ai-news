Size limitations I was surprised to find that there seems to be no limit to the number of frames in a GIF file, and that the maximum resolution is 2^16 by 2^16, which is 4295 megapixels. We are of course limiting ourselves to just 88 by 31 pixels (or 0.003 megapixel), which might mean that regular text fonts don't get much space to shine — Arial, for example, seems to become legible at a minimum of 10 pixels height, which allows us to display about eleven words at once.

尺寸限制：我很惊讶地发现 GIF 文件的帧数似乎没有限制，且最大分辨率为 2^16 x 2^16，即 4295 兆像素。当然，我们将自己限制在 88x31 像素（或 0.003 兆像素），这意味着常规字体没有太多的发挥空间——例如，Arial 字体似乎在 10 像素高度时才变得可读，这使我们一次只能显示大约十一个单词。

Formatting the work If we take our button, which is 88x31, and our font, which is 6x4 (5x3 + spacing), we find that we can fit 5 rows of 22 characters each. ImageMagick, the tool we're going to use, is not very good at laying out text, so it'd be wise to take care of that ourselves. There's several ways to do this, but the neatest one uses three posix tools: cat, tr and fold: cat input.txt | tr '\n' ' ' | tr -d '\r' | fold -s -w 22 > 22w.txt cat is used to send the text to tr. tr translates each newline into a space, condensing the whole text file into one line. fold then takes that one line, splits it into multiple lines that are up to 22 characters wide (-w 22), and tries to avoid splitting words in half (-s).

格式化作品：如果我们以 88x31 的按钮和 6x4（5x3 + 间距）的字体为例，我们发现每行可以容纳 22 个字符，共 5 行。我们将要使用的工具 ImageMagick 在排版文本方面表现不佳，因此最好由我们自己处理。有几种方法可以做到这一点，但最简洁的方法是使用三个 POSIX 工具：cat、tr 和 fold：cat input.txt | tr '\n' ' ' | tr -d '\r' | fold -s -w 22 > 22w.txt。cat 用于将文本发送给 tr。tr 将每个换行符转换为空格，将整个文本文件压缩为一行。fold 随后获取这一行，将其拆分为宽度不超过 22 个字符的多行（-w 22），并尽量避免将单词拆分（-s）。

It's likely that at this point, your text looks fine. Mine was a bit garbled up, because fold doesn't handle multibyte characters well. I checked what non-ascii characters input.txt contained, and got rid of them using sed, like this: sed -i 's/”/"/g'. The -i flag allows you to modify the file in place. You can find all the non-ascii characters using grep: grep -P -n '[^\x00-\x7F]' input.txt. Of course, formatting is subjective. Depending on the kind of literary work, you might want to do it differently. I used sed -i 's/CHAPTER /\n\n\nCHAPTER /g' input.txt to add some space between chapters, but chapters may be marked differently in the text you're using, or they might not be present at all.

此时，你的文本看起来应该没问题了。我的文本有点乱码，因为 fold 对多字节字符的处理不太好。我检查了 input.txt 中包含哪些非 ASCII 字符，并使用 sed 删除了它们，如下所示：sed -i 's/”/"/g'。-i 标志允许你直接修改文件。你可以使用 grep 找到所有非 ASCII 字符：grep -P -n '[^\x00-\x7F]' input.txt。当然，格式化是主观的。根据文学作品的类型，你可能需要采用不同的方式。我使用了 sed -i 's/CHAPTER /\n\n\nCHAPTER /g' input.txt 来在章节之间增加一些空间，但你使用的文本中章节标记方式可能不同，或者根本没有章节。

And turning it into a GIF? For this part, you're going to need ImageMagick installed. Although it's likely that you already have it. We use the following command to generate the first version of our GIF file: cat 22w.txt | convert -page 88x39+0+0 -background white -fill black -font tom.ttf -pointsize 6 text:- high.gif Note that I have the actual tom.ttf file placed in the current working directory. It's mostly self explanatory. Convert takes the text from standard input and, just like that, puts it onto a GIF, frame by frame. Lovely. However, it seems to force some margin on the bottom of the image, which is why we drew the text on an image eight pixiels higher than we wanted. We're going to crop it now: convert high.gif -set delay 600 -coalesce -repage 0x0 -crop 88x31+0+0 +repage good.gif We're cropping those last eight pixels off, and also setting a reasonable delay between frames (in my experience, 6 seconds seems fine — please let me know if you disagree. 那么如何将其转换为 GIF 呢？对于这一部分，你需要安装 ImageMagick。虽然你很可能已经安装了它。我们使用以下命令生成 GIF 文件的第一个版本：cat 22w.txt | convert -page 88x39+0+0 -background white -fill black -font tom.ttf -pointsize 6 text:- high.gif。请注意，我将实际的 tom.ttf 文件放在了当前工作目录中。这基本上是不言自明的。Convert 从标准输入获取文本，就这样将其逐帧放入 GIF 中。很棒。然而，它似乎在图像底部强制留出了一些边距，这就是为什么我们在比预期高 8 像素的图像上绘制文本的原因。现在我们要裁剪它：convert high.gif -set delay 600 -coalesce -repage 0x0 -crop 88x31+0+0 +repage good.gif。我们裁剪掉最后 8 个像素，并设置了合理的帧间延迟（根据我的经验，6 秒似乎还可以——如果你不同意，请告诉我）。现在 good.gif 看起来应该像这样：

Python bonus: centered text I think it would be neat to have the text aligned to center, rather than having it stick so hard to the left edge. I wrote a quick python script for that, made it executable, then piped it's output into a file and once again regenerated the GIF. #!/usr/bin/python3 from math import floor with open("22w.txt") as file: for line in file: i = (22-len(line.strip()))/2 o = " "*floor(i)+line.strip() print(o)

Python 额外内容：居中文本。我认为让文本居中对齐会更整洁，而不是让它紧贴左边缘。我为此写了一个简单的 Python 脚本，使其可执行，然后将其输出通过管道传输到文件中，并再次重新生成了 GIF。#!/usr/bin/python3 from math import floor with open("22w.txt") as file: for line in file: i = (22-len(line.strip()))/2 o = " "*floor(i)+line.strip() print(o)
