# When Do Options Help? Policy Necrosis and Redundant Coverage in Option-Critic
# 选项何时有效？Option-Critic 中的策略坏死与冗余覆盖

**Abstract:** Option-critic learns options: sub-policies together with a learned rule for when each one hands control back. Its headline result is that performance improves as options are added. We explain that result, with theory and experiment.

**摘要：** Option-critic 旨在学习“选项”（options）：即子策略以及一套用于决定何时交回控制权的习得规则。其核心结论是，随着选项数量的增加，性能会得到提升。我们通过理论和实验对这一结果进行了解释。

First, the termination rule option-critic learns by maximising return contributes nothing. When the termination test and the policy that picks options read the same values, the test fires at every step, so the learned rule is identical to always terminating. When that policy explores and the test does not, as in option-critic itself, the rule can block the exploration; there are instances where it suffers $\Omega(T)$ regret while always terminating holds to $O(\log T)$. Forcing termination at every step leaves the option-count curve intact.

首先，Option-critic 通过最大化回报所学习到的终止规则实际上毫无贡献。当终止测试与选择选项的策略读取相同数值时，测试会在每一步触发，因此习得的规则等同于“总是终止”。当该策略进行探索而测试不进行探索时（如 Option-critic 本身的情况），该规则可能会阻碍探索；在某些情况下，它会遭受 $\Omega(T)$ 的遗憾（regret），而“总是终止”策略则保持在 $O(\log T)$。强制每一步都终止，并不会改变选项数量与性能之间的曲线关系。

Second, the policy inside an option barely explores at all, so a state locks onto the first action that looked good and never updates again. We name this policy necrosis, give a state-level test for it, and find three fifths of states necrotic in a typical option. Restoring exploration repairs those states, and one option then solves the task.

其次，选项内部的策略几乎不进行任何探索，导致状态会锁定在第一个看起来不错的动作上，之后便不再更新。我们将这种现象命名为“策略坏死”（policy necrosis），给出了针对状态层面的测试方法，并发现典型的选项中有五分之三的状态处于坏死状态。恢复探索可以修复这些状态，此时仅需一个选项即可解决任务。

Third, extra options improve no option; what falls is the chance that all of them fail in the same state, from $59\%$ to $4\%$, and performance follows that joint quantity.

第三，额外的选项并不会改进任何单个选项；真正下降的是所有选项在同一状态下同时失效的概率（从 $59\%$ 降至 $4\%$），而整体性能正是随着这一联合概率的变化而变化的。
